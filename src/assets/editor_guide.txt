== start | Getting started
see: editor.guide, editor.shortcuts, editor.check, editor.undo, editor.usedby, editor.search, editor.import, concepts.files, concepts.campaigns, tab.maps, maps.play

Editor is the content editor for Triffall. Everything the game shows -
maps, people, monsters, items, spells, quests, dialogue, sounds - lives in
plain text files, and Editor gives each kind of file its own tab with forms,
pickers and previews so you rarely have to touch the text by hand.

The tabs, left to right: Maps (paint maps and place objects), Tiles (what each
map cell type looks like and does), World (overworld locations), Items,
Creatures, Spells, Classes, Shops, Encounters (random fight tables), Quests,
Dungeons (generated dungeons), Dialogue, Sounds, Tileset (browse the art),
Recipes, Affixes, Banter, Achiev. (achievements), Campaign, Flags, Bounties
(notice boards), Factions (town reputation), Objects (object templates and every
placed object), Resources (gather node types) and NPCs (the people and animals
of the world, companions too). A tab with unsaved changes shows a * after its
name.

The Campaign button in the header picks which campaign you are editing, or
makes a new one. Each campaign is a separate game with its own files.

Saving: every tab has its own Save button, and Ctrl+S saves the tab you are
on. Revert throws away unsaved changes in that tab. Exit (or Esc when no field
is focused) asks before discarding unsaved work. When you leave the editor the
game reloads everything you saved.

Undo: the Maps tab and the form tabs (Items, Creatures, Spells and the rest)
have Ctrl+Z / Ctrl+Y; the Dialogue text editor has its own Ctrl+Z.

Finding mistakes: "Check all" in the header (under Exit) checks the whole
campaign at once - missing maps, items, creatures, dialogues, flags nothing
sets - and lists every problem; click one to jump to it. The Items,
Creatures, Spells and Shops forms and the Dialogue tab show a "Used by" list
of everything that refers to the selected id.

Playtesting: in the Maps tab press Play > (or P over a tile). Editor saves
every tab, closes, and drops the party onto that map. With no game running a
level-1 tester with 500 gold is created - or, with "Play from a state" on
(Campaign tab), a fresh party with the level, class, gold, flags, items and
companions you chose. The Campaign tab's "Play from the start" runs a real New
Game instead.

How to use this guide: every tab has a "?" in its header and most fields have
a "?" next to their name; click one to open the matching topic. F1 opens the
guide on the tab you are looking at, and the "? Guide" button in the header
opens it anywhere. Use the filter box to find a topic by name, the See also
buttons to jump to related topics, and Back to return.

== editor.guide | Using the guide window
see: start, editor.shortcuts

The guide window has a topic list on the left and the selected topic on the
right.

- Filter box: type part of a topic name or id (for example "chest" or "obj.door") to narrow the list.
- See also: the buttons under the title jump to related topics.
- Back: returns to the topic you were reading before, step by step.
- "?" buttons: each tab header and most field names in the forms have one. It opens the guide straight on that tab or field.
- F1: opens the guide on the current tab. "? Guide" in the header bar opens it from anywhere.

Topic ids follow the file layout: tab.* are the tabs, concepts.* explain ideas
shared by many tabs, obj.* are map objects and their keys (obj.door.key),
item.*, creature.*, spell.* and so on are the fields of each data file. Lines
shown indented in a monospace style are examples you can copy as-is.

== editor.shortcuts | Keyboard and mouse shortcuts
see: edit.text, maps.tools, maps.select, tab.dialogue, editor.undo, editor.check, editor.guide

Everywhere:
- F1: open the guide on the current tab.
- Ctrl+S: save the current tab.
- Tab / Shift+Tab: move to the next / previous field. Enter or Esc leaves a field.
- Mouse wheel over a number field nudges it; hold Shift for steps of 10.
- Text fields: click, drag or Shift+arrows to select; double-click selects a word, triple-click everything; Ctrl+arrows jump by word (Ctrl+Shift+arrows select by word); Ctrl+Backspace / Ctrl+Delete delete a word; Ctrl+A/C/X/V use the system clipboard; right-click for a menu. Ctrl+E, or the ... button on text too long for its box, edits it in a big box. See edit.text.
- Esc with no field focused: Exit the editor (asks if anything is unsaved). In the Tiles tab after a jump from a map, Esc goes back to the map.
- Popups: list pickers filter as you type, arrows + Enter or click to choose; Enter = Yes/OK, Esc = Cancel.

Form tabs (Items, Creatures, Spells, Classes, Shops, Encounters, Quests,
Dungeons, World locations, Recipes, Affixes, Banter, Achievements):
- Ctrl+Z undo, Ctrl+Y or Ctrl+Shift+Z redo (also the Undo button next to Delete).

Maps tab (with no text field focused):
- Left mouse paints (Paint/Fill/Rect), right mouse picks the tile under the cursor as the brush.
- Middle-drag, wheel (Shift+wheel = sideways), WASD or the arrow keys scroll.
- K over a tile: edit that tile kind in the Tiles tab. P: play from this tile. B: make it the new-game START. N: make it the overworld arrival point.
- Ctrl+Z undo, Ctrl+A select all, Ctrl+C / Ctrl+X copy or cut the selection, Ctrl+V paste then click to stamp (Shift+click keeps stamping), Delete clears the selection or removes the selected object, Esc cancels a paste or selection.
- Rect tool: hold Shift while releasing to draw only the outline.

Dialogue and Scripts text editors: everything Notepad does and more - see
edit.text (word wrap, find / replace, go to line, line tools, Wide).

Tile picker and Tileset tab: wheel scrolls, Shift+wheel or drag scrolls
sideways, arrow keys pan.


== edit.text | Text editing (every text box)
see: editor.shortcuts, tab.dialogue, tab.scripts, editor.undo

Every text box in the Editor works the way Notepad does. The one-line fields
(names, descriptions, search boxes...) and the big text editors of the
Dialogue and Scripts tabs share the same keys.

Mouse:
- Click places the cursor, drag selects, Shift+click selects up to the click.
- Double-click selects a word (keep the button down and drag to select word by word).
- Triple-click selects the whole line (in a one-line field: everything).
- Right-click opens a menu: Undo, Redo, Cut, Copy, Paste, Delete, Select word / line / all, and more in the big editors.

Keys:
- Ctrl+Left / Ctrl+Right: jump a word. Add Shift to select word by word.
- Shift+arrows, Shift+Home / Shift+End: select.
- Ctrl+Backspace / Ctrl+Delete: delete the word before / after the cursor.
- Ctrl+A select all, Ctrl+C copy, Ctrl+X cut, Ctrl+V paste (also Ctrl+Insert, Shift+Delete, Shift+Insert).
- Ctrl+Z undo, Ctrl+Y or Ctrl+Shift+Z redo. Typing a word is one undo step. In the form tabs, Ctrl+Z undoes the whole form (see editor.undo).

Text too long for its box: press Ctrl+E in the field, or click the small ...
button at its right end, or pick "Edit in a big box" from the right-click
menu. The text opens in a large box where it wraps so all of it shows. Enter
or OK puts it back, Esc cancels. It is still one line in the file.

Dialogue and Scripts editors - the extra keys:
- Home goes to the first letter of the line, press it again for the very start. Ctrl+Home / Ctrl+End: start / end of the file.
- Up / Down keep the column you started from. PgUp / PgDn move a page. Ctrl+Up / Ctrl+Down scroll without moving the cursor.
- Ctrl+F find (finds as you type, every match is marked), Enter or F3 = next, Shift+Enter or Shift+F3 = previous; Aa = match case, W = whole words. Ctrl+H find and replace (Replace, Replace all). Ctrl+G go to a line number. Esc closes the bar.
- Ctrl+L select the line (again: the next one too). Ctrl+D duplicate the line (or the selected lines). Ctrl+Shift+K delete the line(s). Alt+Up / Alt+Down move the line(s) up or down.
- Ctrl+/ comments the line(s) out with # (again: back in).
- Tab indents, Shift+Tab outdents - the selected lines when several are selected. Ctrl+] / Ctrl+[ do the same.
- Ctrl+Shift+U makes the selection UPPER CASE, Ctrl+U lower case.
- Ctrl+C or Ctrl+X with nothing selected copies or cuts the whole line.
- Insert switches between inserting and typing over (OVR in the status line).
- Alt+Z or the Wrap button: word wrap. Long lines continue on the next row (a - in the margin). The Dialogue editor starts with it on.
- Ctrl+E, the Wide button in the header or the status line: Wide - the editor takes the whole window (the file list and the help panel step aside). Narrow or Ctrl+E brings them back. Save and Check are in the header while it is wide.
- Selecting a whole word (double-click) outlines its other copies; a bracket next to the cursor and its partner are boxed.
- The status line shows the line and column, how much is selected, and what Check says about the line the cursor is on.

Check while you type: a moment after you stop typing, the tab's Check runs on
its own. Lines with a problem get a dot in the margin (red = error, orange =
warning) and a mark on the scroll bar; point at the dot, or put the cursor on
the line, to read it. The Check button still lists everything.

Scripts only:
- Enter keeps the indent and adds one after if, elif, else, while and for. Typing end, else or elif on its own line steps it back to its block.
- After two letters of a word, a list offers commands, actions, built-in values, functions and words already in the script. Up / Down choose, Tab takes it, Esc closes it (Enter still starts a new line).

== editor.check | Check all (whole-campaign check)
see: maps.check, dlg.check, tab.flags, flags.status, editor.usedby

The "Check all" button in the header, under Exit, checks the whole campaign
and opens a report. ERRORs (something points at an id that does not exist)
are listed first, then warnings.

What it looks at:
- Campaign: the start map, opening dialogue, worldmap= and starting items.
- Every map: objects outside the map; objects on blocked tiles (doors, signs, levers, obstacles, changes and gather nodes may stand on walls); NPCs with a missing dialogue or shop; exits to unknown maps; unknown creatures, chest items, gather items and door keys; a spawn on a blocked tile; unknown tile kinds; a missing table=; a worldmap= naming a missing map.
- Every dialogue file: the same lint as the Dialogue tab's Check.
- Flags that are checked but never set.
- Shops, classes, creatures, recipes, encounter tables, dungeons and world locations that name missing items, spells, creatures or maps; encounter tables nothing uses.
- Quests: pins to unknown places, quests without stages, objectives for a stage that does not exist.
- Items whose effect=revealmap: names a missing map.
- Story contradictions (1.5.0): pairs of flags in contradictions.txt that must never both be true, where some route in the content could set both. See contradictions.

Tick "errors only" to hide the warnings, press Run again after fixing
things, and click any line to jump to the map object, dialogue line, form
entry or flag it is about.

== editor.undo | Undo in the form tabs
see: editor.shortcuts, maps.tools, tab.items

Every form tab - Items, Creatures, Spells, Classes, Shops, Encounters,
Quests, Dungeons, World locations, Recipes, Affixes, Banter and Achievements -
keeps its own undo history.

- Ctrl+Z: undo the last change in this tab.
- Ctrl+Y or Ctrl+Shift+Z: redo.
- The Undo button next to Delete does the same as Ctrl+Z.

What counts as one step: any change to the entries - a field edit, New,
Duplicate, Delete, a stage moved in a quest. Typing in one field counts as a
single step as long as each change comes within a second of the previous
one, so undo takes back a whole word or number rather than one letter. Up
to 80 steps are kept per tab.

Revert (reloading the file) and switching campaign clear the history. Undo
only changes the form; the file changes when you Save.

The Maps tab has its own undo for painting and objects (Ctrl+Z), and the
Dialogue tab's text editor has its own Ctrl+Z.

== editor.usedby | Used by
see: table.usedby, tab.items, tab.creatures, tab.spells, tab.shops, tab.dialogue

The "Used by" box sits under the fields in the Items, Creatures, Spells and
Shops tabs, and at the bottom of the Dialogue tab's right panel. It lists
every place in the campaign that refers to the selected id, so you can see
what breaks before you rename or delete something.

It finds:
- Maps: chest contents and chest keys, gather items and tools, door keys, exit items, enemy groups, NPC dialogue, shop and hostile creatures, obstacle needs=item:, conditions with item:, itemn: and kills:, and scripts.
- Dialogue: give, take, combat, spawn, shop and dialogue actions, and option conditions.
- Data: shop stock, class gear, spells and learn=, creature loot and spells, item spell=, ammo= and salvage=, recipe results, materials and reveal items, encounter groups, dungeon monsters and boss, quest stage and objective conditions, achievement item: and boss: terms, banter if=.
- The campaign's starting items and opening dialogue.

Click a line to jump to that map object, dialogue line or entry. Refresh
rescans after you change other tabs. Encounter tables have their own list
(see table.usedby).

== concepts.files | Files and folders
see: concepts.campaigns, concepts.ids, tab.campaign, tab.flags

A campaign is a folder. The base game lives in assets/data; other campaigns
live in assets/campaigns/<id>/ with the same layout. Which tab edits which file:

- Maps: maps/<map id>.txt (one file per map: header, legend, rows, objects)
- Tiles: tilekinds.txt
- World: overworld.txt (the location list); the painted overworld is maps/overworld.txt
- Items: items.txt, Creatures: creatures.txt, Spells: spells.txt, Classes: classes.txt
- Shops: shops.txt, Encounters: encounters.txt, Quests: quests.txt, Dungeons: dungeons.txt
- Dialogue: dialogue/<dialogue id>.txt (one file per conversation)
- Sounds: sounds.txt (the audio files themselves are in assets/audio)
- Recipes: recipes.txt, Affixes: affixes.txt, Banter: banter.txt, Achiev.: achievements.txt
- Campaign: campaign.txt
- Flags: flags.txt (flag descriptions only - the game never reads it)
- No tab (edit in a text editor): epilogue.txt and credits.txt (the ending), migrations.txt
  (renames for old saves), demo.txt (the demo build) - see the topics "The ending" and "Saves and patches"

Shared by every campaign: the tileset art (assets/tiles.png), the desktop
icons, the sounds and music, and the My Computer lore files. A campaign can add
its own tilekinds.txt to change or add tile kinds.

Every data file is plain text: [section] lines start an entry and key=value
lines fill it. Lines starting with # are comments. You can edit the files in
any text editor too; Editor rewrites a file in its own tidy form when it
saves it (comments inside a form-edited file are not kept).

== concepts.ids | Ids and names
see: concepts.files, concepts.flags, location.id, map.id

Almost everything has an id: a short lowercase name with no spaces, such as
iron_sword, goblin_cave or q_main. Ids are how files point at each other: a
chest's items= lists item ids, an exit's to= names a map id, an NPC's
dialogue= names a dialogue file. Names (name=) are what the player sees and can
be anything.

Rules of thumb:
- Use letters, digits and _ only. Ids are case-sensitive; keep them lowercase.
- An id must be unique within its file. A second entry with the same id replaces the first.
- Map ids and dialogue ids are file names: maps/hollowmere.txt is map hollowmere.
- A dungeon's id is also a map id: exits can lead to it, and a map file with that id replaces the generator.
- An overworld location has its own id (used by quest pins, roads and the coach) and a separate map= it enters. They are often the same, but not always (location greywood enters map goblin_cave).
- Renaming an id does not update the places that use it. Search for the old id (the Flags tab, Dialogue Check all and Maps Check help) and fix them by hand.

== concepts.flags | Flags
see: concepts.conditions, tab.flags, dlg.actions, concepts.scripts

Flags are the game's memory: named numbers saved with each game. A flag that
was never set counts as 0 (false). Anything that is not 0 counts as true.

Setting flags:
- Dialogue and scripts: set=name (to 1), set=name=3, flag=name, inc=name (+1), clear=name (back to unset).
- Map objects set their flag= when they happen: a chest when opened, an enemy group when defeated, a trigger when it fires, a door when opened, an obstacle when cleared, a lever when pulled (and clears it when pushed back).
- Dungeons set bossflag= when the boss group dies. The campaign's starting flags are set on New Game.
- Built-in: joined_<class id> when join= adds a companion, game_won when win= ends the game.

Reading flags: every condition field (option conditions, show=, hide=,
require=, openif=, moveif=, if=, quest stages, banter if=) tests flags.

Numbers make quest progress easy: set=q_main=1 when a quest starts, set=q_main=2
at the next step, and test q_main>=2. A good habit is one counter flag per quest
plus a few yes/no flags for events (bram_quest, metro_open).

Flags starting with _ are used internally (for example _banter_* for banter
lines that play once); do not use that prefix yourself. The Flags tab lists
every flag your campaign uses and warns about flags that are checked but never
set.

== concepts.conditions | Conditions
see: concepts.flags, dlg.options, quest.stage.when, achievement.cond, concepts.statchecks

A condition is a test that is true or false. The same syntax is used by
dialogue options, NPC show/hide/moveif, door openif/require, exit and trigger
require, change if, quest stages, banter if, location require and the
achievements flag: term. Join several tests with & - all of them must be true.
Put ! in front of a test to reverse it. An empty condition is always true.

- name: the flag is set (not 0).
- name>=n: the flag's number is at least n. !name>=n means "below n".
- item:id: someone in the party carries at least one of that item.
- itemn:id:n: the party carries at least n of it.
- gold:n: the party has at least n gold.
- level:n: the hero is at least level n.
- party:class: a member has that class id (or that name).
- kills:creature:n: the party has killed at least n of that creature (bestiary count).
- approval:class:n: that companion's approval is at least n.
- rep:faction:n: the party's reputation with that town or group is at least n (it can be negative: rep:brasswick:-20). !rep:faction:n means "below n".
- night / day: night is roughly 19:30 to 06:00.
- weather:rain (also clear, storm, fog, snow).
- lit: the party has a light going - a torch, a light spell or flare, or worn gear that gives light (1.1.7).
- stat:cha>=12: the hero's stat, gear included (str, dex, con, int, wis, cha). Also >, <=, < and = (1.4.0).
- partystat:str>=14: the best of that stat among the living party members (1.4.0). See Stat checks.
- stealthy: the party is sneaking - Camouflage (or another stealth effect) is on (1.4.0).

Examples:

  q_main>=2&!item:rift_key
  bram_quest&bandit_leader_dead&!q_bram_done
  gold:10

There is no "equals" or "less than" except through !: q_main>=2&!q_main>=3
means exactly 2 (stat checks are the exception: stat:int<10). Spaces around &
are fine. Flag names cannot contain & ! : or >=.

The "+ flag" button next to condition fields also offers stat checks and
stealthy at the top of its list.

== concepts.statchecks | Stat checks in dialogue
see: concepts.conditions, dlg.options, quest.routes, scripting.values

A dialogue answer whose condition holds a stat check shows the check in
front of its text, so the player sees why the answer is there:

  option=Pell has paid the guard to march on you. Go while you can.|persuade|stat:cha>=12
  shows:  [CHA 12] Pell has paid the guard to march on you. Go while you can.

  option=Look at me. Then count how many of you want to die.|intimidate|partystat:str>=14
  shows:  [Party STR 14] Look at me. Then count how many of you want to die.

  option=(Lift the key from his belt.)|steal|stealthy
  shows:  [Sneaking] (Lift the key from his belt.)

The rule: like every other condition, an answer whose check fails is
hidden - the tag only appears on answers the party can actually pick. So
always keep an ordinary answer next to a checked one.

stat: reads the hero (with gear); partystat: the best living member, so a
strong companion can do the intimidating. Habits used by the base game:
CHA to persuade or bluff, STR (party) to intimidate, WIS to spot a lie or see
what someone hides, INT to reason or fix things. Starting stats are 6 to 14;
12 is a real investment for most heroes, 14 is hard.

Scripts read the same numbers with stat("cha") and partystat("str"), or any
condition with cond("stat:cha>=12").

== quest.routes | More than one way through a quest
see: concepts.statchecks, concepts.conditions, obj.npc.show, obj.enemy.hide, dlg.actions

Since 1.4.0 several side quests can be finished by fighting, talking (stat
checks), paying (gold, or standing with a town) or sneaking (the stealthy
condition). The pattern, using the Stolen Caravan (Thornhollow) as the
example:

- Each route sets the quest's usual "done" flag (q_caravan_done) and one flag
  of its own (caravan_talked, caravan_ransom, caravan_stolen), so the
  quest-giver can thank each route differently.
- Quest stages: the last true stage wins, so put a stage per route after the
  plain one: stage=caravan_talked | Harl's band left Thornhollow...
- Make the world show it: enemy groups with hide=caravan_bandits_gone leave
  the camp, an NPC placement with show=caravan_bandits_gone turns up in
  town, rep= moves a town's standing (and with it shop stock item=id:n:rep).
- A sneaking route is a trigger with require=...&stealthy (and a second one
  with !stealthy that only logs a hint).

Base game: the Stolen Caravan (fight / talk / pay / sneak), the Hermit's
Riddle (items / WIS or INT answer / steal while stealthy), Water Rights
(buy or patch the valve; free / toll / CHA middle way / buy the claim) and
Ashwing (fight / reason INT / persuade CHA / pay 400).

== concepts.scripts | Action lists (script=, onuse=, ondefeat=, onclear=, bossdefeat=)
see: scripting.hooks, dlg.actions, obj.trigger.script, obj.enemy.ondefeat, obj.obstacle.onclear, dungeon.bossdefeat

A script is a list of actions run in one go, written on a single line. Actions
are separated by ; and each one is key:value - the same keys as dialogue
actions, but with : instead of = between key and value.

  set:q_main=7;notify:The chief is dead. Return to the Elder.
  flag:rift_shard_found;item:rift_shard;notify:A Rift Shard lies among the bones.
  dialogue:cult_aftermath
  message:Old Shrine|The stones hum under your hand.
  teleport:crypt,10,4

Only the first : splits the key from the value, so values may contain more
colons (item:mayor_seal:1, set:q_main=7). Actions run left to right. Use
dialogue:<id> to open a whole conversation from a trigger or a kill.

Used by: trigger script=, enemy ondefeat=, obstacle onclear=, dungeon
bossdefeat=. The full action list is in the Dialogue actions topic.

script:<id> runs a whole script (Scripts tab) - variables, talk with
answers, loops. Use one when a line of actions isn't enough.

Gotchas:
- A ; always ends an action, so message and notify texts cannot contain one.
- Actions that open something (dialogue, message, shop, combat, teleport) should usually come last.
- Setting a flag here re-checks the current map at once: doors with openif=, changes and moved NPCs update immediately.

== concepts.encounters | How random encounters work
see: map.encounter, map.table, tilekind.encounter, tilekind.biome, tab.encounters, table.usedby

Random fights ("Ambush!") are rolled after every step the party takes on a map
whose header has encounter= above 0, as long as no placed enemy group noticed
the party on that step.

- 1. The chance in percent is: map encounter x encounter weight of the tile kind the party stands on, divided by 2. Example: overworld encounter=4 on forest (weight 4) gives 8% per step; on road (weight 1) 2%.
- 2. Modifiers: stealth (the Stealth spell) divides it by 4; at night it is x1.5; rain or storm x0.75; fog x1.25.
- 3. If the roll succeeds, the table is chosen from the tile kind's biome. At night the game first looks for a table named <biome>_night, then <biome>. If neither exists it uses the map's table=. If none of those exist, nothing happens.
- 4. Tiles with biome loc (overworld location markers) never ambush.
- 5. One group= line of the table is picked at random. Its monsters get +1 level for every 3 hero levels above the table's level=.

So a tile with encounter weight 0 never rolls, whatever the map rate is. Interior
and dungeon tile kinds have weight 0 by default: to get random fights in a cave
you must give its floor kind a weight (or make a copy of the kind just for that
map).

On a map with touch=1 (map.touch) a random fight doesn't start at once: the
group appears 5 to 8 steps away and chases the party step for step, so it
can be fought or outrun. One such group at a time; it goes away once it has
lost the party.

Coach ambush: travelling by coach rolls once per 12 tiles of distance (at least
once), 22% each, 11% with stealth active. On an ambush the party arrives next
to the destination on the overworld and a fight starts at once, using the biome
under them (plains if that is a loc tile) - also on a touch=1 map. This forced
fight ignores the map rate and tile weight.

Placed enemy groups ([enemy] objects) are not random encounters: they fight
when the party comes within their aggro range (on a touch=1 map, when they
touch it).

== concepts.worldmap | The world map (M)
see: campaign.worldmap, map.worldmap, item.effect, location.reveal, dlg.actions, quest.stage.pin, tab.world

The world map opens with M or from the pause menu. What it shows depends on the
campaign's worldmap= setting (Campaign tab, "World map" control):

- overworld (the default): M shows the overworld. It fills in as the party walks it, and lists the overworld locations the party has visited or seen. Quest pins (yellow) and bounty pins (cyan) mark places.
- off: there is no world map. M and the pause menu entry just say there is no map, and the journal's "show on map" is hidden.
- current: an automap. M shows whichever map the party is on, revealed as they explore it.
- a map id (for example castle_hall): M always shows that map, like a floor plan of a castle's main hall. The places listed on it are its exits, named after the map each one leads to, and they appear once the exit tile has been seen. A quest pin can name a map id that one of those exits leads to.

A single map can override this with worldmap= in its own header (self, off,
overworld or a map id): for example every map of a sewer can say
worldmap=sewer_hub so M shows the sewer plan down there and the overworld
everywhere else. See map.worldmap.

Coach travel (NPCs with travel=1, dialogue travel=1) only works in overworld
mode. The coach goes only to places already visited, for 8 gold plus 6 per
league (10 tiles).

Filling the map in on purpose:
- Dialogue or script action revealmap=<map id> reveals that whole map. revealmap=<map id>,x,y,r reveals a circle of radius r around x,y. Use it for a lookout tower or a scout's report.
- Map items: a consumable with effect=revealmap:<map id> (or revealmap:<map id>,x,y,r) reveals it when used. The base game's Surveyor's Map (map_aldmoor, sold at the Brasswick market) reveals the whole overworld.
- Overworld location key reveal=N: entering that location's map reveals the overworld within N tiles of the location. Handy for a campaign that is mostly interiors, so its overworld map still fills in.
- Dev console: reveal reveals the current map.

== concepts.tiles | Tiles, sprites and the tileset
see: tab.tileset, tileset.browse, tab.tiles, creature.sprite, creature.size, class.spriterow

All art comes from sprite sheets. The base game's is assets/tiles.png (the
Urizen 1-bit set): a grid of 206 columns by 50 rows of 12x12 pixel cells. A tile
is written as col,row counting from 0 at the top left, for example 26,6 (iron
sword icon) or 104,0 (a human). A campaign can have more sheets of its own
(Tileset tab); a tile on one of those is written col,row@name, for example
3,1@forest. Every tile or sprite field has a "pick..." button that opens the
tile picker; the Tileset tab shows coordinates as you hover.

Black pixels are transparent. A tint (tile kinds) multiplies the art's colours;
a color= on an NPC or creature repaints the white parts in that colour.

Characters: column 104 holds the base pose of every character "race", one per
row (0 human, 2 skeleton, 4 goblin, 5 orc, 10 elf, 11 dwarf, 15 bandit, 18
knight, 21 mage, 26 priest, 27 ranger, 32 zombie, 33 golem...). The columns to
the right are the same figure with gear: 105 sword, 106 axe, 107 dagger, 109
staff, 110 spear, 113 shield, 116 gun, 117 bow. So 105,18 is a knight with a
sword. Classes use spritecol/spriterow, creatures sprite=col,row or
spriterow (col 104).

Big monsters: size=2 means the sprite is the 2x2 block whose top-left cell is
the sprite tile (col,row; col+1,row; col,row+1; col+1,row+1). Pick the top-left
cell. The editor previews the whole block and marks 2x2 enemies on maps.

Map cells use tile kinds rather than raw tiles: a kind has one or more ground
tiles (one picked at random per cell) and an optional prop drawn on top.

== concepts.colors | Colours
see: tilekind.tint, tilekind.bg, map.bg, obj.npc.color, creature.color

Colours are written r,g,b with each part from 0 to 255:

  255,255,255   white
  200,160,90    sandy brown
  20,40,20      very dark green

Colour fields in the forms are three number boxes with a swatch; the wheel
nudges a value (Shift = 10 at a time).

Where colours are used:
- Tile kind tint: multiplies the ground tile's colours. White leaves the art as drawn.
- Tile kind bg: fills the cell behind the art (the tileset's black is transparent).
- Map bg: fills the screen around and behind the map.
- NPC and creature color: repaints the sprite in that colour (recolouring, not tinting) - good for a red-robed cultist or a pale ghost made from an existing sprite.

A missing colour field means: tint white, bg black, map bg black, and no
recolour for sprites.

== concepts.ending | The ending (epilogue.txt, credits.txt)
see: concepts.scripts, concepts.conditions, concepts.campaigns

The win= action (in a dialogue or a script) ends the story: its lines play as a
cutscene, the flag game_won is set, and then the ending screens follow:

- 1. Epilogue slides from epilogue.txt, one at a time.
- 2. "The Journey": time, days, level, quests, kills and the rest, with the party.
- 3. The credits from credits.txt, scrolling.
- 4. "Keep exploring" (back to the map; an autosave is made) or "Return to desktop".

epilogue.txt is a list of [slide] blocks. Each has a group=; within a group the
FIRST slide whose if= condition is true is shown and the others are skipped, so
put the most specific slide first and a slide without if= last as the fallback:

  [slide]
  group=bram
  if=joined_warrior&approval:warrior:60
  title=Bram
  member=warrior
  text=Bram trained Hollowmere's first militia.|A | starts a new paragraph.

Keys: title=, text=, if= (any condition), tile=col,row (a picture), member=class
(that companion's portrait as it looks in the party), color=r,g,b (tint).
Text may use $hero, {days} (written "one day" / "N days" when followed by
"days"), {kills}, {level}, {campaign} and the quest counters.

credits.txt: one line per line; "= Title" is a big heading, "- text" a small
gold heading, an empty line a gap. A campaign can ship its own copies of both.

== concepts.saves | Saves and patches (migrations.txt)
see: concepts.ids, concepts.flags

Saves are plain text in saves/ (slot1-3.sav, autosave.sav). Each save says which
format it was written in (version= in its [game] section). Before every save the
old file is kept as .bak; a damaged save loads the .bak instead.

Renaming an id after people have saves (a patch): add the old and new id to
migrations.txt and old saves follow the rename when they load:

  [rename]
  item=old_sword>iron_sword
  flag=q_old>q_new
  map=old_cave>greywood
  spell=old_spell>new_spell

An item id that no longer exists (and has no rename) is dropped with a line in
the message log; the rest of the save loads normally.

== editor.import | Import from another campaign
see: concepts.campaigns, editor.search, editor.check

Every tab that holds campaign content has an Import button at the top of its
list (Maps, Tiles, World, Items, Creatures, Spells, Classes, Shops, Encounters,
Quests, Dungeons, Dialogue, Recipes, Affixes, Banter, Achiev., Campaign, Flags,
Bounties, Factions, Objects, Resources). Sounds and the Tileset are shared by
every campaign, so there is nothing to import there.

The window lists the other campaigns on the left (the base game first). Pick
one, tick what you want (the find box narrows the list, "Tick shown" ticks
everything it shows) and press Import.
- Entries (items, creatures, quests...) arrive unsaved: Save the tab to keep them, Revert drops them.
- Maps and dialogue files are copied into the campaign's folders at once.
- Something you already have with the same id is marked "replaces it" and is replaced.
- Only what you tick comes along: an imported creature's spells or loot, a map's dialogue and NPC items stay behind. Check all lists anything missing.

== editor.search | Search and filters
see: editor.import, start

Every list has a search box at the top. Type one or more words: an entry is
shown when every word appears somewhere in it. In the data tabs that means any
field (id, name, type, loot, faction, description...), in Dialogue the file
names and the text, in Tiles the name, biome and "water" / "blocked".

The Filter button next to the search box (data tabs) picks a field, then one of
its values with a count of how many entries have it - type = weapon, faction =
undead, station = forge. Lists like loot=a,b,c or materials=ore:2 offer each
id. "(any value)" shows entries that have the field at all, "(missing or
empty)" the ones that don't. The filter shows under the search box; its x
clears it. The list header says how many entries are shown.

The pickers (the v buttons) have the same search box: just start typing.

== concepts.campaigns | Campaigns
see: tab.campaign, concepts.files, campaign.start, campaign.worldmap

A campaign is a whole separate game with its own desktop icon. The base game
(Triffall) is one campaign; others live in assets/campaigns/<id>/. Saves
remember which campaign they belong to.

To make one:
- 1. Click the Campaign button in the header and choose "+ New campaign...". Type a name.
- 2. Editor creates an empty folder: just campaign.txt with the name. Every tab starts empty (since 1.1.6).
- 2b. Fill it in: each tab's list has an Import button (see editor.import) that copies items, monsters, classes, maps, dialogue, tile kinds... in from the base game or another campaign. Or make your own with New. The first map you make with New becomes the start.
- 3. Open the Campaign tab: set the name, description, icon, intro lines, opening dialogue and starting gold/items/flags.
- 4. Paint maps in the Maps tab. New games start on the yellow START tile; press B over a tile to move it.
- 5. Press "Play from the start" to try it as a player would.

While a campaign is selected the editor shows only that campaign's own files,
never the base game's. Tiles, sprites and sounds are shared by all campaigns.

Advanced: inherit=1 in campaign.txt makes a campaign build on the base game.
Files it lacks then come from assets/data and entries it defines replace base
entries with the same id. Base entries show as "(base)" in the lists; editing
one copies it into the campaign.

== concepts.ambient | Ambient sound
see: tab.sounds, maps.header

The base game has no ambient loops (since 1.3.1: they no longer fitted the
game). A campaign can still add its own: in the Sounds tab make an entry and
set its kind to ambient (the kind button cycles sfx / music / ambient); it is
written to sounds.txt as an [ambient] entry and follows the player's Ambience
volume.

A map then names its loop: the ambient field on the second header row of the
Maps tab (the v button lists every [ambient] entry), or ambient=<id> in the map
header. Generated dungeons take ambient= from their dungeons.txt entry. Empty
or none = silence. Weather and the time of day don't change it.

== tab.maps | Maps tab
see: maps.tools, maps.objects, maps.select, maps.header, maps.check, maps.play, maps.arrival, maps.start, maps.resize

The Maps tab paints maps and places the things on them. Left column: the list
of the campaign's maps, New / Save / Revert / Check, the tools, and the brush
palette. Right: the map header fields on top and the map view below.

Making a new map, step by step:
- 1. Press New and type the map id (it becomes maps/<id>.txt). You get a 30x20 grass field ringed with trees.
- 2. Fill in the header: name, kind (town, interior, dungeon...), spawn. Set size and press Resize if you need it bigger.
- 3. Pick a tile kind in the palette (type in the filter box to find it) and paint with Paint, Fill or Rect. Red names in the palette are kinds you cannot walk on.
- 4. Switch to Objects, choose an object type (npc, exit, chest...) and click the map to place it. Edit its fields in the panel that appears.
- 5. Add at least one exit so the party can leave, and connect the map from somewhere: an exit on another map, an overworld location (World tab, map=), or a dialogue teleport.
- 6. Press Check, fix what it reports, then Save (Ctrl+S).
- 7. Press Play > to walk around in it.

Map view markers: green S = spawn point, purple A = where an overworld
location drops the party, yellow START = where new games begin. The info line
at the top right names the tile under the cursor, its kind, and any object
there.

Every paint, fill, rect, object placement, deletion, paste and resize can be
undone with Undo or Ctrl+Z (40 steps). Switching maps with unsaved changes asks
first.

== tab.tiles | Tiles tab
see: concepts.tiles, tilekind.name, tilekind.ground, tilekind.prop, tilekind.walkable, tilekind.encounter, tilekind.biome

Tile kinds are the building blocks of every map: each map cell is one kind,
such as grass, wall_stone, door_wood or torch. A kind says what the cell looks
like (ground tiles, prop, tint, background) and how it behaves (walkable,
blocks sight, water, encounter weight and biome, move cost, footsteps, light).

The list on the left shows every kind with a small preview; red names are not
walkable. The form on the right edits the selected kind. At the bottom of the
form you see a 2x preview and how many cells of the map open in the Maps tab use
this kind.

Common tasks:
- Fix a wrong-looking tile: select the kind, click "..." next to the prop or a ground tile and pick the right art. Every map using the kind changes.
- Make a variant: select a kind and press New. It copies the selected kind as <name>_new; rename it and change what you need. For example a cave floor with an encounter weight for one dungeon.
- Jump from a map: in the Maps tab press K over a cell (or "edit" next to the brush). < Back or Esc returns to the map.

Save writes tilekinds.txt. Light: kinds such as torch, brazier, campfire,
crystal and streetlamp light up dark maps around them. The radius comes from
light=N in tilekinds.txt (the built-in kinds have sensible defaults).

Joined pieces (paths, rivers, shores, bridges, streets): some kinds pick their
picture from their neighbours. In tilekinds.txt, edges= lists 16 ground tiles
chosen by which of the four neighbours connect (N=1 E=2 S=4 W=8, add them up;
the first entry is for none, the last for all four), join= names the groups a
kind belongs to and link= the groups its pieces connect to. under=1 puts the
ground colour of the neighbours under the cell, so a trail or a shore sits on
whatever grass, sand or snow is next to it, and a chair or a rock stands on
the floor around it. recolor=1 paints the ground flat in the tint colour.
These fields are kept when the Tiles tab saves, but are edited in the file.
For example paint "path" for a one-cell trail, "street" for a paved square,
"floor_water" for a pond (its shore draws itself) and "bridge" across it.

Gotchas: deleting a kind turns every cell that used it into void. Renaming a
kind breaks maps that use the old name - make a new kind instead.

== tab.world | World tab
see: world.preview, world.bake, location.id, location.map, concepts.worldmap, maps.arrival

The World tab places the overworld locations: towns, caves, ruins and every
other place the party can enter from the overworld. Left: a preview of the
whole overworld with red markers (yellow = selected). Right: the location list
and the selected location's fields.

To add a place:
- 1. Press New in the list. Give it an id and name.
- 2. Set kind to the marker tile (loc_village, loc_cave, loc_tower...).
- 3. Set map to the map it enters (a map file or a dungeon id).
- 4. Click on the preview to move the location there.
- 5. Set tx,ty to where the party arrives inside the map, or open that map in the Maps tab and press N over the tile. 0,0 means the map's spawn.
- 6. Inside the target map add an exit to overworld with tx,ty next to the location, so the party comes out beside the marker.
- 7. Press "Save locations".

The overworld itself is either generated from the world seed (with roads and
clearings made from the location list) or, once baked, a hand-painted map in
the Maps tab. See World > Bake.

== tab.items | Items tab
see: item.id, item.color, item.type, item.effect, item.dmg, item.def, concepts.ids, editor.usedby, editor.undo

Items are weapons, armour, potions, keys, materials and ammo (items.txt). The
list on the left has a filter box; New adds an item with the common keys,
Duplicate copies the selected one (a fast way to make a stronger variant),
Delete removes it. The form on the right shows the item's keys: stats are
number fields, damage is a from-to pair, types and damage types are dropdowns,
tile has a picker, resistances and stat bonuses are rows of six numbers. The x
at the end of a row removes that key. "add key" adds any key; the buttons next
to it add common keys the item does not have yet.

The Look card at the top of the form (1.1.8) shows the item's picture large,
in a menu and on the ground. Pick sprite opens the sheet as it is; the colour
row sets the item's colour (see item.color): every item picture is a single
colour, so it can be drawn as a white shape in any colour. Without a colour
the picture keeps its own colour from the sheet (shown as the starting
value). The swatches are the colours the items already use plus the sheet's
most used ones; hover one to see who uses it. Sheet colour goes back to the
picture's own colour; Lighter and Darker nudge the current one.

Making a new weapon:
- 1. Select a similar weapon and press Duplicate.
- 2. Change id and name, pick a new tile.
- 3. Adjust dmg, ap, stat, accuracy and crit; set value for its price.
- 4. Save. Add it to a shop (Shops tab), a chest or a creature's loot.

Only the keys that matter for the item's type have an effect: def means
nothing on a potion, heal nothing on a sword.

The "Used by" box under the fields lists every chest, shop, creature,
recipe, dialogue and condition that uses the selected item; click a line to
go there. Ctrl+Z / Ctrl+Y undo and redo changes in the form.

== tab.creatures | Creatures tab
see: creature.id, creature.sprite, creature.ai, creature.loot, creature.level, tab.encounters, editor.usedby

Creatures are every monster and enemy fighter (creatures.txt). The same list
and form layout as the Items tab; sprites have a picker and preview (2x2 when
size=2, recoloured when color= is set).

Making a new monster:
- 1. Duplicate a monster of about the right strength.
- 2. Change id, name and sprite (pick a character row at column 104, or a single sprite).
- 3. Tune hp, stats, dmg, def, res, apmax and move. Choose ai.
- 4. Set xp, level, gold and loot.
- 5. Save, then use it: an [enemy] group on a map, an encounter table group, a dungeon's monsters or boss, or a dialogue combat=.

Placed groups and random encounters can be levelled up beyond the creature's
own numbers: each level bonus adds +1 to every stat, +6 HP, +1 damage and some
defence and XP.

== tab.spells | Spells tab
see: spell.id, spell.target, spell.area, spell.effect, spell.utility, spell.level, class.learn, editor.usedby

Spells are spells and class abilities alike (spells.txt): Fireball, Heal, War
Cry and Volley are all spells. The usual list and form; target, effect,
utility and damage type are dropdowns.

A spell does whatever its keys add up to: dmg deals damage, heal heals, effect
applies a status, utility does something outside combat, area makes it hit a
radius. Mix freely: a frost bolt is dmg + effect=freeze.

To give a spell to the party: add it to a class's spells= (known from rank 1)
or learn= (rank:spell), or let an item cast it with spell=. Monsters use spells
listed in their spells= (with ai caster, support or boss).

Outside combat only spells with a utility, a heal, or effect cure/revive can be
cast from the Spells menu.

== tab.classes | Classes tab
see: class.id, class.stats, class.hd, class.learn, class.sprite, dlg.actions

Classes are the hero's starting choices and every companion's class
(classes.txt). Triffall uses multiclassing: each level gives one rank point to
spend on any class. HP and MP grow with the hit and mana die of the classes
ranked up, and spells unlock by rank in that class (learn=).

Companions are NPCs (NPCs tab) with companion=<class id>; they join through
the dialogue action join=<npc id>. The class decides their stats, gear and
spells (the NPC can change those) and the joined_<class> flag; their banter
uses class= of the same id. So each companion needs their own class.

The order of classes in the file is the order on the character creation screen.

== tab.shops | Shops tab
see: shop.id, shop.hours, shop.item, obj.npc.shop, dlg.actions, editor.usedby

A shop is a stock list with opening hours (shops.txt). Shops do nothing on
their own: an NPC opens one, either with shop=<id> on the map object (when the
NPC has no dialogue) or with a shop=<id> action in a dialogue node (the usual
way, so the merchant can greet the player first).

Making a shop:
- 1. Press New, give it an id such as millbrook_smith.
- 2. Set hours (for example 8-18) or leave it empty for always open.
- 3. Add stock with item lines: the "pick..." button chooses an item; add :N to limit stock.
- 4. Save, then add shop=millbrook_smith to the merchant's dialogue.

Prices come from each item's value and the hero's CHA. While a shop with hours
is closed, the front door of the building its merchant stands in is locked
(inns never lock, and anyone already inside can always walk out).

== tab.encounters | Encounters tab
see: concepts.encounters, table.id, table.group, table.level, table.usedby

Encounter tables (encounters.txt) are the lists of monster groups that random
fights pick from. A table is chosen by the biome of the tile the party stands
on, with a <biome>_night variant at night and the map's table= as the fallback.

The list marks tables nothing uses as "(unused)". Select one to edit its id,
level and group lines; the "+ add" button on a group adds a creature. The
"Where this table is used" panel shows every tile kind, map and dungeon that
reaches the table and its day/night partner - click an entry to jump to it.

Adding random fights to a new region:
- 1. Make a table, for example id=marsh with level=4 and a few group= lines.
- 2. In the Tiles tab give the region's tile kinds biome=marsh and an encounter weight (1-6).
- 3. On the map that uses those tiles set the header encounter= (4 is the overworld's rate).
- 4. Optional: add marsh_night with nastier groups.
- 5. Check the "Where this table is used" panel: it should list your tile kinds and map, with no warnings.

== tab.quests | Quests tab
see: quest.id, quest.stage, quest.stage.when, quest.stage.text, quest.stage.pin, quest.stage.done, quest.objective, quest.preview

Quests (quests.txt) are journal entries driven entirely by conditions. Nothing
"starts" a quest: the journal shows the LAST stage whose condition is true, and
a quest with no true stage is not shown at all. So you write the stages in
story order and let flags move the quest along.

The form shows each stage as a numbered card:
- Shows when: the stage's condition, with a "+ flag" picker and a plain-English reading under it ("q_main is at least 2 and you do NOT have item rift_key").
- The journal text.
- DONE checkbox: greys the entry out and counts the quest as finished.
- Map pin: the place the stage points to.
- "+ objective": checklist lines shown under the quest while this stage is current (see quest.objective).
- Move up / move down, delete, and "+ stage" to add one. Objectives move and delete with their stage.

Under each card the flags it uses are listed with where they are set, so you
can spot a stage that can never show.

Writing a quest:
- 1. New quest: id and name.
- 2. Stage 1: Shows when q_fish>=1, text "Old Tam wants three river trout.", pin the river.
- 3. Stage 2: Shows when q_fish>=1&itemn:trout:3, text "You have three trout. Take them to Tam."
- 4. Last stage: Shows when q_fish>=2, tick DONE.
- 5. In dialogue, set=q_fish=1 when Tam asks, set=q_fish=2 when you hand them over, and quest=Old Tam's Trout for the popup.
- 6. Use the Preview box to tick flags and check which stage shows.

== tab.dungeons | Dungeons tab
see: dungeon.id, dungeon.style, dungeon.monsters, dungeon.boss, dungeon.exit, dungeon.bake

Dungeons (dungeons.txt) are generated maps: rooms or caves, monsters, chests,
a boss, ore and herbs, a save shrine near the entrance, all built from a few
settings and a seed. Any exit, location or teleport can lead to a dungeon's id
like any map.

Making a dungeon:
- 1. New, set id and name, choose a style (cave, crypt, castle, tech, ship, mine, sewer), size w/h and level.
- 2. monsters: the pool groups are picked from. boss and bossflag for the end fight; bossdefeat for what happens then.
- 3. exit: where the entrance stairs lead back to (overworld,x,y next to its location).
- 4. Add an overworld location with map=<dungeon id> in the World tab.
- 5. Save and playtest. Change seed to roll a different layout.

Bake map turns the current layout into maps/<id>.txt so you can hand-edit it.
Once a map file with the dungeon's id exists the game uses that file, and the
dungeon entry only matters again if you delete the file. All shipped dungeons
are baked.

== tab.dialogue | Dialogue tab
see: edit.text, dlg.nodes, dlg.options, dlg.actions, dlg.camp, dlg.check, editor.usedby, concepts.conditions

The Dialogue tab is a text editor for dialogue files (dialogue/<id>.txt) with
a syntax cheat-sheet on the right. Left: the file list, New, Save, Delete,
Check and Check all. Lines are coloured: [node] headers, option= lines and
speaker= lines stand out.

A dialogue file is a set of nodes. The conversation opens at [start]; options
lead to other nodes or to end. Actions in a node run the moment it shows.

  [start]
  speaker=Old Tam
  text=Fish aren't biting, $hero. Haven't been since the lights.
  option=I could help.|help|!q_fish>=1
  option=Goodbye.|end

  [help]
  text=Bring me three trout from the north bank and I'll pay you.
  set=q_fish=1
  quest=Old Tam's Trout
  option=Deal.|end

Hook a file to an NPC by setting the NPC's dialogue=<file id> in the Maps tab
("pick dialogue" in the object panel). Check finds broken links before you
playtest. The "Used by" box at the bottom of the right panel lists the NPCs,
scripts, other dialogues and campaign start that open the file.

== tab.sounds | Sounds tab
see: sound.triggers, sound.crunch, sound.id, sound.kind, sound.files, sound.volume, item.sound, map.music

Every sound effect and music track the game plays is an entry here
(sounds.txt): an id that the game or your data asks for, and the audio file(s)
it plays. The audio files live in assets/audio (sfx/ and music/), shared by all
campaigns.

The list shows effects, and music tracks marked [music]. "group" above it
narrows it to one kind of sound (Interface, Exploring, Footsteps, Combat,
Spells, Music...). Below the entries come the game's triggers that have no
entry of their own, shown as "trigger > the sound it plays" (see
sound.triggers).

The form edits the id, kind, description, files, volume, pitch and volume
variation and crunch (effects) or looping (music), and has Play / Stop
buttons. "Played when" says when the game itself plays it, which triggers
borrow it, and which items, spells, creatures, objects, tile kinds, maps,
dialogue and scripts ask for it.

Replacing a sound: either drop a new file over the old one in assets/audio, or
select the entry and use "change" on its file. Adding a sound: "+ import new
file..." copies a .wav/.ogg/.mp3 into assets/audio, or "New sound" makes a new
event you can set as sound= on an item, spell or creature.

Music is chosen automatically by map kind unless a map or dungeon sets music=.

== tab.tileset | Tileset tab
see: sheet.campaigns, sheet.import, sheet.categories, sheet.groups, tile.picker, tileset.browse, concepts.tiles

The campaign's sprite sheets: the pictures every tile, sprite and icon comes
from. On the left, the sheets this campaign has (with Import picture..., Copy
base game's, Grid..., Reload and Remove), the categories and the groups; on the
right, the chosen sheet as it is laid out, every tile marked with a coloured line
in its category's colour.

Sorting tiles:
- Click a tile to select it, drag to select a block, Ctrl+click to add or take
  away one, Shift+click to add the block from the last tile clicked. Ctrl+A
  selects every tile shown (the category or group picked on the left).
- Keys 1 to 9 (or the coloured buttons under the sheet) give the selected tiles
  a category. Right-click for the same choices plus the groups.
- Click a category on the left to dim everything else; click it again for all.
- Groups: New... (with the selected tiles), Rename..., Delete, + Add selected
  and - Remove selected work on the group picked in the list.

Every change is saved at once into sheets/<name>.txt. The line at the bottom
shows the tile under the pointer: col,row (with @sheet when it isn't the main
sheet), its category, its groups and what uses it.

== tab.recipes | Recipes tab
see: recipe.id, recipe.station, recipe.materials, recipe.difficulty, recipe.known, recipe.reveal

Recipes (recipes.txt) are what the crafting screens can make. A smith opens
the forge, an alchemist the alchemy bench, a tinker the workbench (NPC craft=
or dialogue craft=). Recipes with station any are made anywhere from the Items
menu (field crafting, C).

Each station has its own skill that rises as the party crafts there. Harder
recipes can fail (losing half the materials); a high skill can turn out fine or
masterwork results with extra affixes. Forges and workbenches also reinforce
gear (+1 to +3) and salvage it; alchemy benches enchant it with rift dust.

Making a recipe:
- 1. New: set result (the item made) and count.
- 2. Choose station, add materials with "+ add" (edit the :count), set gold and difficulty.
- 3. To make it a secret, set known=0 and give an item effect=learn:<recipe id> (a formula scroll).

== tab.affixes | Affixes tab
see: affix.id, affix.pos, affix.tier, affix.types, affix.mods

Affixes (affixes.txt) are the random "Keen ... of Burning" parts of loot
names. Equipment found in chests or dropped by monsters rolls a loot tier:
uncommon gets one affix, rare gets a prefix and a suffix. Each affix changes
the item's numbers (mods) and price (value).

An item never gets two prefixes or two suffixes. Affixes are only picked if
their types= include the item's type (or any) and their tier is not above the
rolled tier.

Making an affix:
- 1. Press New, give it an id and a name ("Frosted").
- 2. Choose pos (prefix or suffix), tier (2 or 3) and the item types it fits.
- 3. Add mods such as res_cold:15,def:1 and a value multiplier.
- 4. Save. New loot rolls can use it at once; items already in saves keep their old numbers until reloaded.

== tab.banter | Banter tab
see: banter.class, banter.when, banter.if, banter.flag, banter.text

Banter (banter.txt) is what companions say on their own: one-liners in a
speech bubble and the message log. Each entry belongs to a class (the
companion's class id, or any), fires at a moment (when=), can be limited to one
map, a condition and once per game, and has one or more text lines (one is
picked at random).

The hero never banters - only companions. How often they talk is a player
setting (Settings > General: off / rare / normal / often).

The list is labelled by class, so many entries share a label; select one to
see its when and text.

== tab.achievements | Achievements tab
see: achievement.id, achievement.cond, achievement.hidden, achievement.tile

Achievements (achievements.txt) unlock across all save slots of the game and
pop up Win98-style. Each has a name, description, icon and a condition made of
stat counters and flags, checked twice a second while playing. Unlocked ones
are stored in saves/achievements.ini and listed in the desktop Achievements
window (and sent to Steam in a Steam build).

Making one:
- 1. New: id, name and desc.
- 2. Write cond, for example flag:q_main>=7 or kills:100&level:10.
- 3. Pick an icon with tile, and tick hidden=1 for spoilers.
- 4. Save and playtest; the dev console's achieve ID unlocks one by hand and reset_achievements locks them all again.

== tab.campaign | Campaign tab
see: concepts.campaigns, campaign.name, campaign.start, campaign.intro, campaign.dialogue, campaign.worldmap, campaign.defeat

The Campaign tab is campaign.txt as a form: what the desktop icon and the New
Game window show, where a new game begins, the intro cutscene, the opening
dialogue, starting gold, items and flags, the world map mode and what a lost
fight does (If the party falls).

Order on New Game: character creation -> intro lines (one screen each) -> the
party appears on the start tile -> the opening dialogue opens.

Buttons: Save, Revert, "Show in Maps tab" (opens the start map at the START
tile) and "Play from the start" (saves, leaves the editor and opens New Game
for this campaign).

== tab.flags | Flags tab
see: concepts.flags, flags.status, flags.desc, flags.rename, concepts.conditions

The Flags tab lists every flag the campaign uses, gathered from all of its
files:
- dialogue: set=, flag=, inc=, clear= and option conditions
- map objects: chest, enemy, trigger, door, obstacle and lever flag=; show=, hide=, moveif=, openif=, require=, if=; and scripts
- quest stage and objective conditions, dungeon bossflag (and bossdefeat scripts), achievement flag: terms, banter if= and flag=, location require=, the campaign's starting flags
- built-ins: joined_<class> from every join=, game_won from win=

Select a flag to see "Set by" and "Checked by" lists; click an entry to jump to
that file, line or map object. Each flag has a status and an optional
description you type yourself.

"New flag" documents a flag before you use it anywhere, so it shows up in the
"flag" pickers that flag fields in other tabs now have.

"Rename everywhere..." renames the selected flag in every file that uses it
and saves them (see flags.rename).

== maps.tools | Map painting tools
see: tab.maps, maps.select, maps.objects, editor.shortcuts, tab.tiles

The Tools box under the map list:

- Paint: hold the left button and drag to paint the brush onto cells.
- Fill: click a cell to flood-fill every connected cell of the same kind with the brush.
- Rect: drag a rectangle and release to fill it; hold Shift when releasing to draw only its outline (walls for a room).
- Objects: place, select and drag map objects (see Map objects).
- Erase obj: click an object to delete it.
- Select: drag a region to copy, cut, stamp or clear it (see Select, copy and paste).

The brush is the tile kind shown after "brush:". Pick it from the palette (type
in the filter box above it), or right-click any cell of the map to take its
kind. "edit" next to the brush jumps to that kind in the Tiles tab.

1x / 2x zoom the view; grid draws cell corners at 2x; objs shows or hides
objects and markers. Undo steps back (Ctrl+Z), Copy / Paste / Clear act on the
selection.

Scroll the view with middle-drag, the wheel (Shift+wheel sideways), WASD or the
arrow keys. The hint line at the bottom of the view lists the keys for the
active tool.

== maps.objects | Placing map objects
see: tab.maps, tab.objects, tab.resources, obj.npc, obj.enemy, obj.chest, obj.exit, obj.trigger, obj.door, obj.obstacle

Everything that is not plain terrain is an object listed below the map rows:
npc, enemy, chest, exit, trigger, sign, door, savepoint, obstacle, lever,
change, gather, and (1.4.0) crate and plate (see obj.crate, obj.plate).

- 1. Choose the Objects tool and click the object type under "place:".
- 2. Click an empty cell: the object is created there with a template of its usual keys.
- 3. The object panel opens at the right of the view. Edit the values; x removes a key; type a key name and press Add for extra keys; Delete removes the object.
- 4. Helper buttons: "pick dialogue" (npc), "pick map" (exit), "add creature" (enemy), "add item" (chest). Sprite fields have a "..." tile picker. 1.4.0: an obstacle's needs= has a + list of every way to clear it; action keys (onuse, onclear, onpress, onrelease, ondefeat, a trigger's script) have a + list of actions and scripts - a script shows its arguments and is added with their names for you to replace (scripting.puzzles).
- 5. Drag an object to move it. Click another to select it. With the Objects tool active, the Delete key removes the selected object.
- 6. Templates: pick one under "template:" (below the type buttons) and every click places a copy of it. A copy only writes what belongs to its spot (x, y, an npc's id, a chest's flag) and takes the rest from the template, so editing the template in the Objects tab changes every copy on every map.
- 7. "make template" in the panel turns the selected object into a template and links it. A copy shows its template's values dimmed under "from template ..."; "own" gives just that copy its own value. "detach" copies the template's values in and unlinks it.

The panel takes the mouse wheel when it is taller than the view. Clicks on it
never reach the map underneath.

Areas: exits, triggers, obstacles and changes cover w x h cells starting at
x,y (top-left). The view draws them as coloured rectangles.

Objects copied with Select keep their keys, so copying a finished house with
its NPCs and door into another map works.

== maps.select | Select, copy and paste
see: maps.tools, editor.shortcuts, tab.maps

With the Select tool, drag over empty map space to mark a region (it blinks).
Clicking an object instead selects that object and shows its panel.

- Ctrl+C copies the region's tiles and the objects inside it; Ctrl+X cuts (copies, then clears).
- Ctrl+V (or Paste) shows a ghost of the copy under the cursor. Click to stamp it; hold Shift while clicking to keep stamping copies. Right-click or Esc stops.
- Delete (or Clear) fills the region with the current brush and removes the objects in it.
- Ctrl+A selects the whole map.
- Right-click or Esc drops the selection.

The clipboard stays while you switch maps, so you can copy a room or a whole
house from one map and stamp it into another. Pasted objects keep all their
keys - change ids and flags that must be unique (chest flags especially).

== maps.check | Check (map problems)
see: tab.maps, maps.arrival, maps.start, dlg.check, editor.check

Check scans the open map and shows the number of problems and the first three
in the status bar. It looks for:

- objects (other than doors) standing on a blocked tile
- NPCs whose dialogue file does not exist
- exits leading to a map that is neither a map file, a dungeon nor the overworld
- enemy groups with unknown creatures, chests with unknown items
- a spawn point on a blocked tile, cells using an unknown tile kind
- the new-game START on a blocked tile
- an overworld arrival point on a blocked tile, or more than 3 tiles from the exit back out to the overworld

Check does not test conditions or flags; use the Flags tab, Dialogue Check or
the header's Check all (every map and file at once) for those. Run it after big edits and before playtesting.

== maps.play | Play > (playtest a map)
see: tab.maps, maps.start, start, campaign.start

Play > in the map header saves every tab with unsaved changes, leaves the
editor and puts the party on this map at its spawn point. Press P while
pointing at a tile to start on that tile instead.

If no game is running, a level-1 tester with 500 gold is created. If a game is
running, that party is moved here, keeping its flags, items and progress - so
you can test a late-game scene with a real save by loading it first.

Flags are not reset by Play, so a trigger with once=1 that already fired in
this game will not fire again. To test the real opening, use "Play from the
start" in the Campaign tab.

Back in the editor (open the Editor again from the desktop), your tabs are as you
left them.

== maps.arrival | Overworld arrival point (N)
see: location.tx, location.ty, tab.world, maps.check, obj.exit

When the party enters a map from an overworld location, it appears at that
location's tx,ty (0,0 = the map's spawn). The map view marks each such arrival
point with a purple A.

To set it: open the map, point at the tile where the party should appear
(usually just inside the entrance, next to the exit back out) and press N. Every
overworld location whose map= is this map gets tx,ty set to that tile, and
overworld.txt is saved at once.

Check warns when the arrival is on a blocked tile or more than 3 tiles from an
exit leading to overworld. If the arrival is blocked the game moves the party
to the nearest free tile, which may be the wrong side of a wall.

If N says no location enters the map, set a location's map= to it in the World
tab first.

== maps.start | New-game START (B)
see: campaign.start, tab.campaign, maps.check, maps.play

The yellow blinking START in the map view is where new games of this campaign
begin. Point at a tile and press B to move it there: the campaign's start= is
set to this map and tile and campaign.txt is saved at once.

You can also set it in the Campaign tab (start map, x, y). With x,y at 0,0 the
party starts on the map's spawn point.

Check warns when START sits on a blocked tile. Remember that the opening
dialogue opens right after the party appears, so the start tile is where the
player first looks around.

== maps.resize | Resizing a map
see: tab.maps, maps.header

The size boxes in the second header row show the map's width and height
(4 to 300). Change them and press Resize.

The map grows or shrinks from its top-left corner: rows and columns are added
or cut at the right and bottom. New cells are filled with the current brush,
so pick the right kind first (wall, void or grass).

Objects are not moved. After shrinking, objects outside the new edge stay in
the file but are out of bounds; move or delete them. To add space at the top or
left, resize, then Select everything (Ctrl+A), cut and paste it further down.
Resize can be undone with Ctrl+Z.

== maps.header | Map header fields
see: map.id, map.name, map.kind, map.spawn, map.dark, map.light, map.encounter, map.music, map.combatmusic, map.table, map.bg, map.worldmap, map.ambient, map.touch

The two rows above the map view edit the [map] header of the file:

  [map]
  id=old_mine
  name=Old Mine
  kind=dungeon
  spawn=4,20
  dark=1
  light=3
  encounter=0
  music=dungeon
  table=
  bg=0,0,0
  worldmap=

Fields left empty use their defaults. The id is the file name and is not
edited here. music, table and ambient have pickers (the v buttons); "fight"
picks the map's own fight music (map.combatmusic). Changes mark the map unsaved; save
with Save or Ctrl+S.

The id is never written by these fields; it comes from the file name you chose
with New. Hover a field's ? for its own topic. Most interiors only need name,
kind and spawn; dungeons add dark and light; outdoor maps with random fights add
encounter and, if their tiles have no matching biome tables, table.

== map.id | Map id
see: concepts.ids, map.name, obj.exit.to

The map's id is its file name: maps/old_mine.txt has id=old_mine. Exits
(to=), overworld locations (map=), teleports, quest pins in map-id world map
modes and dungeon exits all refer to maps by this id.

Format: lowercase letters, digits and _. Set when you press New in the map
list.

  id=old_mine

Gotchas: the id overworld is special - it is the overworld map (generated, or
maps/overworld.txt once baked). A map file with the same id as a dungeon
replaces that dungeon's generator. Renaming the file breaks every exit that
points at the old id.

== map.name | Map name
see: map.id, maps.header

The name the player sees: it pops up when the party enters the map, heads
the sign notes in the journal, and names exits on a map-id world map.

Format: any text. Default: empty (no popup).

  name=Hollowmere

Give every map a name, even small interiors ("Doss's Inn"), so the player knows
where they are.

== map.kind | Map kind
see: map.music, map.dark, banter.when, concepts.worldmap

What sort of place this is. It changes several behaviours:

- overworld: each step takes 3 game minutes (1 elsewhere); default music overworld.
- town: default music town; entering it sets the Recall spell's return point; banter when=town.
- interior: default music town; no weather and no night tint (indoors).
- dungeon: default music dungeon; banter when=dungeon.
- ruins or anything else: default music forest.

Format: one of the words above. Default: empty (behaves like "anything else").

  kind=town

Gotchas: dark=1 maps also count as indoors for weather and night, whatever
their kind. Generated dungeons are always kind=dungeon.

== map.spawn | Map spawn point
see: obj.exit.tx, location.tx, maps.play, maps.start

The tile x,y where the party appears when it enters the map with no specific
target: an exit or location with tx,ty 0,0, a teleport to x,y 0,0, Play >, or
the campaign start with 0,0. Shown as a green S.

Format: x,y in tiles from the top-left (0,0). Default: 1,1.

  spawn=20,29

Gotchas: if the spawn tile is blocked, the game moves the party to the nearest
free tile within 6 - Check warns about it. Put the spawn next to the main
entrance so a party arriving there can find the way out.

== map.dark | Dark map
see: map.light, item.light, tilekind.name, spell.utility

dark=1 turns on darkness: the party only sees what light reaches. Each member
glows with the map's light radius; torches, lanterns, the Light spell and
flares widen it; tiles such as torches, braziers and crystals light their
surroundings. Monsters in the dark are hidden, and attacking into darkness costs
accuracy unless the attacker has darkvision.

Format: 1 or 0. Default: 0 (everything visible).

  dark=1

Gotchas: dark maps count as indoors (no weather, no night tint). Place a few
light tiles (torch_wall, brazier) in important rooms so the player can see
them from a distance. Generated dungeons are always dark.

== map.light | Party light radius
see: map.dark, item.light, spell.power

On a dark map, the radius in tiles that each party member's own glow reaches
(a bare lantern). A lit torch (5), the Light spell or an equipped item with
light= can raise it; nothing lowers it.

Format: whole number of tiles. Default: 7. Generated dungeons use 3 (caves,
crypts), 4 (castles) or 5 (tech, ship).

  light=3

Gotchas: has no effect unless dark=1. Around 3 feels tense and makes torches
matter; 7 is almost a normal room.

== map.encounter | Random encounter rate
see: concepts.encounters, map.table, tilekind.encounter

How likely random fights are on this map. After each step the chance in percent
is this number x the encounter weight of the tile kind underfoot / 2 (then
modified by stealth, night and weather).

Format: whole number. Default: 0 = no random encounters at all. The overworld
uses 4.

  encounter=4

Gotchas: tile kinds with weight 0 never roll. That is every interior and
dungeon kind by default and the location markers, so on a cave map you also
need a floor kind with a weight. The Encounters tab warns when a table is reached by a
map whose rate is 0.

== map.music | Map music
see: tab.sounds, map.kind, map.combatmusic, dungeon.music

The music track played on this map. The v button next to the field lists every
music track of the Sounds tab. Fights switch to the fight music
(map.combatmusic, campaign.combatmusic) and boss fights to the boss music.

Format: the id of a [music] entry in the Sounds tab. Every base-game map names
its track (since 1.3.1). Default: empty = by kind - overworld, town (kind town
or interior), dungeon, or forest (anything else); the field then shows that
track greyed.

  music=tech

On the overworld, music=overworld (or empty) turns to overworld_night at night.

Gotchas: an id that does not exist is silent and is reported in the Sounds tab
under "events requested but not defined".

== map.combatmusic | Map fight music
see: campaign.combatmusic, creature.music, map.music, tab.sounds

The music for ordinary fights on this map, instead of the campaign's fight
music. In the Maps tab it is the "fight" button on the first header row
("fight*" when the map has its own); its list holds every music track.

Format: the id of a [music] entry. Default: empty = the campaign's fight
music (Campaign tab), which itself defaults to the combat track.

  combatmusic=tales_by_firelight

A boss, or any creature with its own music, plays that instead (creature.music). Generated
dungeons take it from dungeons.txt combatmusic= (baking copies it).

== map.table | Fallback encounter table
see: concepts.encounters, map.encounter, table.usedby, tilekind.biome

The encounter table random fights use on this map when the tile underfoot has
no matching table of its own (its biome has no table, or no biome at all). At
night a <biome>_night table is still tried first.

Format: a table id from the Encounters tab (there is a picker). Default:
empty.

  table=plains

Gotchas: the table is only consulted when a roll succeeds, and rolls need
encounter= above 0 and tiles with weight above 0. A tile whose biome has its
own table always uses that table instead.

== map.bg | Map background colour
see: concepts.colors, tilekind.bg

The colour that fills the screen behind the map: around its edges, and
through void cells.

Format: r,g,b. Default: 0,0,0 (black).

  bg=20,40,20

Pick a dark version of the map's main ground colour so the edge of a small
map does not look like a hole. Dark dungeons look best with black.


== map.ambient | Map background loop
see: concepts.ambient, tab.sounds, map.music, maps.header

A background loop played under the music on this map. The base game has none
(1.3.1); a campaign can add [ambient] entries in the Sounds tab. It is on the
second header row of the Maps tab; the v button next to it lists every
[ambient] entry.

Format: the id of an [ambient] entry, or none. Default: empty = silence.

  ambient=my_wind

Its loudness is the entry's volume in the Sounds tab times the player's
Ambience volume setting.


== map.worldmap | Map world map override
see: concepts.worldmap, campaign.worldmap, maps.header

What the M world map shows while the party is on THIS map, overriding the
campaign's worldmap= setting. It is on the second header row of the Maps tab.

Format: empty, self, off, overworld or a map id. Default: empty (use the
campaign setting).

- self: an automap of this map, revealed as it is explored.
- off: no world map here ("show on map" is hidden too).
- overworld: the overworld, even if the campaign uses something else.
- a map id: that map, with its exits as the listed places.

  worldmap=sewer_hub

Typical use: a sewer made of several maps where every one of them says
worldmap=sewer_hub, so pressing M underground shows the sewer plan, while the
rest of the campaign keeps the overworld. Or worldmap=self on one big
dungeon level in an otherwise overworld campaign.

Gotchas: a map id that does not exist is reported by Check all. Coach travel
still only works from the overworld world map.

== map.touch | Fights start by touch
see: obj.enemy, obj.enemy.aggro, obj.enemy.leash, obj.enemy.link, dungeon.touch, maps.header, concepts.encounters

When ticked, the enemy groups placed on this map only start a fight by
touching the party: a group (or the party) has to step right next to the
other, diagonals included. Seeing the party from afar is not enough. It is
the "touch" box on the second header row of the Maps tab; mainly meant for
overworld maps, but any map can use it.

Chases: a group that notices the party (within its aggro range, in line of
sight) chases it - one step for every step the party takes, never on its own.
Stand still and so do they; walk away and they keep the same distance; walk
towards them or get cornered and they catch you. Each group has a leash point
(where it was placed) and a leash range (obj.enemy.leash): once the party is
further than that from the leash point, the group gives up and walks back.

Random ambushes (encounter= and the tile kinds' weights, and the encounter
action) don't jump the party here: the group appears 5 to 8 steps away, in
sight when there is room, and chases from there (leash point = where the
party stood, range 12). Only one such group roams at a time. The coach's
ambush still starts the fight at once (the coachman script uses
encounter now).

Format: 1 or empty. Default: empty = groups attack when the party comes within
their aggro= range in line of sight.

  touch=1

Who joins: only the other groups that are touching the party too, and groups
sharing a link= with the one that started it. During the fight, a group joins
only when a fighter ends up right next to it (or it is linked), instead of
everything within earshot coming running.

Gotchas: set encounter=0 if the map should have only the placed groups. The
Stealth spell makes groups notice the party only from a third of their aggro
range (one already chasing keeps chasing). After the party flees a fight the
groups wait 8 steps before they chase again.

== obj.npc | NPC object (a placement of an NPC)
see: tab.npcs, obj.npc.npc, obj.npc.id, obj.npc.dialogue, obj.npc.sprite, obj.npc.show, obj.npc.hide, obj.npc.shop, obj.npc.moveif, maps.objects

A person or animal standing on the map. Since 1.1.9 the person is an entry in
the NPCs tab (npcs.txt) and the map object is a placement of it: npc=<id>,
its spot (x, y), its own id on this map, and when it is there (show=, hide=,
moveif=). Every key the placement doesn't set - or leaves empty - comes from
the NPC, so editing the NPC changes it everywhere it stands. A placement can
still set a key itself (Ilse has her own name= and dialogue= in her cell).

To place one: Maps tab > Objects > npc, then pick the NPC under the type
buttons (or "a new NPC") and click the map. From the NPCs tab, Place on map...
does the same. An old-style npc object with its own name/sprite/dialogue and
no npc= still works; select it and press make NPC to turn it into an NPC.

Walking into an NPC or pressing E next to it interacts with it. What happens,
in this order:

- 1. hostile= set: a fight with those creatures starts.
- 2. board= set: the notice board for that town opens.
- 3. travel=1: the coach / world map travel screen opens.
- 4. craft= set and no dialogue: that crafting station opens.
- 5. dialogue= set: the conversation starts.
- 6. shop= set: the shop opens (if it is open now).
- 7. Otherwise: "<name> has nothing to say."

  [npc]            (on the map)
  id=smith
  npc=smith_gorran
  x=33
  y=16

  [npc]            (in npcs.txt, the NPCs tab)
  id=smith_gorran
  name=Smith Gorran
  sprite=105,2
  dialogue=smith_gorran

NPCs block movement. show=/hide= make them appear and disappear with the
story; moveif= moves them once something happened; wander=1 lets them stroll
near their spot.

== obj.npc.id | NPC id
see: obj.npc, dlg.actions, concepts.ids

A short name for this NPC, unique on its map. It is used by the dialogue
actions npcmove=, hidenpc= and shownpc=, and the save uses it to remember
where a moved NPC stands and whether it has been hidden for good.

Format: lowercase id. Default: the NPC's id (npc=). A new placement gets the
NPC's id, or id_2, id_3... when that is taken on the map. This is the
placement's id, not the NPC's: renaming the NPC keeps it.

  id=elder

Gotchas: two NPCs with the same id on one map are moved and hidden together.
An NPC without an id can still be hidden by join=, combat= or hostile=, but
only until the map is loaded again. Changing the id after release loses a
moved NPC's saved position and hidden state.

== obj.npc.name | NPC name
see: obj.npc, dlg.nodes

The name shown as the speaker in the NPC's dialogue (unless a node sets
speaker=) and in messages such as "Mutt has nothing to say".

Format: any text. Default: the id.

  name=Healer Wren

Gotchas: a dialogue node with speaker= overrides this name for that node, so
the same dialogue file can be shared by several NPCs if its nodes leave
speaker= out.

== obj.npc.sprite | NPC sprite
see: concepts.tiles, obj.npc.color, tab.tileset

The tile drawn for the NPC on the map and as the portrait in dialogue.

Format: col,row in the tileset (the "..." button picks it). Default: 104,0 (a
plain human).

  sprite=105,18

Character rows are at column 104 (base pose) with gear variants to the right:
105 sword, 106 axe, 109 staff, 113 shield, 116 gun, 117 bow. Rows: 0 human, 10
elf, 11 dwarf, 18 knight, 21 mage, 26 priest... Animals and monsters have
single sprites elsewhere on the sheet (Mutt the dog is 4,14).

== obj.npc.color | NPC colour
see: concepts.colors, obj.npc.sprite, creature.color

Repaints the NPC's sprite (and portrait) in one colour, so one sprite can make
many different-looking people.

Format: r,g,b. Default: none (the sprite's own white).

  color=200,160,90

Gotchas: this replaces the colour, it does not tint, so all detail stays in the
same hue. Light colours read best on dark ground.

== obj.npc.dialogue | NPC dialogue
see: tab.dialogue, dlg.nodes, obj.npc

The dialogue file the NPC opens when the party talks to it; the conversation
starts at its [start] node.

Format: a dialogue id (file name without .txt). Use "pick dialogue" in the
object panel. Default: empty.

  dialogue=elder_mara

Gotchas: hostile=, board= and travel=1 win over dialogue=. craft= only works
without a dialogue - to have a smith talk first, put craft=forge as an action in
the dialogue instead. Check warns about missing files.

== obj.npc.wander | NPC wander
see: obj.npc, obj.npc.moveif

wander=1 lets the NPC take a random step every second or two, staying within 3
tiles of its home spot and never onto exits or the party.

Format: 1 or 0. Default: 0 (stands still).

  wander=1

Good for animals and villagers. Keep shopkeepers, guards and quest givers still
so players can find them. A moved NPC (moveif=, npcmove=) wanders around its new
spot.

== obj.npc.shop | NPC shop
see: tab.shops, shop.id, dlg.actions

Opens this shop when the party talks to an NPC that has no dialogue=. While the
shop is closed (outside its hours) the NPC says so instead.

Format: a shop id. Default: empty.

  shop=hollowmere_general

Usually it is nicer to give the merchant a dialogue with a shop=<id> action in
a node, so they greet the player and can offer other options. Either way the
merchant's shop, if it has hours, locks the building's door while closed.

== obj.npc.show | NPC show condition
see: concepts.conditions, obj.npc.hide, obj.enemy.show

The NPC is only there while this condition is true. Use it for people who
arrive later in the story.

Format: a condition. Default: empty (always shown).

  show=rook_freed

Gotchas: checked continuously, so the NPC appears the moment the flag is set,
even mid-conversation. If both show and hide are set, the NPC needs show true
and hide false.

== obj.npc.hide | NPC hide condition
see: concepts.conditions, obj.npc.show, obj.npc.id, dlg.actions

The NPC disappears while this condition is true. The standard way to remove a
companion's map NPC after they join, or a villager after they leave town.

Format: a condition. Default: empty.

  hide=joined_warrior

Other ways to remove an NPC for good: the dialogue actions join= and combat=,
a hostile= fight, and hidenpc=<npc id> all hide it permanently (saved per map
in the save file); shownpc=<npc id> brings it back. These need the NPC to
have an id.

Gotchas: hide= is the better choice when the NPC should come back once the
condition turns false again, or when it has no id. joined_<class> is set
automatically by join=.

== obj.npc.hostile | Hostile NPC
see: obj.npc, obj.enemy, dlg.actions

Talking to (or bumping) this NPC starts a fight with the listed creatures
instead of a conversation. The NPC vanishes as the fight begins.

Format: creature ids separated by commas. Default: empty.

  hostile=bandit,bandit_archer

Gotchas: the NPC stays gone after the fight (saved) only if it has an id;
without one it is back next time the map loads. Hostile NPCs have no
ondefeat script and set no flag, so for an ambush the story reacts to use an
[enemy] object with flag= and ondefeat=, or a dialogue that sets a flag and
ends with combat=.

== obj.npc.craft | NPC crafting station
see: tab.recipes, recipe.station, dlg.actions

Makes the NPC open a crafting screen when talked to, if it has no dialogue=.

Format: forge, alchemy, workbench or any. Default: empty.

  craft=forge

The forge works metal (and reinforces and salvages non-tech gear), alchemy
brews and enchants, the workbench handles tech. Most shipped craftsmen use a
dialogue with a craft=forge action so they can also sell things.

== obj.npc.board | Notice board
see: obj.npc, dlg.actions

Turns the NPC (or a sign-like object drawn as an NPC) into a notice board that
posts bounties for a town. Each board posts up to three offers a day: kill
creatures from nearby dungeons, fetch materials, or carry a letter to another
visited town.

Format: the town's map id (its location id works too). Default: empty.

  board=hollowmere

Gotchas: board= wins over dialogue=. Kill bounties draw from the monsters= of
dungeons near the town on the overworld, so the town needs a location and
nearby dungeons with monster pools.


What the board posts (and where its courier letters may go) is set in the Bounties tab - see the board topic.
== obj.npc.travel | Coachman
see: concepts.worldmap, obj.npc, dlg.actions

travel=1 opens the world map in travel mode when the NPC is talked to (the
built-in coach; since 1.1.10 the base game's coachman uses script=coachman
instead, which does the same as a script you can change),
where the party can ride to any place it has visited for 8 gold + 6 per league.
The trip takes game time and may be ambushed.

Format: 1 or 0. Default: 0.

  travel=1

Gotchas: travel wins over dialogue=. Coach travel only works when the
campaign's world map mode is overworld. Put one coachman in each town square.

== obj.npc.moveif | NPC move condition
see: obj.npc.movex, obj.npc.movey, concepts.conditions, dlg.actions

Once this condition is true, the NPC stands at movex,movey instead of x,y - a
guard steps aside from a gate, a villager goes home after a quest.

Format: a condition. Default: empty (never moves). Needs movex and movey.

  moveif=keep_open
  movex=47
  movey=12

Gotchas: the move is checked when the map's state is re-applied (entering the
map, or right after a flag changes). There is no walking animation - the NPC
just appears there. For a one-off scripted move, use the dialogue action
npcmove=.

== obj.npc.movex | NPC move-to x
see: obj.npc.moveif, obj.npc.movey

The x tile the NPC moves to once moveif= is true.

Format: whole number. Default: -1 (no move; the NPC stays put even if moveif is
true).

  movex=47

Make sure the target tile is walkable and not where another object stands.

== obj.npc.movey | NPC move-to y
see: obj.npc.moveif, obj.npc.movex

The y tile the NPC moves to once moveif= is true. Used together with movex.

Format: whole number. Default: -1.

  movey=12

Gotchas: always set both. The move only happens when movex is 0 or more, and
a missing movey would put the NPC off the top of the map.

== obj.npc.x | NPC x
see: obj.npc.y, obj.npc

The column the NPC stands on, counting from 0 at the left edge. Dragging the
NPC with the Objects tool updates it.

Format: whole number. Default: 0.

  x=7

This is also the NPC's home spot: wander= stays within 3 tiles of it.

== obj.npc.y | NPC y
see: obj.npc.x, obj.npc

The row the NPC stands on, counting from 0 at the top edge. Dragging the NPC
with the Objects tool updates it.

Format: whole number. Default: 0.

  y=5

Check warns when an NPC stands on a blocked tile.

Together with x it places the NPC; moveif= can move it elsewhere later.

== obj.enemy | Enemy group object
see: obj.enemy.group, obj.enemy.aggro, obj.enemy.flag, obj.enemy.level, obj.enemy.ondefeat, obj.enemy.link, obj.enemy.leash, map.touch, concepts.encounters

A group of monsters placed on the map. They roam within about 4 tiles of their
spot and close in when they see the party. When the party comes within aggro
tiles and in line of sight, a fight starts where everyone stands. Nearby groups
that can see the fight join it, and groups sharing a link= always come
together.

  [enemy]
  group=skeleton,skeleton
  x=12
  y=8
  aggro=4
  flag=barrow_g1

The first creature's sprite is drawn on the map (2x2 if it is big). After a
victory the group is gone; its flag= keeps it gone for good.

== obj.enemy.group | Enemy group creatures
see: obj.enemy, tab.creatures, table.group

The creatures in this group, as creature ids separated by commas. Repeat an id
for several of the same.

Format: id,id,... ("add creature" in the panel appends one). Default: empty.

  group=goblin,goblin,goblin_archer

Gotchas: Check warns about unknown ids. The first creature is the one drawn on
the map, so put the leader or the biggest monster first.

== obj.enemy.aggro | Enemy aggro range
see: obj.enemy, spell.utility

How close (in tiles) the party may come before the group notices it and the
fight starts. They also need line of sight. While the Stealth spell is active
the range is a third.

Format: whole number. Default: 5.

  aggro=4

Small values (2-3) let the party sneak past or choose the moment; large values
(6-8) make a guard post that spots you across a room.

Gotchas: on a map with touch=1 (map.touch) the fight only starts when the group
is right next to the party; aggro is then just how far away it notices you and
starts chasing (step for step, within its leash - obj.enemy.leash).

== obj.enemy.flag | Enemy defeated flag
see: obj.enemy, concepts.flags, obj.enemy.ondefeat

The flag set when this group is defeated. If the flag is already set when the
map loads, the group is gone.

Format: a flag name. Default: empty.

  flag=barrow_g1

Gotchas: without a flag the group comes back the next time the map is loaded
fresh (after loading a save). Give every placed group a unique flag, and use it
in quests (q_wolves_done) or doors.

== obj.enemy.level | Enemy level bonus
see: obj.enemy, creature.level, table.level

Extra levels for every creature in this group: each level adds +1 to all six
stats, +6 HP, +1 damage, half a point of defence and +8 XP.

Format: whole number. Default: 0.

  level=2

Use it to make a familiar monster a real threat in a later area without
creating a new creature.

== obj.enemy.ondefeat | Enemy on-defeat script
see: concepts.scripts, obj.enemy.flag, dlg.actions

A script that runs after the party wins against this group: set quest flags,
give items, show a message or open a dialogue.

Format: actions key:value separated by ;. Default: empty.

  ondefeat=flag:rift_shard_found;item:rift_shard;notify:The Lich crumbles.

Gotchas: it runs only when this group is in the fight. If several groups fight
together, every defeated group's flag is set, but only the group that started
the fight runs its ondefeat. For bosses with escorts, link= the escorts to the
boss and put ondefeat on the boss group.

== obj.enemy.show | Enemy show condition
see: concepts.conditions, obj.enemy.hide, obj.npc.show

The group is only present while this condition is true: ignored, invisible
and harmless otherwise.

Format: a condition. Default: empty (always present).

  show=cult_awake

Use it for an ambush that appears after a story beat, or reinforcements that
arrive once an alarm flag is set.

== obj.enemy.hide | Enemy hide condition
see: concepts.conditions, obj.enemy.show

The group is absent while this condition is true.

Format: a condition. Default: empty.

  hide=truce_made

Use it for enemies that leave once you settle things peacefully - a bandit
camp that stands down after a deal, guards that stop attacking once you have
the pass.

== obj.enemy.link | Enemy link
see: obj.enemy, obj.enemy.ondefeat

Groups that share the same link id always join the same fight: start a fight
with one, and all the others with that link come too, wherever they stand on
the map.

Format: any id. Default: empty.

  link=goblin_cave_boss

Use it for a chief and his bodyguards, or a whole camp that reacts as one.
Groups without a link still join if they are close (4 tiles) or can see the
fight.

== obj.enemy.leash | Enemy leash range
see: obj.enemy, obj.enemy.aggro, map.touch

Only on maps with touch=1 (map.touch). How far (in tiles) from its leash
point - the spot where the group is placed - the party may be for the group
to keep chasing it. Further than that and the group gives up and walks back.
It never follows the party more than a step beyond its leash range.

Format: whole number. Default: empty = aggro + 5 (at least 6).

  leash=12

Small values keep a guard near its post; large values make a pack that
hounds the party across the map.

== obj.chest | Chest object
see: obj.chest.flag, obj.chest.items, obj.chest.gold, obj.chest.locked, objtype

A chest the party opens by walking into it or pressing E next to it. It gives
its gold and items once. Equipment inside can roll random affixes (uncommon or
rare) when opened.

  [chest]
  x=8
  y=4
  flag=hm_elder_chest
  items=potion_blue:1
  gold=10

Chests block movement. The Detect spell counts unopened chests on the map and
makes them glow.

== obj.chest.flag | Chest flag
see: obj.chest, concepts.flags

The flag set when the chest is opened. If it is set when the map loads, the
chest is already empty.

Format: a flag name. Default: empty. New chests get chest_<x>_<y>.

  flag=hm_elder_chest

Gotchas: without a flag the chest refills when the map is loaded fresh. Every
chest needs its own flag - two chests sharing one empty each other. Pasted
chests keep the copied flag, so rename it.

== obj.chest.items | Chest items
see: obj.chest, tab.items, item.id

What the chest contains: item ids with counts.

Format: id:count,id:count (count defaults to 1). "add item" in the panel
appends one. Default: empty.

  items=oathkeeper:1,bone_dust:2

Gotchas: weapons and armour roll a loot tier when the chest is opened and may
gain affixes ("Keen Iron Sword"). Quest keys are safe - only equippable items
roll. Check warns about unknown ids.

== obj.chest.gold | Chest gold
see: obj.chest

Gold coins in the chest.

Format: whole number. Default: 0.

  gold=25

Gold is meant to be scarce: a few to a few dozen coins in early chests is
plenty. A chest with no gold and no items says "The chest is empty."

== obj.chest.locked | Chest lock
see: obj.chest, obj.door.key, spell.utility

The item needed to open the chest. Without it the chest says it is locked and
names the key.

Format: an item id. Default: empty (unlocked).

  locked=mayor_seal

Gotchas: the key is not used up. The Unlock spell (utility=unlock) opens a
locked chest standing next to the caster without the key.

== obj.exit | Exit object
see: obj.exit.to, obj.exit.tx, obj.exit.ty, obj.exit.w, obj.exit.require, obj.exit.item, maps.arrival

An area that moves the party to another map when they step onto it: a door
to a house, the edge of a town, stairs, a cave mouth.

  [exit]
  x=7
  y=30
  w=3
  h=1
  to=overworld
  tx=44
  ty=93

The party arrives at tx,ty in the target map (0,0 = its spawn). Paint the
cells under an exit with something that looks like a way out: a door,
stairs, a road leading off the edge.

Gotchas: put the arrival tile next to the target map's way back, not on it:
standing on an exit cell, pressing E sends the party straight through again.

== obj.exit.w | Exit width
see: obj.exit, obj.exit.h

How many cells wide the exit area is, counting right from x.

Format: whole number. Default: 1.

  w=3

Use a wide exit along a road at a town's edge so the party does not have to hit
one exact tile.

== obj.exit.h | Exit height
see: obj.exit, obj.exit.w

How many cells tall the exit area is, counting down from y.

Format: whole number. Default: 1.

  h=2

A whole map edge can be one exit: x=0, y=0, w=1, h=<map height>.

Exits are drawn as cyan rectangles in the map view so you can see the whole area.

== obj.exit.to | Exit target map
see: obj.exit, map.id, dungeon.id

The map the exit leads to: a map file id, a dungeon id, or overworld.

Format: a map id ("pick map" in the panel lists all three kinds). Default:
empty.

  to=hollowmere_home

Gotchas: Check warns about unknown targets. An unknown map loads a tiny
"Nowhere" room with an exit to the overworld.

== obj.exit.tx | Exit arrival x
see: obj.exit.ty, map.spawn, maps.arrival

The x tile the party arrives on in the target map. For to=overworld it is the
overworld tile (usually right next to the location's marker).

Format: whole number. Default: 0 (together with ty 0: the target's spawn).

  tx=44

Gotchas: if the tile is blocked, the party is placed on the nearest free tile.
Hover the target map in the Maps tab to read coordinates from the info line.

== obj.exit.ty | Exit arrival y
see: obj.exit.tx, map.spawn

The y tile the party arrives on in the target map.

Format: whole number. Default: 0.

  ty=93

When both tx and ty are 0 the party goes to the target map's spawn point, so a
real arrival at 0,0 is not possible (use the spawn for it instead).

== obj.exit.require | Exit condition
see: concepts.conditions, obj.exit.locked, obj.exit.item

The exit only works while this condition is true. Otherwise the party just
stands on it, and the locked= message is shown if there is one.

Format: a condition. Default: empty.

  require=q_main>=3

Use it to keep a road closed until the story allows, for example a bridge that
is guarded until you have the pass.

== obj.exit.item | Exit required item
see: obj.exit, obj.exit.locked, obj.door.key

An item the party must carry to use the exit, such as a keycard for a hatch.

Format: an item id. Default: empty.

  item=keycard_blue

Gotchas: the item is not used up. Without it the party hears the locked
sound and sees locked= (or "It is locked."). require= is checked first.

== obj.exit.locked | Exit locked message
see: obj.exit.require, obj.exit.item

The message shown when the exit refuses the party because of require= or
item=.

Format: any text. Default: empty (no message for require=; "It is locked."
for item=).

  locked=The hatch needs a blue keycard.

Always write one: an exit that silently does nothing looks like a bug.

== obj.trigger | Trigger object
see: obj.trigger.script, obj.trigger.flag, obj.trigger.once, obj.trigger.require, concepts.scripts

An invisible area that runs a script when the party steps into it: a
cutscene at a cave mouth, a message at a shrine, an ambush in a corridor, a
quest step when you reach a place.

  [trigger]
  x=40
  y=25
  w=12
  h=8
  script=dialogue:cult_aftermath
  flag=cult_aftermath_done
  require=cult_fought

Every step inside the area checks it. With a flag and once=1 (the default) it
fires one time per game; require= delays it until the story is ready.

Gotchas: a trigger without a flag fires on every step taken inside it, even
with once=1. The view draws triggers as yellow rectangles; they are invisible in
game.

== obj.trigger.w | Trigger width
see: obj.trigger, obj.trigger.h

How many cells wide the trigger area is, counting right from x.

Format: whole number. Default: 1.

  w=12

Make the area span the whole corridor or doorway so the party cannot walk
around it.

Triggers are drawn as yellow rectangles in the map view and are invisible in game.

== obj.trigger.h | Trigger height
see: obj.trigger, obj.trigger.w

How many cells tall the trigger area is, counting down from y.

Format: whole number. Default: 1.

  h=8

A wide, one-cell-tall trigger across a road is the classic "you cross a line"
trigger.

Remember that each step inside the area checks the trigger again, so a large area with once=0 fires a lot.

== obj.trigger.script | Trigger script
see: concepts.scripts, dlg.actions

What the trigger does: one or more actions separated by ;, each key:value.

Format: a script. Default: empty. New triggers get message:Title|Text.

  script=message:Old Shrine|The stones hum under your hand.
  script=set:q_main=2;dialogue:elder_arrives
  script=combat:wolf,wolf,wolf

Gotchas: dialogue: opens the conversation without an NPC (no portrait), so
give its nodes a speaker=. combat: starts the fight on the party's tile.

== obj.trigger.flag | Trigger flag
see: obj.trigger, obj.trigger.once, concepts.flags

The flag set the moment the trigger fires. With once=1 a trigger whose flag
is already set never fires again.

Format: a flag name. Default: empty.

  flag=cult_aftermath_done

Gotchas: the flag is set before the script runs, so the script's dialogue can
already test it. Without a flag, once=1 cannot remember anything and the
trigger repeats.

== obj.trigger.once | Trigger once
see: obj.trigger.flag, obj.trigger

once=1 means the trigger fires only while its flag is not yet set (so one
time, with a flag). once=0 fires it on every step inside the area, setting
the flag each time.

Format: 1 or 0. Default: 1.

  once=0

Use once=0 for repeating effects: a healing spring that restores the party on
every visit, or a warning message that should always show.

== obj.trigger.require | Trigger condition
see: concepts.conditions, obj.trigger

The trigger only fires while this condition is true. Steps taken while it is
false do nothing and do not use up a once trigger.

Format: a condition. Default: empty (always).

  require=q_main>=2&!night

Combine with flag + once for "the first time the party gets here after
talking to the Elder".

== obj.sign | Sign object
see: obj.sign.text, obj.npc, objtype

A readable sign. Bump into it or press E next to it to show its text; the
text is also copied into the journal's Notes.

  [sign]
  x=12
  y=9
  text=HOLLOWMERE - pop. 61. Mind the goats.

The cell under a sign becomes blocked. The sign object does not draw anything
itself: paint a tile with a sign prop under it (sign, shop_sign, inn_sign) or
place it on a notice board, gravestone, statue or plaque.

== obj.sign.text | Sign text
see: obj.sign

What the sign says.

Format: any text on one line. Default: empty.

  text=The Weary Goat Inn. Rooms 10 gold. No goblins.

Signs are a cheap way to add flavour, directions and hints. The journal note
is titled "<map name> sign", so give the map a name.

1.4.0: a sign with an empty text= and an onuse= shows nothing and only runs its
onuse. That is how terminals and combination locks are made (Objects tab
templates terminal and combo_lock; see scripting.puzzles).

== obj.door | Door object
see: obj.door.key, obj.door.require, obj.door.openif, obj.door.flag, obj.door.locked, obj.door.metal, objtype

A door that blocks movement and sight until opened. Bump into it or press E
to open it. Doors can need a key item, a condition (require=), or open by
themselves when a condition becomes true (openif=, a lever for example).

  [door]
  x=26
  y=8
  openif=barrow_lever
  locked=A slab of carved stone, no handle, no keyhole.

The closed look is the prop of the tile kind painted under the door (paint
door_wood, door_metal or door_arch there). Once open, a doorway (or an open
metal door with metal=1) is shown.

Plain door_wood tiles without a [door] object are just walkable doorways.
Shops with hours lock their building's front door at night by themselves.

== obj.door.key | Door key
see: obj.door, obj.chest.locked, obj.exit.item

The item needed to unlock the door. Without it: "Locked. It needs a <key>."

Format: an item id. Default: empty.

  key=crypt_key

Gotchas: the key is not used up. The Unlock spell opens a locked door next to
the caster without the key (and without checking require=). If a door should
need a story event, not just a key, use require= too.

== obj.door.flag | Door flag
see: obj.door, concepts.flags

The flag set when the door is opened. If the flag is set when the map loads,
the door is already open.

Format: a flag name. Default: empty.

  flag=vault_door_open

Gotchas: without a flag an opened door closes again next time the map is
loaded fresh. Other things can test the flag (a quest stage "You opened the
vault").

== obj.door.openif | Door opens when
see: concepts.conditions, obj.lever, obj.door.require

The door opens by itself as soon as this condition becomes true - pulling a
lever, finishing a quest step - and until then it cannot be opened by hand.

Format: a condition. Default: empty.

  openif=barrow_lever

Gotchas: trying the door while it is still shut shows locked= (or "It won't
open from this side. There must be a mechanism somewhere."). The door stays
open once it has opened, even if the lever is pushed back; use a [change]
for a passage that closes again.

== obj.door.require | Door condition
see: concepts.conditions, obj.door.openif

The door can be opened by hand only while this condition is true.

Format: a condition. Default: empty.

  require=q_main>=4

Unlike openif=, the door does not open by itself: the party still opens it,
it is just refused until then (with locked=, or "It won't open. Not yet.").

== obj.door.locked | Door locked message
see: obj.door.require, obj.door.openif

The message shown when require= or openif= keeps the door shut.

Format: any text. Default: empty (a generic line).

  locked=A sealed blast door. Its lock panel is dead.

Write a hint here: what is missing, or where to look. The key= message is
always the automatic "Locked. It needs a ..." line.

== obj.door.metal | Metal door
see: obj.door

metal=1 shows the door open as an open metal door rather than an empty
doorway - for sci-fi bulkheads and vaults.

Format: 1 or 0. Default: 0.

  metal=1

The closed look still comes from the tile painted under the door; paint
door_metal there for a matching pair.

== obj.savepoint | Save point object
see: obj.npc, dlg.actions, objtype

A save shrine: the party saves the game by stepping onto it and pressing E,
or with F5 (quick save) while standing on it. Saving is only possible on
shrines.

  [savepoint]
  x=7
  y=11

Place one in every town and near the entrance of each dungeon (generated
dungeons get one automatically). A shrine before a boss is kind.

Only x and y. The dialogue action savepoint=1 can add a shrine where the party
stands, but it is not kept after the map is reloaded.

== obj.obstacle | Obstacle object
see: obj.obstacle.needs, obj.obstacle.kind, obj.obstacle.clear, obj.obstacle.flag, obj.obstacle.onclear, obj.lever

Something that blocks the way until the party deals with it: rubble to dig or
blast, vines to burn, ice to melt, a boulder to shove, a sealed door to hack.
Bump into it or press E: a menu describes it, hints what would work, and offers
every way the party can manage right now.

  [obstacle]
  x=52
  y=39
  name=Collapsed metro stairs
  needs=rubble
  clear=stairs_down
  flag=metro_open
  text=Stairs down to the old metro, choked with fallen concrete.
  onclear=notify:The way down to the metro is open.

While blocked, its cells show the kind= tile; once cleared they become
clear=, its flag is set and onclear= runs.

== obj.obstacle.w | Obstacle width
see: obj.obstacle, obj.obstacle.h

How many cells wide the obstacle is, counting right from x. All cells are
cleared together.

Format: whole number. Default: 1.

  w=2

Gotchas: the clear= kind defaults to whatever was painted under the top-left
cell only.

Obstacles are drawn as brown rectangles with a rock icon in the map view.

== obj.obstacle.h | Obstacle height
see: obj.obstacle, obj.obstacle.w

How many cells tall the obstacle is, counting down from y.

Format: whole number. Default: 1.

  h=3

A 1 x 3 obstacle fills a three-wide corridor end to end.

The menu opens when the party bumps into any cell of the area; clearing it clears every cell.

== obj.obstacle.name | Obstacle name
see: obj.obstacle

The title of the obstacle's menu.

Format: any text. Default: Rubble.

  name=Grave-vines

Name it for what it looks like, so the player can guess the solution:
"Rockfall", "Frozen archway", "Rusted hatch".

The name is also the speaker line of the menu, so keep it short enough to read at a glance.

== obj.obstacle.needs | What clears an obstacle
see: obj.obstacle, spell.utility, item.effect, obj.obstacle.flag

The ways the obstacle can be cleared. Separate several with |.

- rubble: dig or blast (the default).
- dig: a shovel (it breaks).
- blast: a blasting charge (3-second fuse - run!) or a big area spell of fire, shock or physical damage, which also hurts the party standing near.
- burn, melt: a torch, fire oil, or any fire spell.
- force:N: the strongest party member needs STR N or more - or anyone casts a spell with utility=force (1.4.0), whatever the STR.
- spell:UTILITY: a spell with that utility, e.g. spell:unlock.
- item:ID: uses up one of that item.
- freeze (1.4.0): water that a cold spell (utility=freeze) or a Frost Flask turns to ice for this visit. No flag is set and the water comes back when the party leaves the map. Default look: the water on its cell (else floor_water); clear= defaults to floor_ice.
- shock (1.4.0): a dead machine, lift or door. A utility=shock spell, any shock damage spell, a Charged Cell or an Energy Cell Pack wakes it. Default look: door_metal.
- emp (1.4.0): a sealed tech door. A utility=emp spell or an EMP Grenade scrambles its lock. Default look: door_metal.
- light (1.4.0): something only seen in the light. A lit party (torch, light spell, glowing gear) that comes within two steps reveals it by itself; the menu also offers a light spell or lighting a torch. Default look: whatever the map has on the cell, so it can pass for a plain wall.
- spell:detect: also uncovered by a utility=detect spell cast within 8 steps (needs=light|spell:detect is a hidden niche both a torch and a ranger can find).
- flag:COND: the obstacle clears itself as soon as the condition COND is true, like a door's openif=. Its menu hint says nothing the party does here will shift it - something else must happen first.

  needs=burn
  needs=force:15|blast
  needs=item:keycard_red|spell:unlock
  needs=flag:pump_on&q_flood>=2
  needs=freeze
  needs=shock
  needs=light|spell:detect

The utility spells work from the Spells menu too: cast one next to an obstacle
it clears (freeze, shock, emp, force) and it clears it; light and detect reveal
hidden ones nearby. In the object panel the "+" button next to needs lists every
value.

Gotchas: if the obstacle's flag gets set any other way (dialogue set=, a
lever) it also clears by itself. flag: can be mixed with other ways
(needs=blast|flag:pump_on) so the party may force it early.

== obj.obstacle.kind | Obstacle look
see: obj.obstacle, obj.obstacle.clear, tab.tiles

The tile kind painted on the obstacle's cells while it blocks.

Format: a tile kind name. Default: vines when needs mentions burn, ice_wall
when it mentions melt; freeze: the water already on the cell (else floor_water);
shock or emp: door_metal; light: the cell's own kind; otherwise rubble_pile.
(1.4.0) The cells always block, even when the kind is walkable.

  kind=rubble_pile

Gotchas: the kind should be non-walkable or the party just walks past. To make
a different-looking blocker (a rusted door), make a non-walkable tile kind for
it in the Tiles tab.

== obj.obstacle.clear | Obstacle cleared tile
see: obj.obstacle, obj.obstacle.kind

The tile kind its cells become once cleared.

Format: a tile kind name. Default: whatever was painted under the obstacle's
top-left cell, or floor_cave if that was not walkable.

  clear=stairs_down

Gotchas: an exit placed on the same cell starts working once it is
walkable - that is how the collapsed metro stairs become a way down.

== obj.obstacle.flag | Obstacle flag
see: obj.obstacle, concepts.flags, obj.obstacle.needs

The flag set when the obstacle is cleared. If it is already set when the map
loads (or is set later by anything), the obstacle is cleared.

Format: a flag name. Default: empty. New obstacles get rubble_<x>_<y>.

  flag=metro_open

Gotchas: without a flag a cleared obstacle comes back when the map is loaded
fresh. Give every obstacle its own flag.

== obj.obstacle.text | Obstacle description
see: obj.obstacle

The description at the top of the obstacle's menu. The game adds hints for
each way in needs= ("A shovel would dig through it.").

Format: any text. Default: "Something blocks the way."

  text=Fallen rock blocks the way.

Describe what the party sees and hint at the story behind it.

== obj.obstacle.onclear | Obstacle on-clear script
see: concepts.scripts, obj.obstacle

A script that runs when the party clears the obstacle (not when it clears
itself because its flag was set elsewhere).

Format: actions key:value separated by ;. Default: empty.

  onclear=notify:The way down to the metro is open.
  onclear=set:q_mine=2;message:Behind the rocks|A skeleton still clutches a lantern.

== obj.lever | Lever object
see: obj.lever.flag, obj.lever.toggle, obj.door.openif, obj.change, obj.change.if, objtype

A lever the party pulls by bumping into it or pressing E. Pulling sets its
flag; pulling again clears it (unless toggle=0). Doors with openif=, changes
with if= and NPCs with moveif= that test the flag react at once.

  [lever]
  x=3
  y=5
  flag=barrow_lever
  name=Bronze lever
  toggle=0
  text=Somewhere east, stone grinds on stone.

The lever's cell is painted with the lever tile automatically and is not
walkable.

Classic uses: a lever that opens a far door (door openif=), drains a flooded
hall (change if= turning water to floor), or extends a bridge.

== obj.lever.name | Lever name
see: obj.lever

The lever's name.

Format: any text. Default: Lever.

  name=Bronze lever

Currently the name is only kept in the file for you; the messages come from
text= or the default lines.

Name levers anyway: it documents the map for you and for anyone who edits it after you.

== obj.lever.flag | Lever flag
see: obj.lever, concepts.flags

The flag the lever sets when pulled and clears when pushed back.

Format: a flag name. Default: empty. New levers get lever_<x>_<y>.

  flag=marsh_sluice

Gotchas: the lever shows its state by the flag, so two levers sharing a flag
move together. The flag can also be set from dialogue - the lever then counts
as pulled.

== obj.lever.toggle | Lever toggle
see: obj.lever

toggle=1 lets the lever be pushed back (clearing the flag). toggle=0 makes
it one-way: once pulled it is "stuck in place".

Format: 1 or 0. Default: 1.

  toggle=0

Use toggle=0 for story levers, so the player cannot undo progress by
accident; toggle=1 for puzzles.

== obj.lever.text | Lever message
see: obj.lever

The message logged when the lever is pulled or pushed back.

Format: any text. Default: "You pull the lever. Somewhere, something
grinds." (or "You push the lever back.").

  text=Water gurgles away somewhere below.

Tell the player what changed and roughly where, especially if it happened off
screen.

== obj.change | Map change object
see: obj.change.if, obj.change.kind, obj.change.w, obj.lever, concepts.conditions

An area of the map that looks different while a condition is true: a bridge
appears, a flooded hall drains, a wall collapses, a campfire is lit. When the
condition becomes false again (a lever pushed back) the original tiles return.

  [change]
  x=20
  y=10
  w=6
  h=2
  kind=floor_stone
  if=metro_drained

Paint the "before" state on the map; the change paints kind= over it.

Gotchas: the change is applied when the map loads and right after flags
change; the party is never moved, so do not turn the ground under them into a
wall.

== obj.change.w | Change width
see: obj.change, obj.change.h

How many cells wide the change area is, counting right from x.

Format: whole number. Default: 1.

  w=6

Every cell in the area gets the same kind; for a mixed change use several
[change] objects with the same if=.

Changes are drawn as purple rectangles in the map view.

== obj.change.h | Change height
see: obj.change, obj.change.w

How many cells tall the change area is, counting down from y.

Format: whole number. Default: 1.

  h=2

The purple rectangle in the map view shows the area.

Changes can overlap; the later one in the file paints last. Use h=1 strips for bridges.

== obj.change.kind | Change tile kind
see: obj.change, tab.tiles

The tile kind painted over the area while the condition holds.

Format: a tile kind name. Default: empty (nothing is painted; set it).

  kind=bridge

A walkable kind opens the way (bridge, floor_stone), a blocking one closes it
(wall_stone, rubble_pile).

Exits, doors and objects standing in the area are not changed - only the tile kind of the cells.

== obj.change.if | Change condition
see: concepts.conditions, obj.change, obj.lever

The change is applied while this condition is true and undone when it is
false.

Format: a condition. Default: empty (always applied).

  if=marsh_sluice

Works with any flag, not just levers: if=q_main>=5 can rebuild a burnt
village later in the story.

== obj.gather | Gather node object
see: obj.gather.node, tab.resources, obj.gather.item, obj.gather.count, obj.gather.tool, obj.gather.respawn, obj.gather.name, tab.recipes

A spot the party can harvest: an ore vein, a herb patch, a scrap heap.
Pressing E on (or bumping into) it gives the item, takes 10 game minutes, and
then it is "picked clean" for some days. Gather nodes sparkle so players notice
them.

  [gather]
  x=33
  y=16
  node=iron_ore

node= names its resource type (Resources tab). Everything the node does not
set itself comes from that type: item, count, tool, respawn, name, picture and
colours. Set a key on the node only when this one spot should differ
(count=2-4 for a rich vein). The panel lists the values it takes from its type,
dimmed; "pick node type" changes the type.

A type with no sprite= draws the map tile under the node in the node's colour,
so paint something fitting there (rocks, mushroom, crystal, box). A type with
a sprite draws that picture instead of the tile.

== obj.gather.item | Gather item
see: obj.gather, item.id

The item harvested.

Format: an item id. Default: empty (the node does nothing).

  item=herb_moon

Usually a material used by recipes: iron_ore, ember_cap, herb_moon, scrap,
bone_dust.

Usually left to the node's type (node=). A node with an item but no node= uses the first resource type that gives that item. Check that the item exists: an unknown id makes the node do nothing.

== obj.gather.count | Gather amount
see: obj.gather

How many items one harvest gives.

Format: n or lo-hi. Default: 1.

  count=1-3

Keep it low (1-3): nodes respawn, so a good spot is worth a lot over a
playthrough.

Each harvest picks a random amount in the range. The count is per harvest, not per day.

== obj.gather.tool | Gather tool
see: obj.gather, item.id

An item the party must carry (or have equipped) to harvest. It is not used
up.

Format: an item id. Default: empty (bare hands).

  tool=pickaxe

Without it the game says "You need a Pickaxe to work this." Sell the tool in
a nearby shop.

== obj.gather.respawn | Gather respawn days
see: obj.gather

How many in-game days until the node can be harvested again.

Format: whole number of days. Default: 3.

  respawn=5

A day is 24 minutes of real walking; sleeping at an inn skips to morning.

Nodes that need a tool can afford a longer respawn (5) than bare-hand nodes (3), as in the generated dungeons.

== obj.gather.name | Gather name
see: obj.gather

The name used in the "picked clean" message, for example "Herb patch:
picked clean. Give it 2 more days."

Format: any text. Default: empty (the item's name).

  name=Herb patch

Use it when the item name alone sounds odd as a place: "Iron vein" reads better than "Iron Ore".

== obj.gather.node | Gather node type
see: obj.gather, tab.resources

The resource type this node is (an id from the Resources tab, resources.txt).
The node takes every key it does not set itself from the type.

  node=iron_ore

Empty: the node uses the first type whose item= matches its own item=, or the
old behaviour (colour guessed from the item, the map tile under it) if there is
none.

== obj.gather.sound | Gather harvest sound
see: obj.gather, resource.sound
The sound event played when the party harvests this node. Empty: its resource type's sound=, else pickup (by hand) or hit (with a tool).
  sound=gather_mine

== obj.gather.sprite | Gather node picture
see: obj.gather, resource.sprite
Usually left to the node's type. A tile (col,row) drawn for this node instead of the map tile under it, in the node's colour.
  sprite=6,46

== obj.gather.color | Gather node colour
see: obj.gather, resource.color
Usually left to the node's type. The colour the node is drawn in while it can be harvested (r,g,b).
  color=235,140,60

== obj.gather.spent | Picked-clean colour
see: obj.gather, resource.spent
Usually left to the node's type. The colour once picked clean (r,g,b). Default 85,85,85 (grey).

== obj.gather.spentsprite | Picked-clean picture
see: obj.gather, resource.spentsprite
Usually left to the node's type. A different picture once picked clean (empty = the same picture).

== tilekind.name | Tile kind name
see: tab.tiles, concepts.ids

The kind's id. Maps store each cell as a kind name, so this is what the map
files, palette, brushes and the change/obstacle kind= fields refer to.

Format: lowercase id, unique. Built-in names include grass, forest, road,
wall_stone, floor_wood, door_wood, torch, loc_village...

  name=floor_cave_wet

Gotchas: renaming a kind that maps already use turns those cells into
"unknown tile kind" (drawn magenta, Check reports it). To change a kind's look
keep the name; to make something new press New. Names starting with door make
the cell count as a door for shop opening hours; names starting with loc_ are
overworld location markers.

== tilekind.ground | Ground tiles
see: tab.tiles, concepts.tiles, tilekind.prop, tilekind.tint

The base art of the cell. With several ground tiles, each cell picks one at
random, which breaks up repeating patterns (grass with tufts, cracked
floors).

Format: in the form, a row of tiles with "..." pickers, + to add (up to 6), x to
remove. In tilekinds.txt: col,row|col,row|...

  ground=15,5|15,5|15,5|16,5|14,5

Gotchas: repeat a tile to make it more common. The ground is drawn with the
kind's tint; walls with opaque=1 keep their black parts.

== tilekind.prop | Prop tile
see: tilekind.ground, concepts.tiles

An overlay drawn on top of the ground, in its own colours (not tinted): a tree
on grass, a barrel on a wooden floor, a door in a doorway, a torch on a wall.

Format: one tile (col,row) with a "..." picker, x to remove. Default: none.

  prop=4,1

This is where you fix a wrong-looking door or furniture tile: select door_wood
and pick a different prop. The prop's look also tells players what a cell is,
so keep walkable props (flowers, chairs) visually lighter than blocking ones.

== tilekind.walkable | Walkable
see: tilekind.blockssight, tilekind.water

Whether the party (and monsters) can step onto the cell. Non-walkable names
are shown red in the palette and the list.

Format: checkbox (walk=1/0 in the file). Default: 1.

  walk=0

In combat, a non-walkable cell next to a fighter gives half cover (full cover
if it also blocks sight); water gives no cover.

== tilekind.blockssight | Blocks sight
see: tilekind.walkable, map.dark

Whether the cell blocks line of sight: for spotting the party (enemy aggro),
ranged attacks and spells, light on dark maps, and full cover in combat.

Format: checkbox (sight=1/0 in the file). Default: 0.

  sight=1

Walls, trees in forests, shelves and closed doors block sight. A walkable kind
can block sight too (forest on the overworld): the party can walk through it
but cannot see across.

== tilekind.water | Water
see: tilekind.walkable, tilekind.biome

Marks the cell as water: drawn blue on the world map, no cover in combat, and
treated as water by the overworld generator (roads become bridges over it).

Format: checkbox (water=1/0 in the file). Default: 0.

  water=1

Water does not have to be unwalkable: shallows and mire are walkable water.
Lava is "water" too in this sense.

== tilekind.opaque | Opaque ground
see: tilekind.ground, tilekind.bg

When ticked, the ground tile is drawn with its black background as part of
the art (and tinted) instead of letting the bg colour show through. Used for
walls, so they read as solid blocks.

Format: checkbox (opaque=1/0 in the file). Default: 0 in tilekinds.txt.

  opaque=1

If a wall looks hollow or see-through, tick opaque. Floors look better with
opaque off and a dark bg.

== tilekind.tint | Tint
see: concepts.colors, tilekind.bg, tilekind.ground

The colour the ground tile is multiplied by. The tileset is white-on-black, so
the tint is effectively the ground's colour.

Format: r,g,b. Default: 255,255,255 (no change).

  tint=110,170,90

The prop is never tinted. On the world map, explored cells are drawn in a
darker version of the tint.

== tilekind.bg | Background colour
see: concepts.colors, tilekind.tint, map.bg

The colour behind the art of the cell (the tileset's black is transparent).
A dark shade of the tint looks natural.

Format: r,g,b. Default: 0,0,0 when missing from the file.

  bg=58,112,52

The World tab preview and the editor palette use bg as the cell's main colour,
so a sensible bg also makes the overworld preview readable.

== tilekind.encounter | Encounter weight
see: concepts.encounters, map.encounter, tilekind.biome

How likely random fights are on this kind of cell. The chance per step is the
map's encounter rate x this weight / 2 percent.

Format: whole number 0-20. Default: 0 (never).

  encounter=4

Shipped values: road 1, grass 2, hills 3, forest 4, swamp and dead trees 5,
rift scar 6. Location markers and all interior kinds are 0. A cell with weight
0 never ambushes, whatever the map's rate.

== tilekind.biome | Biome
see: concepts.encounters, tab.encounters, table.id, table.usedby

Names the region this kind belongs to. It picks the encounter table for random
fights (the table with the same id, or <biome>_night at night) and also the
weather: snow brings snow, desert and wasteland are mostly clear, swamps are
foggy and rainy.

Format: a word; there is a picker listing the encounter tables. Default:
empty (fights fall back to the map's table=).

  biome=forest

Shipped biomes: plains, forest, hills, desert, swamp, snow, wasteland, rift,
water, mountain, and loc for location markers (loc never ambushes).

== tilekind.movecost | Move cost
see: tab.tiles

How hard the ground is to cross: 1 is normal, 2 or more is rough (forest,
hills, dunes, swamp, mire).

Format: whole number 1-9. Default: 1.

  cost=2

In combat, stepping onto the cell costs that many movement points, and the
reachable area is worked out cheapest-first, so a unit may go around a patch
of swamp rather than through it. The combat tile panel shows it as "rough
ground (N MV)". Walking onto the cell outside combat takes N times as long
on the world clock. The overworld generator also clears these cells around
locations and turns them into road.

Gotchas: high costs on common ground make fights slow and frustrating; keep
3 or more for rare patches.

== tilekind.step | Footsteps
see: tab.tiles, tab.sounds

The sound the party's footsteps make when they walk onto this kind of
ground. The v button lists every sound event; play tries it.

Format: a sound event id. Default: empty = step (plain boots on dirt).

  step=step_grass

Shipped: step_grass (grass, forest, fields), step_sand (sand, ash, rubble),
step_snow, step_stone (dungeon and cave floors, with an echo), step_hard
(streets, tiles, concrete, ice), step_wood (floors, bridges, boardwalks),
step_metal (metal floors and grates), step_water (shallows, fords, mire).
A name that isn't a sound event plays the plain step.

== world.preview | World preview
see: tab.world, location.x, location.y, world.bake

The left side of the World tab draws the whole overworld at 2 pixels per tile,
with every location as a red square (yellow = selected). Hover a marker to see
its name; click a marker to select it.

Moving a location: select it in the list (or click its marker), then click
anywhere on the preview. Its x and y change to that tile.

The preview updates live: moving a location, editing any location field, or
painting the overworld map in the Maps tab (even before you save it) refreshes
it at once. Remember to press "Save locations" to keep location changes.

On a generated overworld the preview also shows the roads and clearings the
generator makes from the location list.

== world.bake | Bake the overworld
see: tab.world, world.preview, tab.maps, location.road, location.clear

A new or unbaked overworld is generated from the world seed: noise-made
terrain, rivers, regions, roads between locations (road=), clearings around
them (clear=), roaming monsters and wild chests.

"Bake to paintable map" saves that generated overworld as maps/overworld.txt.
From then on the overworld is a normal map you paint in the Maps tab ("Paint in
Maps tab" opens it): terrain, monsters, chests, signs, anything.

Locations stay in overworld.txt and are stamped on top when the map loads: each
location puts its marker tile at x,y and an exit to its map there (unless the
painted map already has an exit on that tile). So moving a location never needs
repainting - but roads and clearings are no longer generated; paint them.

To go back to a generated overworld, delete maps/overworld.txt.

== location.id | Location id
see: tab.world, location.map, quest.stage.pin, concepts.ids

The location's own id. Quest pins (@id), roads, bounty boards and the coach

  id=greywood

Gotchas: this is not the map id - see map=. A quest stage pinned to @greywood
points at this location even though it enters the map goblin_cave.

== location.name | Location name
see: location.id, tab.world

The place name shown on the world map, in the coach travel list and in the
journal next to pinned quests.

Format: any text. Default: the id.

  name=Greywood Cave

Unvisited but seen places show as "?" until the party has entered them.

== location.x | Location x
see: location.y, world.preview

The overworld column of the location's marker. Clicking on the World preview
sets x and y.

Format: whole number (0 to the overworld width - 1). Default: 10.

  x=56

The marker tile (kind=) is painted there and an exit to map= is placed on it.

== location.y | Location y
see: location.x, world.preview

The overworld row of the location's marker.

Format: whole number. Default: 10.

  y=78

Gotchas: exits leading back to the overworld from the location's map should
use a tx,ty right next to x,y, or the party will appear somewhere else.

Rows count from 0 at the top of the overworld map.

== location.kind | Location marker
see: tab.world, tilekind.name

The marker tile kind drawn at the location: loc_village, loc_town, loc_city,
loc_house, loc_farm, loc_tent, loc_cave, loc_mine, loc_tower, loc_castle,
loc_ruin, loc_temple, loc_crypt, loc_ship, loc_citymod, loc_lab, loc_shrine.

Format: a loc_* kind (picker). Default: loc_village.

  kind=loc_cave

loc_village, loc_town, loc_city, loc_citymod and loc_farm get a bigger square

== location.map | Location map
see: location.id, obj.exit.to, dungeon.id

The map the party enters when stepping on the location: a map file id or a

Format: a map id (picker). Default: the location's id.

  map=goblin_cave

Gotchas: in the Maps tab, N over a tile sets the arrival point of every

== location.tx | Location arrival x
see: location.ty, maps.arrival, map.spawn

The x tile where the party appears inside map= when entering from the

Format: whole number. Default: 0 (with ty 0: the map's spawn).

  tx=8

== location.ty | Location arrival y

The y tile where the party appears inside map= when entering from the

  ty=29

  clear=3

== item.id | Item id

The item's id, used everywhere an item is named: chests, shops, loot, recipes,

  id=iron_sword

Gotchas: an id containing @ is reserved (the game builds ids like
iron_sword@keen for items with affixes). Renaming an id breaks every chest,
shop and recipe that used the old one.

== item.name | Item name
see: item.id, item.desc

The name shown in menus, shops, loot lists and messages. Affixes and
reinforcing add to it ("Keen Iron Sword of Burning +1").

Format: any text. Default: the id.

  name=Iron Sword

Keep names short enough for the shop and loot lists (about 20 characters).

== item.type | Item type
see: tab.items, item.effect, item.stack

What kind of thing the item is; it decides where it goes and what its other
keys mean.

- weapon (weapon slot), offhand (shields, off-hand slot), armor (body), helm (head), boots (feet), accessory (rings, amulets, lanterns).
- consumable: used from the Items menu or in combat (potions, food, scrolls, grenades, torches).
- key: quest items and keys. material: crafting ingredients. ammo: arrows, bullets, cells.

Format: one of the words above (dropdown). Default: material.

  type=weapon

Consumables, materials, ammo and keys stack in the pack; equipment does not.
Only equipment can roll affixes.

== item.tile | Item icon
see: concepts.tiles, tab.tileset

The icon drawn in menus, shops and the hotbar (and for gather nodes, on the
map).

Format: col,row (picker). Default: 26,46.

  tile=36,6

Weapons, armour, potions and scrolls are grouped on the sheet; open the picker
on a similar item's tile to land near the right area.

== item.color | Item colour
see: item.tile, tab.items

The colour the item's picture is drawn in (1.1.8): the picture becomes a white
shape tinted with this colour, everywhere the item is shown (pack, shops,
crafting, hotbar, on the ground). Set it in the Look card of the Items tab.

Format: r,g,b (0-255 each). Default: none - the picture's own colour on the
sheet.

  color=218,0,0

Handy for variants that share a picture: a copper, iron and mithril version of
the same ring, or a red and a blue potion.

== item.value | Item value
see: tab.shops, item.salvage

The base price in gold. Shops sell for roughly value x 1.1 down to x 0.8 (a
charismatic hero pays less) and buy for about 18-35% of value. Affixes and
reinforcing multiply it.

Format: whole number. Default: 0.

  value=55

Gotchas: value 0 items sell for nothing and cost 1 gold in shops. Quest items
are usually value 0 so players do not sell them.

== item.desc | Item description
see: item.name

The description shown in the item's info panel. Mechanics such as damage, AP
and bonuses are listed by the game automatically, so use desc for flavour and
anything special.

Format: any text on one line. Default: empty.

  desc=Quick and cheap. Two stabs for the price of one swing.

== item.dmg | Item damage
see: item.dmgtype, item.stat, item.range, item.ap

For a weapon: the damage range of an attack, before the stat bonus, the
target's defence and resistances. For a consumable: makes it a thrown
explosive (grenade) that hits everyone within range-1 of the target tile.

Format: lo-hi (two number boxes). Default: 0-0.

  dmg=4-9

The stat bonus is (stat - 8) / 2 added to both ends, so STR 14 adds +3. Armour
defence subtracts from weapon hits but always lets at least 35% through.

== item.dmgtype | Item damage type
see: item.dmg, item.res, creature.res

The damage type of the weapon or explosive: physical, fire, cold, shock,
poison or magic.

Format: dropdown. Default: physical.

  dmgtype=fire

Elemental weapons sometimes add a status: fire may burn, cold may freeze,
poison may poison, shock may stun. Undead and machines ignore poison; machines
take extra shock damage.

== item.range | Item range
see: item.dmg, item.gun

For a weapon: the attack reach in tiles (1 = melee, bows and guns 5-8). For a
thrown explosive: the blast radius is range - 1. For a flare: the light radius.

Format: whole number. Default: 1.

  range=6

Ranged attackers standing next to an enemy often step back before shooting
(monster AI); there is no penalty for shooting at range 1.

== item.ap | Item attack AP
see: item.dmg, creature.ap

For a weapon: the AP one attack costs. Fighters get 8 AP a turn plus DEX/5,
so ap=3 means two or three attacks a turn and ap=6 one heavy blow.

Format: whole number. Default: 4.

  ap=3

An aimed attack costs 2 AP more. Using a consumable in combat costs 3 AP for
thrown items and 4 for everything else, whatever ap= says.

== item.stat | Item damage stat
see: item.dmg, class.stats

Which stat adds to the weapon's damage: (stat - 8) / 2 on top of dmg.

Format: str, dex or int (also con, wis, cha). Default: str.

  stat=dex

Swords and axes use str, daggers, bows and guns dex, magic staves int. The
right stat lets a weapon suit one class better than another.

== item.accuracy | Item accuracy
see: item.crit, item.evasion

Bonus (or penalty) to hit, in percent points. Base hit chance is 72% + DEX x
2 + accuracy - the target's evasion, then cover and darkness apply.

Format: whole number, can be negative. Default: 0.

  accuracy=5

Positive accuracy suits fine weapons and scopes; negative accuracy balances very heavy hitters.

== item.crit | Item critical chance
see: item.accuracy

Bonus to the critical hit chance, in percent points. Base crit chance is 5% +
DEX / 2; aimed shots add 30 and flanking 15. Crits deal more damage and halve
the target's defence.

Format: whole number. Default: 0.

  crit=10

== item.twohanded | Two-handed
see: item.type

twohanded=1 means the weapon needs both hands: equipping it unequips the
off-hand item, and equipping an off-hand item unequips it.

Format: 1 or 0. Default: 0.

  twohanded=1

Give two-handed weapons clearly better damage to pay for the lost shield.

The item panel tells the player "Two-handed." automatically.

== item.gun | Gun
see: item.ammo, item.tech, item.sound

gun=1 marks a firearm or energy weapon: it plays gun sounds (laser sounds for
fire, shock and magic damage) and counts as tech unless tech=0.

Format: 1 or 0. Default: 0.

  gun=1

Guns usually also have ammo=, range 5-8 and dex as their stat.

== item.ammo | Ammo
see: item.gun, item.type

The ammunition item each attack uses up (party members only; monsters shoot
for free). With none left the attack does not happen: "Out of Arrows!".

Format: an item id (picker), usually of type ammo. Default: empty (no ammo).

  ammo=arrows

Shipped ammo: arrows, ammo_pistol, ammo_rifle, cell. Sell ammo in the shops
near where the weapon is found.

== item.def | Item defence
see: item.evasion, item.res

Armour value: subtracted from every weapon hit the wearer takes (halved
against critical hits), but at least 35% of the damage always gets through. All
equipped items add up.

Format: whole number. Default: 0.

  def=4

Defence does not reduce spell or explosive damage - resistances (res=) do.

== item.evasion | Item evasion
see: item.def, item.accuracy

Makes the wearer harder to hit: subtracted from attackers' hit chance in
percent points.

Format: whole number, can be negative (heavy armour). Default: 0.

  evasion=5

Light armour and cloaks give 2-5; heavy plate can give -2 to -5 as the price of its high def. Accessories can carry evasion too.

== item.res | Item resistances
see: item.dmgtype, creature.res

Percent resistances to damage types while equipped. 25 = a quarter less
damage, negative = weakness. All equipped items add up; the total is capped at
90%.

Format: type:value,... (a row of six number boxes in the form). Default: none.

  res=fire:25,cold:-10

== item.bonus | Item stat bonuses
see: class.stats, item.hp

Stat bonuses while equipped: STR, DEX, CON, INT, WIS, CHA. They count for
everything the stat affects (damage, HP from CON, MP from INT/WIS, hit chance
from DEX, prices from CHA).

Format: stat:value,... (six number boxes). Default: none.

  bonus=str:2,con:1

Rings and amulets usually carry one +1 to +3 bonus; affixes can add more.

== item.hp | Item HP bonus
see: item.mp, item.bonus

Extra maximum HP while equipped.

Format: whole number. Default: 0.

  hp=10

For healing potions use heal= instead.

Typical on armour, helms and amulets: 5 to 20. The item panel lists it as HP +N. Affixes and reinforcing an accessory can raise it further. Remember that max HP also grows with CON, so +2 CON is worth +6 HP.

== item.mp | Item MP bonus
see: item.hp, item.mana

Extra maximum MP while equipped.

Format: whole number. Default: 0.

  mp=8

For mana potions use mana= instead.

Typical on robes, staves and amulets for casters: 5 to 15. Max MP also grows with INT and WIS (x2 each), so a +2 INT bonus is worth +4 MP and more spell power.

== item.apbonus | Item AP bonus
see: item.ap, item.move

Extra AP per combat turn while equipped.

Format: whole number. Default: 0.

  apbonus=1

One AP is a lot (often an extra attack every few turns); keep it for rare
gear.

Remember that party members get 8 + DEX/5 AP a turn, so +1 is up to 12% more actions.

== item.move | Item movement bonus
see: item.apbonus

Extra movement (tiles per combat turn) while equipped.

Format: whole number. Default: 0.

  move=1

Typical on boots.

Each point is one more tile per combat turn. It does not change walking speed on the map. Two points is already a lot for a melee character who has to reach the enemy.

== item.heal | Item healing
see: item.mana, item.effect

HP a consumable restores when used (up to the maximum).

Format: whole number. Default: 0.

  heal=30

Works outside combat and in combat (4 AP). Can be combined with an effect:
heal=60 plus effect=haste.

Outside combat a consumable must have heal, mana or an effect to be usable at all (spell= scrolls work only in combat).

== item.mana | Item mana
see: item.heal, item.effect

MP a consumable restores when used. For imbue oils (effect=imbue_*) it is
instead the number of attacks the coating lasts.

Format: whole number. Default: 0.

  mana=20

Mana is capped at the user's maximum MP. Combine with heal= for an elixir that restores both.

== item.effect | Item use effect
see: item.type, item.heal, item.spell, obj.obstacle.needs, recipe.known

What a consumable does when used (besides heal/mana):

- cure: removes poison, burn, weaken and blind.
- revive: raises a fallen member at half HP (usable on the downed).
- strength, haste, shield, regen, aim, focus: buffs for a few turns.
- torch: lights the way on dark maps for a long while.
- flare: thrown in combat, lights an area (radius = range) for several rounds.
- dig: shovel - opens the menu of an adjacent obstacle. blast: blasting charge, likewise.
- imbue_fire, imbue_cold, imbue_shock, imbue_poison, imbue_magic: the next mana= attacks deal that damage type.
- respec: Draught of Forgetting - re-pick a member's class ranks.
- learn:recipe,recipe: a formula that teaches recipes (used up).
- revealmap:MAP: a map item - using it reveals that whole map on the world map (used up). revealmap:MAP,x,y,radius reveals only a circle. Not usable in combat.

Format: one value. Default: empty.

  effect=learn:potion_regen,potion_haste
  effect=revealmap:overworld
  effect=revealmap:old_mine,20,14,8

The base game sells the Surveyor's Map (map_aldmoor, effect=revealmap:overworld)
at the Brasswick market.

== item.spell | Item spell
see: spell.id, item.effect

Makes a consumable cast a spell when used in combat (a scroll): no MP is needed
and anyone can use it. It costs 4 AP and is used up.

Format: a spell id (picker). Default: empty.

  spell=fireball

Gotchas: only works in combat - the Items menu outside a fight cannot use it.

== item.stack | Item stack size
see: item.type

The most of this item one inventory slot holds. When more arrive, the extra
spills into a new slot.

Format: whole number. Default: 99.

  stack=20

Gotchas: whether an item stacks at all depends on its type (consumable,
material, ammo and key stack; equipment never), so stack= means nothing on
equipment. A low stack on ammo or a crafting material fills the pack fast.

== item.salvage | Item salvage yield
see: tab.recipes, item.tech, item.value

What salvaging the item at a forge or workbench gives back. Without it the
game works out a yield from the item's type, value and materials (scrap and
circuits for tech, ingots for metal, leather for bows...).

Format: id:count,... Default: empty (automatic).

  salvage=steel_ingot:2,gem_rough:1

Use it for special items whose automatic yield would make no sense, or to make
a unique item salvage into something story-related.

== item.light | Item light
see: map.dark, map.light

While equipped by any party member, the party's glow on dark maps reaches at
least this many tiles - a lantern that never burns out.

Format: whole number. Default: 0.

  light=6

Gotchas: only equipment counts; torches you use are consumables with
effect=torch.

== item.tech | Item tech
see: item.gun, item.salvage, recipe.station

tech=1 marks a machine-age item: it is reinforced at a workbench (not a
forge), salvages into scrap, circuits and power cores, and reinforcing costs
tech parts.

Format: 1 or 0. Default: 1 for guns, 0 otherwise.

  tech=1

Set tech=1 on laser blades, power armour and gadgets; tech=0 on a gun that
should be treated like a crossbow.

== item.sound | Item sound
see: tab.sounds, sound.id, creature.attacksound

The sound event played when the item is used: on every attack for weapons,
on use for consumables, on the throw for explosives.

Format: a sound event id (picker). Default: empty = automatic (melee, bow,
gun or laser for weapons; potion for consumables; explosion for grenades).

  sound=attack_laser

== creature.id | Creature id
see: tab.creatures, concepts.ids

The creature's id, used by enemy groups, encounter tables, dungeon monsters
and boss, dialogue combat= and spawn=, conditions kills:id:n, bounties and the
bestiary.

Format: lowercase id, unique in creatures.txt.

  id=goblin_archer

Renaming an id breaks every group, table, dungeon and bounty that used the old one.

== creature.name | Creature name
see: creature.id

The name shown in combat, the turn strip, the bestiary and kill bounties.

Format: any text. Default: the id.

  name=Goblin Archer

Several creatures can share a name (two Goblin variants with different stats); the bestiary keeps them apart by id.

== creature.sprite | Creature sprite
see: concepts.tiles, creature.spritecol, creature.spriterow, creature.size, creature.color

The creature's picture: one tile, or the top-left of a 2x2 block when size=2.

Format: col,row (picker). Default: none - then spritecol/spriterow are used.

  sprite=106,40

Character rows at column 104 + gear columns make humanoids (113,8 is a goblin
with a shield); animals and monsters have single sprites (104,40 rat, 106,40
wolf, 108,40 bear). sprite= wins over spritecol/spriterow.

== creature.spritecol | Creature sprite column
see: creature.sprite, creature.spriterow

The tileset column of the sprite, used when sprite= is not set.

Format: whole number. Default: 104 (character base pose).

  spritecol=113

Gear columns: 105 sword, 106 axe, 107 dagger, 109 staff, 110 spear, 113 shield,
116 gun, 117 bow. Picking a tile with the picker replaces spritecol/spriterow
with one sprite= key.

== creature.spriterow | Creature sprite row
see: creature.sprite, creature.spritecol

The tileset row of the sprite, used when sprite= is not set - with column 104
this picks the character "race".

Format: whole number. Default: 0.

  spriterow=8

Rows include 0 human, 2 skeleton, 4 and 8 goblins, 5 orc, 9 troll, 13 ghoul,
15 bandit, 23 ghost, 30 wraith, 32 zombie, 33 golem.

== creature.size | Creature size
see: creature.sprite, concepts.tiles

size=2 makes a big monster that fills 2x2 tiles on the map and in combat
(dragons, golems, hydras). Its sprite is the 2x2 block starting at sprite=.

Format: 1 or 2. Default: 1.

  size=2

Gotchas: pick the top-left cell of the 2x2 art. A big monster needs 2x2 free
space to stand and move, so do not place it in one-tile corridors.

== creature.color | Creature colour
see: concepts.colors, obj.npc.color

Repaints the sprite in one colour: an ice wolf from the wolf sprite, a pale
ghost, a toxic slime.

Format: r,g,b. Default: none (the sprite's own white).

  color=170,220,255

The editor previews the recoloured sprite next to the field and on the map view. Recolouring works best on simple single-figure sprites.

== creature.hp | Creature HP
see: creature.level, creature.def

Maximum hit points. Each level bonus from groups, dungeons or encounter
tables adds 6.

Format: whole number. Default: 10.

  hp=22

Rough guide from the shipped game: level 1 monsters 9-20, level 4 bosses
around 70, late bosses several hundred.

Bosses that should last several rounds need a lot more HP than their level suggests.

== creature.mp | Creature MP
see: creature.spells

Mana for the creature's spells. Each cast costs the spell's cost.

Format: whole number. Default: 0.

  mp=30

A caster with too little MP falls back to plain attacks after a few spells.

Without spells= MP does nothing. Shipped casters carry 10 to 50 MP, bosses up to 300.

== creature.stats | Creature stats
see: class.stats, creature.dmg, creature.level

The six stats: STR, DEX, CON, INT, WIS, CHA. DEX raises hit chance (x2) and
crit chance; the spell stat (usually INT or WIS) powers its spells.
Creatures' HP, MP and attack damage come from their own keys, not from
stats.

Format: str:n,dex:n,... (six number boxes). Default: 8 each.

  stats=str:10,dex:13,con:8,int:3,wis:6,cha:3

Each level bonus adds +1 to every stat.

== creature.def | Creature defence
see: item.def, creature.res

Armour: subtracted from every weapon hit it takes (halved on crits), keeping at
least 35% of the damage. Each 2 level bonuses add 1.

Format: whole number. Default: 0.

  def=3

High def makes a monster shrug off daggers but not spells - give heavily
armoured enemies a magic or shock weakness for balance.

== creature.evasion | Creature evasion
see: item.evasion

Percent points subtracted from attackers' hit chance.

Format: whole number. Default: 0.

  evasion=5

Fast small things (rats, bats, wisps) get 5-15.

Each point is one percent less chance to be hit. Very high evasion (25+) makes a fight feel random; use it on small, quick creatures only.

== creature.res | Creature resistances
see: item.res, creature.undead, creature.mechanical

Percent resistance to each damage type; negative values are weaknesses (they
take more). The party learns them by hitting the creature and sees them in the
bestiary.

Format: type:value,... (six number boxes). Default: none. Capped at 90.

  res=physical:20,poison:100,fire:-40,cold:-20

Weaknesses make fights interesting: a slime weak to fire rewards a torch or a
fire spell.

== creature.dmg | Creature damage
see: creature.dmgtype, creature.range, creature.ap

The damage range of the creature's attack. Each level bonus adds 1 to both
ends.

Format: lo-hi. Default: 1-3.

  dmg=7-13

Creatures do not use weapons, so stat bonuses do not apply; set the damage you
want directly.

Spread matters: 1-10 feels swingy, 5-6 steady.

== creature.dmgtype | Creature damage type
see: creature.dmg, item.dmgtype

The damage type of its attack: physical, fire, cold, shock, poison or magic.

Format: dropdown. Default: physical.

  dmgtype=poison

Combine with onhit= for attacks that also apply a status.

The party's resistances (from armour and affixes) reduce it. A poison or fire attacker makes antidotes and fire resistance worth carrying.

== creature.range | Creature attack range
see: creature.ai, item.range

Attack reach in tiles: 1 is melee, more is a ranged attacker (archers,
gunners, spitters).

Format: whole number. Default: 1.

  range=6

Ranged monsters next to the party often step back before shooting, and may go
on overwatch when they cannot see a target.

== creature.ap | Creature attack AP
see: creature.apmax, item.ap

How many AP one attack costs.

Format: whole number. Default: 4.

  ap=3

With apmax=6 and ap=3 a creature can attack twice a turn if it does not need
to move.

If ap is higher than apmax the creature can never attack, so keep ap at or below apmax.

== creature.apmax | Creature AP per turn
see: creature.ap, creature.move

The AP the creature gets each turn for attacks and spells.

Format: whole number. Default: 6.

  apmax=7

Party members have about 8 + DEX/5; most monsters 6-7, bosses up to 9.

Movement uses move=, not AP, so apmax is all about how many attacks or spells it can fit in.

== creature.move | Creature movement
see: creature.apmax

How many tiles the creature can move each turn.

Format: whole number. Default: 4.

  move=5

0 makes a stationary enemy (turrets, plants). Wolves and rats 5-6, heavy
golems 3.

Stationary enemies (move=0) still attack anything within their range. Movement does not cost AP.

== creature.accuracy | Creature accuracy
see: item.accuracy

Bonus to hit in percent points, on top of 72% + DEX x 2.

Format: whole number, can be negative. Default: 0.

  accuracy=10

Use a negative value for clumsy brutes that hit hard but often miss. DEX matters more: every point of DEX is worth 2 accuracy.

== creature.ai | Creature AI
see: creature.spells, creature.range, creature.boss

How the creature fights:

- melee: closes in and attacks.
- ranged: keeps its distance, shoots, may step back or go on overwatch.
- caster: uses its damage spells when it can, otherwise attacks.
- support: heals hurt allies with its healing spells first, then attacks.
- coward: often backs away when the party is close.
- boss: heals and casts like support/caster, and never retreats.

Format: dropdown. Default: melee.

  ai=caster

Gotchas: caster, support and boss only cast if the creature has spells= and
enough MP and AP (4+).

== creature.spells | Creature spells
see: creature.ai, creature.mp, spell.id

The spells the creature can cast in combat.

Format: spell ids separated by commas ("+ add" picker). Default: none.

  spells=fireball,heal

Gotchas: needs ai caster, support or boss, and mp= enough for a few casts.
Monster area spells hurt their own allies standing in the blast, just like the
party's.

== creature.xp | Creature XP
see: creature.level

Experience the party gets for killing it, shared among the living members.
Each level bonus adds 8.

Format: whole number. Default: 10.

  xp=90

Kill bounties also pay more for high-XP creatures.

Rough guide: about 6 for a rat, 20-40 for mid monsters, 90 for an early boss.

== creature.level | Creature level
see: obj.enemy.level, table.level, creature.xp

The creature's base level, shown in combat and the bestiary. It also sets the
loot tier odds of the equipment it drops (higher = more uncommon and rare
items). Level bonuses from groups, tables and dungeons are added to it.

Format: whole number. Default: 1.

  level=4

Level does not change hp, dmg or stats by itself - only level bonuses do.

== creature.gold | Creature gold
see: creature.loot

Gold dropped when killed, a random amount in the range.

Format: lo-hi. Default: 0-0.

  gold=18-36

Animals usually drop none; bandits and bosses carry coin.

Gold from all defeated creatures is added up and shown on the victory screen. Remember that fleeing costs 5% of the party's gold, so gold should not be too plentiful.

== creature.loot | Creature loot
see: creature.gold, obj.chest.items

Items the creature may drop, each with its own chance in percent.

Format: id:chance,... ("+ add" picker appends id:50 - edit the number).
Default: none.

  loot=steel_sword:30,kite_shield:30,chief_tusk:100

Equipment drops roll a loot tier by the creature's level and may gain affixes.
Use 100 for quest items a boss must always drop.

== creature.onhit | Creature on-hit effect
see: creature.dmgtype, spell.effect

A status its attacks inflict 35% of the time (for 3 turns): poison, weaken,
burn, freeze or stun.

Format: dropdown. Default: empty.

  onhit=poison

Spiders and snakes poison, ghouls weaken. Use sparingly on early monsters -
stacked poison is deadly at level 1.

== creature.boss | Boss
see: creature.ai, creature.music, dungeon.boss

boss=1 marks a boss: combat switches to its own music (creature.music; none =
the boss track), stun does not work on it,
fleeing is much harder (-25%), and notice boards never post kill bounties for
it. The bestiary labels it BOSS.

Format: 1 or 0. Default: 0.

  boss=1

Usually paired with ai=boss and size=2 for the big ones.

== creature.undead | Undead
see: creature.darkvision, creature.res

undead=1: immune to poison damage, and sees in the dark unless darkvision=0.

Format: 1 or 0. Default: 0.

  undead=1

Give undead a weakness to magic or fire so clerics and torches shine in
crypts.

Undead skeletons and ghosts are good for crypts where the party lacks light.

== creature.mechanical | Mechanical
see: creature.undead, creature.darkvision

mechanical=1: immune to poison, takes 50% extra shock damage, may be stunned by
shock grenades, and sees in the dark unless darkvision=0.

Format: 1 or 0. Default: 0.

  mechanical=1

Use it for drones, robots and golems.

Mechanical creatures are the natural targets for shock weapons and EMP grenades.

== creature.darkvision | Darkvision
see: map.dark, creature.undead

darkvision=1 means the creature fights normally in the dark: no accuracy
penalty for attacking unlit targets. Others suffer a penalty attacking into
darkness on dark maps.

Format: 1 or 0. Default: 1 for undead and mechanical creatures, 0 otherwise.

  darkvision=1

Most cave dwellers (rats, goblins, spiders) have it in the shipped game.

== creature.faction | Creature faction
see: creature.id

A label for what sort of foe it is: monster, bandit, machine, wild, undead or
rift. It is shown in the bestiary.

Format: dropdown. Default: monster.

  faction=wild

It does not change behaviour: every non-party creature fights the party.
It is also unrelated to town reputation (the Factions tab), which is about
how people see the party.

Pick the faction that matches the creature's story for a tidy bestiary.

== creature.sound | Creature death sound
see: tab.sounds, creature.attacksound

The sound event played when the creature dies.

Format: a sound event id (picker). Default: empty = death_enemy. Shipped: death_machine,
death_spirit, death_bones, death_slime, death_big, death_rift (1.3.3).

  sound=death_enemy

Use a custom event (Sounds tab, New sound) for a memorable boss death. A creature without a death sound still plays the default one.

== creature.attacksound | Creature attack sound
see: creature.sound, item.sound

The sound event played on each of its attacks.

Format: a sound event id (picker). Default: empty = attack_melee, or attack_bow
for ranged creatures.

  attacksound=attack_laser

Monsters with a gun look need attack_gun or attack_laser here, because creatures have no weapon item to pick the sound from.

== spell.id | Spell id

The spell's id, used by class spells= and learn=, creature spells=, item

Format: lowercase id, unique in spells.txt.

  id=frost_bolt

The name shown in spell menus, the hotbar and the combat log ("Mara casts

  name=Frost Bolt

see: spell.name

The description in the spell list and level-up screen. Cost, damage and area

Format: any text. Default: empty.

  desc=A shard of ice that may freeze the target.

== spell.tile | Spell icon
see: concepts.tiles

The icon in menus and the projectile drawn in combat.

Format: col,row (picker). Default: 82,33.

  tile=97,37

== spell.cost | Spell MP cost
see: spell.ap, creature.mp

MP spent per cast.

Format: whole number. Default: 5.

  cost=4

Scrolls (item spell=) cast it for free.

Cheap spells (2-4 MP) are used every fight; big area spells cost 8-15. Monster casters need enough mp= for a few casts. MP refills when the party rests.

== spell.ap | Spell AP cost
see: spell.cost, item.ap

AP spent per cast in combat.

Format: whole number. Default: 4.

  ap=3

see: spell.area, spell.target

How far away (in tiles) the target tile may be. The caster also needs line

Format: whole number. Default: 5.

  range=6

== combat.tactics | Fights: cover, terrain and tricks (1.4.0)
see: combat.combos, tilekind.fights, spell.shape, creature.role, creature.windup, obj.enemy.goal, item.trait, class.passive

What decides a fight besides the numbers:

- Cover: a blocking tile on the side facing the shooter gives half cover
  (-20% to hit; impassable but see-through: tables, crates, rocks) or full cover
  (-40%; walls). Point blank there is no cover. The move preview marks every
  tile you can reach with a bar on each side that would give cover against the
  foes who can see it there (short bar = half, long = full).
- Exposed: a target standing next to cover that doesn't face the attacker
  (shot from the open side) is +15% to hit and +15% crit, like a flanked one.
- Hunker down: Defend in cover doubles the cover (half 40%, full 80%);
  Defend in the open is -20%.
- Spells: single-target damage spells do 25% less against half cover and 50%
  less against full cover. Area spells, lines, cones, chains, grenades and
  weapon skills like Volley ignore cover.
- Smoke (Smoke Bomb, Smoke Screen): blocks sight; whoever stands in it has
  full cover and can only be aimed at from right next to them.
- Cover changes: furniture with breaks= is blown apart by enough area damage
  and burns at the first fire (tile kinds burns=1); Shield Bash shoves its
  target a tile back, out of its cover.
- Terrain: shock spreads through water (conduct=1) to everyone standing in
  it; fire spells leave burning ground on flammable kinds (it spreads, and
  burns whoever walks in or starts a turn there); cold area spells leave ice
  (+1 move cost). Ground effects end with the fight; broken furniture and
  snuffed braziers stay until the party leaves the map.
- Darkness: monsters that see in the dark and stand unlit when a fight starts
  get a free round; some (snuff=1) put out braziers; a unit next to an unlit
  brazier can light it again (2 AP). Torches burn in fights too.
- Surprise: catching a group unaware (Camouflage, or walking up to it unseen
  and attacking, or a touch map's group that wasn't chasing yet) gives the party
  a free first round.
- Morale: when a group's leader (role=leader) falls, the rest run and are
  gone a turn later.
- Bosses with windup= announce their big attack: the marked tiles get hit at
  the start of the boss's next turn.
- Difficulty: Hard foes flank, focus fire harder, go for exposed and helpless
  targets and drink a draught when hurt; Story foes do less of that.

== combat.combos | Status combos
see: combat.tactics, spell.effect

A status on the target plus a hit of the right element sets off a reaction.
The rules live in one table in the game (kCombos in combat.cpp); the Journal's
Tactics page lists them for players.

- SHATTER: shock on a frozen target (+60% damage) or a chilled one (+40%);
  ends the freeze.
- THAW: fire on a frozen target - an extra burst of fire damage; ends the
  freeze.
- FLARE: fire on a poisoned target - all the poison it still had does its
  damage at once.
- STEAM: cold on a burning target - puts the fire out and blinds them.

Primers: every cold hit leaves the target chilled (2 turns). Mark Target
(effect=marked) gives everyone +15% to hit and crit against the target;
Scan Weakness (effect=tagged) makes the next hit on it a critical. The Mage's
passive makes combos 50% stronger and primers last a turn longer.

== tilekind.fights | Tile kinds in fights
see: tilekind.conduct, tilekind.flammable, tilekind.burns, tilekind.breaks, tilekind.snuff, combat.tactics

The "in fights" and "turns into" rows of the Tiles tab say what a kind does
when a fight happens on it. Nothing here changes exploring.

  breaks=debris
  breakhp=12
  burns=1
  conduct=1
  flammable=1
  snuff=brazier_out
  kindle=brazier

== tilekind.conduct | Carries shock
see: tilekind.fights, combat.tactics

conduct=1: shock damage (spells, shock grenades) on someone standing on this
kind also hits everyone else standing in the same patch of conducting tiles,
up to 4 tiles away, for half. Chain spells jump 2 tiles farther between two
units standing in it.

Format: 1 or 0. Default: 0. The base game sets it on water, deepwater,
shallows, floor_water, mire, ford, river and swamp.

== tilekind.flammable | Flammable ground
see: tilekind.fights, tilekind.burns, spell.ground

flammable=1: fire area spells and fire grenades leave burning ground on this
kind for 3 rounds. Fire spreads to neighbouring flammable tiles. Standing in it
(walking in, or starting a turn there) burns.

Format: 1 or 0. Default: 0. Grass, meadow, tall grass, crops, reeds and hay
have it.

== tilekind.burns | Burns (cover)
see: tilekind.breaks, tilekind.flammable

burns=1 on a kind with breaks=: the first fire damage on it breaks it at once
and leaves burning ground where it stood; burning ground next to it may set it
alight too. For wooden furniture.

Format: 1 or 0. Default: 0.

== tilekind.breaks | Breaks into
see: tilekind.burns, tilekind.fights, combat.tactics

breaks=KIND: area damage on this tile (blasts, grenades, Volley, a boss's
wind-up) adds up, and at breakhp= (default 10) the cell turns into KIND - a
crate blown apart into debris, so whoever hid behind it loses their cover.
breakhp= sets how much it takes.

The change lasts until the party leaves the map.

  breaks=debris
  breakhp=16

== tilekind.snuff | Put out / lit
see: tilekind.fights, creature.snuff

snuff=KIND on a light source: what it becomes when a monster with snuff=1 puts
it out in a fight. kindle=KIND on the unlit kind: what it becomes when a party
member next to it lights it (2 AP; click it in a fight).

  snuff=brazier_out
  kindle=brazier

== tilekind.kindle | Lit
see: tilekind.snuff

kindle=KIND: an unlit light source a party member can light in a fight (stand
next to it, click it, 2 AP). See tilekind.snuff.

== spell.shape | Spell shape
see: spell.area, spell.chain, spell.range

shape=ball (default) covers area= tiles round the target. shape=line runs from
the caster through the target, range= tiles long, and stops at a wall. shape=cone
widens from the caster toward the target, range= tiles long. Lines and cones hit
friend and foe (unless ff=0) and ignore cover. The targeting preview shows the
tiles.

  shape=line

== spell.chain | Chain
see: spell.shape, tilekind.conduct

chain=JUMPS:RANGE:FALLOFF - hits the target, then jumps to the nearest living
unit (either side) within RANGE tiles that it hasn't hit yet, JUMPS times, each
jump FALLOFF percent weaker. Water carries it 2 tiles farther. The preview
shows the jumps and the damage left at each.

  chain=4:3:25

== spell.knockback | Knockback
see: combat.tactics

knockback=1: a damaged enemy is shoved one tile straight away from the caster
if that tile is free and walkable - out of its cover. Bosses and big creatures
hold firm. Shield Bash has it.

== spell.smoke | Smoke
see: combat.tactics, spell.area

smoke=N: a cloud over the spell's area for N rounds. It blocks sight lines;
whoever stands in it has full cover and can only be aimed at from next to them.

  smoke=3

== spell.ground | Ground effect
see: tilekind.flammable, combat.tactics

ground=fire leaves burning ground on every tile the spell covers (without it,
fire area spells only light flammable ground); ground=ice leaves ice (+1 move
cost). Often given by an upgrade= line (Fireball at Mage rank 8).

== spell.upgrade | Rank upgrades
see: class.learn, class.passive

upgrade=RANK:key=value,key=value:Text - from RANK in the class that teaches the
spell (its learn= or spells=), the spell changes as if those keys were set. Use
several upgrade= lines for several steps. The text is shown on the level-up
screen when that rank is chosen.

  upgrade=8:ground=fire:Mage rank 8 - leaves the whole blast burning.
  upgrade=10:area=2:Ranger rank 10 - covers a wider area.

== creature.role | Role
see: combat.tactics, creature.windup

How the creature behaves beside its numbers:

- guard: allies next to it count as in half cover; it keeps by its side's
  archers and raises its shield.
- sniper: holds a lane on overwatch and rarely moves.
- support: (with ai=support) buffs allies with its ally spells - bless,
  strength, shield - not only heals.
- leader: when it falls, the rest of its group breaks and runs.

== creature.windup | Wind-up attack
see: creature.role, combat.tactics

windup=SPELL: from round 2, at most every third round, the creature announces
SPELL instead of acting: the tiles it will hit are marked red, and it lands at
the start of its next turn on whoever is still there. The spell needs no MP.
Without area= or shape= it covers 3x3 round the target.

  windup=grave_nova

== creature.ward | Ward
see: creature.windup

ward=CREATURE: takes half damage while a creature of that id still stands in
the fight. The Lich is warded by its necromancer: kill that first.

== creature.snuff | Puts out lights
see: tilekind.snuff

snuff=1: on dark maps it walks to lit braziers (kinds with snuff=) and puts
them out in a fight.

== creature.fx | Creature effects
see: item.fx

fx=key:value,... - the same effect keys as items (see item.fx).

== item.trait | Weapon trait
see: item.fx, combat.tactics

The weapon family's trait:

- reach: hits enemies 2 tiles away in a straight line (spears; range=1).
- cleave: also hits foes next to both you and the target, for half (axes).
- backstab: +25% crit against flanked or exposed targets (daggers).
- crush: armour soaks at most 40% of a blow instead of 65% (maces).
- arc: shoots over half cover, for 25% less damage (bows).
- steady: loses no accuracy at long range (rifles).
- quick: attacks cost 1 less AP (pistols).
- spread: also hits others in a short cone past the target, for half
  (shotguns).

== item.fx | Item effects
see: item.trait, affix.mods

fx=key:value,... special effects while the item is worn, shown on the item in
plain words: ignorehalfcover, flankcrit:N, noowpenalty, vsfrozen:N,
critburn, covermove:N, aooslow, aoostop, shieldcover, combopower:N,
primerturns:N, vsundead:N, lightaura:N, killap:N, laststand, move:N,
markdmg:N, spelldmg:N, chillfreeze, mpcost:N, itemap:N, machinecrit:N,
healpower:N, healcure, smoketurns:N, hit:N, exposedhit:N. Class passives and
perks use the same keys. smoke:N on a smoke bomb is how many rounds its cloud
lasts.

  fx=ignorehalfcover:1,flankcrit:15

== class.passive | Class passive and perks
see: class.learn, item.fx, spell.upgrade

passive=Name|fx|Description is what every rank in the class gives from rank 1;
perk4=, perk8=, perk12= (any perkN=) add a perk at that rank in the class. fx is
key:value;key:value with the item.fx keys, or spell:ID to teach a spell. The
level-up screen shows the perk a rank brings, and the next one to come.

  passive=Hold the Line|aoostop:1;shieldcover:1|Their swings stop a foe that slips past.
  perk12=Override|spell:override|Learns Override.

see: class.passive

== obj.enemy.goal | Fight goal
see: obj.enemy.goaltext, obj.enemy.ongoal, combat.tactics

goal= gives the fight with this group a goal, shown at the top of the fight:

- protect:CREATURE - that creature joins on your side; if it falls the goal
  fails (ongoalfail= runs) and the fight goes on.
- reach:X,Y[,W,H] - a party member standing on those tiles wins the fight;
  the enemy left withdraws.
- hold:ROUNDS - last that many rounds and the enemy withdraws.
- close:CREATURE - the group's creatures with ai=rift are rift tears: each
  round every open one lets a CREATURE through, until a party member next to
  it spends 2 AP to close it (click it).

  goal=hold:4
  goaltext=Hold the gate until the guards come

== obj.enemy.goaltext | Goal text
see: obj.enemy.goal

The line shown at the top of the fight (empty = one made from goal=).

== obj.enemy.ongoal | On goal done
see: obj.enemy.goal, obj.enemy.ongoalfail

Actions run when the goal is done (the same actions as a trigger's script=).

== obj.enemy.ongoalfail | On goal failed
see: obj.enemy.goal

Actions run when a protect goal fails.

== spell.area | Spell area
see: spell.range, spell.ff, spell.dmg

Radius in tiles around the target tile. 0 hits one target; 1 is a 3x3 blast;
2 a 5x5.

Format: whole number. Default: 0.

  area=1

Gotchas: damaging area spells hit everyone inside, the caster and allies too
(unless ff=0); the targeting preview warns. Fire and shock blasts light the
area for a moment on dark maps.

== spell.dmg | Spell damage
see: spell.dmgtype, spell.stat, spell.area

Damage dealt to each target, plus (stat - 8) / 2 from the caster's spell stat.
Crit chance is 5% + stat/3 (x1.5 damage).

Format: lo-hi. Default: 0-0 (no damage).

  dmg=10-18

Spell damage ignores armour defence; only resistances reduce it.

== spell.dmgtype | Spell damage type
see: spell.dmg, creature.res

physical, fire, cold, shock, poison or magic. It also picks the cast sound
(fire, ice, lightning, poison) when sound= is empty.

Format: dropdown. Default: magic.

  dmgtype=cold

A big fire, shock or physical area spell can also blast through rubble
obstacles.

== spell.stat | Spell stat
see: spell.dmg, spell.heal, class.stats

The caster stat that powers the spell: +(stat-8)/2 damage, +(stat-8) healing,
effect strength, crit chance, and how long utility spells last.

Format: str, dex, con, int, wis or cha. Default: int.

  stat=wis

Mage spells use int, cleric spells wis, warrior shouts str, ranger skills dex.

== spell.heal | Spell healing
see: spell.stat, spell.target

HP restored to each target, plus (stat - 8). Healing spells can also be cast
outside combat from the Spells menu.

Format: whole number. Default: 0.

  heal=12

Use target=ally (or self) - healing only ever touches the caster's side.

A heal spell with effect=cure both heals and removes poison.

== spell.effect | Spell effect
see: spell.duration, creature.onhit, item.effect

A status applied to each target: burn, freeze, shock, poison, regen, haste,
shield, weaken, stun, aim, strength, focus, blind; or cure (removes poison,
burn, weaken, blind, freeze) or revive (raises a fallen ally at a third of
their HP).

Format: dropdown. Default: empty.

  effect=freeze

Spells without damage always apply the effect; with damage it lands 50% of the
time. Bosses resist stun.

1.4.0: marked (everyone gets +15% to hit and crit against the target), tagged
(the next hit on it is a critical), override (an enemy machine fights for the
caster's side for the duration; not bosses), slow (half move). Every cold hit
also leaves the target chilled - see combat.combos.

== spell.duration | Spell effect duration
see: spell.effect

How many turns the effect lasts.

Format: whole number. Default: 0 = 3 turns.

  duration=2

Keep stun and freeze short (1-2); buffs can last 3-5.

A status already on the target is refreshed to the longer of the two durations, not stacked.

== spell.target | Spell target
see: spell.area, spell.heal

Who the spell can be aimed at:

- enemy: an enemy (default).
- ally: a member of the caster's side.
- self: the caster only - cast at once, no targeting.
- any: anyone, friend or foe.
- ground: any tile, even an empty one (for area spells).

Format: dropdown. Default: enemy.

  target=ally

Gotchas: single-target enemy spells need someone on the tile; area spells can
be aimed at an empty tile anyway.

== spell.summon | Spell summon
see: spell.duration, spell.target, creature.id

Makes the spell call creatures into the fight. They appear on free tiles
around the tile the spell was aimed at and fight for the caster's side: a
party member's summons are allies the game moves for you (blue frame), a
monster's summons join the monsters.

Format: creature id, optionally :count (1-4). Default: empty (no summon).

  summon=wolf
  summon=skeleton:2

- duration= is how many of the summon's own turns it stays (0 or empty = the whole fight).
- target=ground lets the caster pick the tile; range= is how far away.
- A caster keeps at most 3 summons at once; when the caster dies, its summons crumble.
- Summons leave no body and give no XP, gold or loot (so a necromancer can't be farmed).
- A party caster's summons get +1 level for every 3 levels of the caster.
- Monsters with ai=caster, support or boss use their summon spells early in a fight.

Gotchas: summon=1 is the old placeholder and does nothing - Check all warns
about it. The creature must exist (Creatures tab).

To have a spell bring in monsters, use a script-capable route instead, such as a dialogue spawn= action.

== spell.utility | Spell utility
see: spell.power, obj.obstacle.needs, tab.spells

A non-combat use, cast from the Spells menu outside fights:

- light: a glow around the party on dark maps for a while (in combat: a light at the target tile).
- stealth: monsters notice the party from a third of the distance and random fights are rarer.
- detect: counts the unopened chests on the map and makes them glow; 1.4.0: also uncovers needs=spell:detect obstacles within 8 steps.
- unlock: opens a locked door or chest next to the caster.
- recall: returns to the last town entered.
- One out-of-combat ability per class (1.4.0): Mage Rime (freeze), Scavenger Jumpstart (shock) and EMP Pulse (emp), Warrior Heave (force), Cleric Light, Ranger Camouflage and Sense Treasure, Scavenger Hack (unlock).
- freeze (1.4.0): turns the water of a needs=freeze obstacle next to the caster into ice for this visit.
- shock (1.4.0): wakes a dead machine, lift or door (needs=shock) next to the caster. Any shock damage spell does it from the obstacle's menu too.
- emp (1.4.0): scrambles a sealed tech door (needs=emp) next to the caster.
- force (1.4.0): clears a force:N obstacle next to the caster whatever the STR; with none, heaves the crate in front of the party one tile (heavy crates too).

light also reveals needs=light obstacles within two steps.

Format: dropdown. Default: empty.

  utility=unlock

Obstacles can ask for a utility: needs=spell:unlock.

== spell.power | Spell utility power
see: spell.utility, map.light

For utility=light cast in combat: the radius of the party's glow while the
light lasts.

Format: whole number. Default: 0 (= 7).

  power=8

Gotchas: cast outside combat, the Light spell currently uses the standard glow
of 5 (or a stronger light already active) and ignores power=. Other utilities
ignore it too; their duration grows with the spell stat.

== spell.ff | Spell friendly fire
see: spell.area

ff=1 (the default): a damaging area spell hurts everyone in the blast,
friends and the caster included. ff=0: it only hits enemies - for weapon skills
such as Cleave and Volley.

Format: 1 or 0. Default: 1.

  ff=0

Gotchas: only ff=1 area spells can blast through rubble obstacles.

== spell.level | Spell level
see: class.learn

The character level a party member needs to cast the spell. A member below
it cannot cast it, in combat or from the field; the Spells menu shows "needs
Lv N" instead of the MP cost. Monsters ignore it.

Format: whole number. Default: 1.

  level=3

Gotchas: it does not teach the spell - when a class learns it is still set by
that class's learn= (rank:spell), and an item spell= scroll still casts it.
Make sure level= is not higher than the level at which a class can learn it,
or the spell sits unusable in the list.

== spell.sound | Spell sound
see: tab.sounds, item.sound

The sound event played when the spell is cast.

Format: a sound event id (picker). Default: empty = automatic (heal, fire,
ice, lightning, poison, buff or a plain cast sound by what the spell does).

  sound=spell_fire

Utility spells pick light, stealth, detect, unlock or teleport sounds by default.

  id=warrior

The class name shown at character creation, on the party screen and in the

  name=Warrior

== class.role | Class role
see: class.desc, class.hd

A one-line summary shown on the level-up screen, where the player picks which

Format: any text. Default: empty.

  role=Front-liner. Biggest hit die (+8 HP a rank); shouts, Shield Bash and Cleave.

Say what a rank in this class adds, so multiclassing choices are easy.

== class.stats | Class starting stats
see: class.hd, item.bonus

The six starting stats for a character of this class. Every 2 levels a
companion who joins later gains +1 in each; the hero spends 3 stat points per

Format: str:n,dex:n,con:n,int:n,wis:n,cha:n (six number boxes). Default: 8

  stats=str:12,dex:9,con:12,int:6,wis:7,cha:8

What stats do: STR melee damage and force:N obstacles; DEX hit chance, crits,

== class.hd | Class hit die
see: class.md, class.stats

HP gained per rank in this class. Max HP = 8 + CON x 3 + the hit die of every

Format: whole number. Default: 6.

  hd=8

Shipped: Warrior 8, Ranger, Cleric and Scavenger 6, Mage 4.

  spells=spark,light

For spells that come later, use learn=.

Starting spells appear in the Spells menu right away and can be put on the hotbar (1-8). Companions also get them when they join.

== class.sprite | Class sprite
see: class.spriterow, class.spritecol, concepts.tiles

The character's sprite as one col,row, overriding spritecol/spriterow.

Format: col,row (picker). Default: none.

  sprite=105,18

A companion NPC's partysprite= (NPCs tab) gives them a different sprite from
their class.

Use the picker; it writes sprite= and removes spritecol/spriterow for you. The preview next to the field shows the chosen sprite.

== class.spriterow | Class sprite row
see: class.spritecol, class.sprite

The tileset row of the class sprite (the character "race").

Format: whole number. Default: 0.

  spriterow=18

Row 18 is a knight, 21 a mage, 26 a priest, 27 a ranger.

The hero and companions are drawn with this sprite on the map, in combat and in portraits.

== class.spritecol | Class sprite column
see: class.spriterow, class.sprite

The tileset column of the class sprite: 104 base pose, or a gear column such
as 105 sword, 109 staff, 113 shield, 116 gun, 117 bow.

Format: whole number. Default: 104.

  spritecol=117

Match the column to the starting weapon so the sprite shows what they carry.

== class.learn | Class spell progression
see: class.spells, spell.id, tab.spells

Spells learned as the character gains ranks in this class.

Format: rank:spell,rank:spell,... ("+ add" inserts 5:<spell>; edit the
number). Default: none.

  learn=3:war_cry,6:shield_bash,10:cleave,14:iron_skin

Gotchas: the rank is the rank in THIS class, not the character's level: a
Warrior 3 / Mage 2 knows the warrior spells up to rank 3 and mage spells up to
rank 2. Companions joining at a higher level arrive with their spells.

== shop.id | Shop id
see: tab.shops, obj.npc.shop, dlg.actions

The shop's id, used by dialogue shop=<id> and NPC shop=<id>.

Format: lowercase id, unique in shops.txt.

  id=hollowmere_smith

Name shops after town and trade (brasswick_market, murkwater_herbs) so they are
easy to find in pickers.

One shop can be used by several NPCs (a market with two stalls), and changing a shop's stock changes it for every NPC that opens it.

== shop.hours | Shop opening hours
see: tab.shops, obj.door

When the shop is open, as hours of a 24-hour clock: open from the first hour
until the second.

Format: from-to, for example 8-18. Default: empty = always open. 20-4 wraps
past midnight.

  hours=7-20

While closed, the merchant says "We're closed" (with the hours), and the front
door of the building they stand in is locked. Inns (a dialogue with rest=) are
never locked.

== shop.item | Shop stock line
see: tab.shops, item.id, item.value

One item the shop sells. Repeat the key for each item.

Format: id, or id:N to stock only N (restocking every 3 days). Default: weapons
and armour without :N stock 1-2; everything else never runs out.

  item=pickaxe:2
  item=bread

Gotchas: unknown ids are skipped. The order of the lines is the order in the
shop. Shops buy anything the party sells.

== table.id | Encounter table id
see: concepts.encounters, tilekind.biome, map.table, table.usedby

The table's id. A table is used when a tile kind's biome= matches it, when a
map's table= names it, or as <biome>_night at night.

Format: lowercase id. Shipped tables: plains, forest, hills, desert, swamp,
snow, wasteland, rift, water, plus plains_night, forest_night, hills_night,
swamp_night.

  id=forest_night

Gotchas: renaming a table cuts it off from every biome that used the old name.

== table.level | Encounter table level
see: table.group, obj.enemy.level

The level the table is balanced for. When the hero is above it, monsters get
+1 level for every 3 levels of difference.

Format: whole number. Default: 1.

  level=2

So a level 1 plains table stays a little relevant: a level 10 hero meets
goblins with +3 levels.

== table.group | Encounter table group
see: table.id, obj.enemy.group

One possible fight: the creatures that appear together. Repeat the key for
each possible group; one is picked at random on each ambush.

Format: creature ids separated by commas ("+ add" picker). Default: none.

  group=goblin,goblin,goblin_archer

Repeat a group line to make it more likely. Keep early tables to 1-3 weak
monsters - ambushes happen often.

== table.usedby | Where this table is used
see: concepts.encounters, tilekind.biome, map.table, map.encounter, dungeon.table

The panel under the table's fields lists everything that can make the game
pick this table:

- Tile kinds whose biome= is this table's id, with their encounter weight.
- Maps whose table= names it, with their encounter rate - and a warning when the rate is 0 (the table can never be rolled there).
- Dungeons with table= set to it.
- Maps that random-roll on those biome tiles (maps with an encounter rate that use those tile kinds).
- The night/day pairing: for a table <id>, its <id>_night partner (or for a _night table, its day table).

Click an entry to jump to it. In the table list, tables nothing uses are
marked "(unused)" - either the biome name is misspelled or nothing points at it
yet.

== quest.id | Quest id
see: tab.quests, concepts.ids

The quest's id. Quests are not started by id - their stages' conditions
decide everything - but a campaign or inherit file replaces a quest with the
same id.

Format: lowercase id, unique in quests.txt.

  id=caravan

Ids only matter for keeping entries unique; the player never sees them.

== quest.name | Quest name
see: quest.id, quest.stage

The quest's title in the journal and on the world map when a stage is pinned.

Format: any text. Default: the id.

  name=The Stolen Caravan

Use the same text in the dialogue's quest= action so the "Quest updated"
popup matches the journal.

== quest.stage | Quest stages
see: quest.stage.when, quest.stage.text, quest.stage.pin, quest.stage.done, quest.objective, quest.preview

A quest is a list of stages. Each stage is a condition and a journal text; the
journal shows the text of the LAST stage whose condition is true. If no stage
is true the quest is not in the journal yet.

Format in the file, one line per stage:

  stage=q_caravan>=1 | Pell's caravan was taken by bandits. @thornhollow
  stage=q_caravan_done | The bandit captain is dead. Tell Pell. @brasswick
  stage=q_caravan>=2 | DONE Pell rewarded you for recovering his goods.

The Quests tab shows each stage as a card with its condition (Shows when),
text, DONE box and map pin, in order. Order matters: put later story steps
lower.

== quest.stage.when | Stage condition (Shows when)
see: quest.stage, concepts.conditions, quest.preview

The condition that makes this stage the current one, as long as no later
stage is true too. The card reads it back in plain English, for example "q_main
is at least 2 and you do NOT have item rift_key". "+ flag" inserts a flag from
the list.

Format: a condition (the part before | in the file). Empty = always true.

  q_main>=3
  rift_shard3_found&!item:rift_key

Gotchas: because the last true stage wins, earlier conditions do not have to
turn false. Under each card the flags it uses are listed with where they are
set; a flag with nothing setting it means the stage can never show.

== quest.stage.text | Stage journal text
see: quest.stage, quest.stage.pin, quest.stage.done

What the journal says while this stage is current: what happened and what to
do next, with a hint where.

Format: any text (the part after | in the file). The DONE prefix and @pin
suffix are kept separately by the card.

  Carry the Elder's letter to Mayor Aldous in Brasswick, east along the road.

Write in second person ("You found..."), and always say where to go next.

== quest.stage.pin | Stage map pin
see: quest.stage, location.id, concepts.worldmap

The place this stage points at: a yellow pin on the world map, the place name
next to the quest in the journal, and the target of "show on map".

Format: in the file, " @<location id>" at the end of the stage text; the card
has a picker. Default: no pin.

  stage=q_main>=1 | Deal with the goblins in Greywood Cave. @greywood

Gotchas: pins use overworld location ids, not map ids. When the campaign's
world map is a map id, a pin can instead name a map id that one of that map's
exits leads to. Pins are hidden on DONE stages.

== quest.stage.done | Stage DONE
see: quest.stage, achievement.cond

Ticking DONE marks the quest as finished while this stage is current: the
journal entry is greyed out, its pin disappears, and it counts toward the
quests:N achievement term.

Format: in the file the stage text starts with DONE. Default: off.

  stage=q_main>=7 | DONE The Rift is sealed. Aldmoor is free.

Usually only the last stage is DONE.


== quest.objective | Quest objectives (checklist)
see: quest.stage, quest.stage.text, concepts.conditions, tab.quests

An objective is a checklist line shown in the journal under the quest. When
the player selects a quest in the journal it expands to show its full text
and the checklist; each line is ticked when its condition is true.

Format in quests.txt, one line per objective:

  objective=STAGE | DONE-CONDITION | TEXT
  objective=1 | itemn:herb_moon:3 | Gather Moonleaf in the Murkwater swamps ({itemn:herb_moon}/3)

- STAGE: the stage number (1 = first stage) during which the line shows. 0 shows it at every stage.
- DONE-CONDITION: a condition; while it is true the line is ticked.
- TEXT: what the line says. Counters fill in live: {itemn:id} (how many of an item the party has), {kills:creature}, {flag:name} (a counter flag's value), {gold}.

In the Quests tab each stage card has "+ objective"; each objective row has
"done when", "text" and an x to remove it. Moving or deleting a stage
carries its objectives along. Stage-0 objectives appear as plain key rows
in the form.

Gotchas: objectives are not shown on a DONE quest. Check all reports an
objective whose stage number does not exist.

== quest.preview | Quest preview
see: quest.stage, quest.stage.when, concepts.conditions

The Preview box lets you try the quest without playing: tick flags, type
numbers for counter flags (q_main = 3), and set items, and it highlights the
stage the journal would show - the LAST stage whose condition is true - with
its text and pin.

Use it to check that:
- each stage can be reached by some set of flags;
- a later stage really replaces an earlier one (the order is right);
- the DONE stage only shows when it should.

The preview does not change any save or file.

== dungeon.id | Dungeon id
see: tab.dungeons, map.id, location.map, obj.exit.to

The dungeon's id - also its map id. Exits, overworld locations and teleports
lead to it like any map.

Format: lowercase id, unique.

  id=goblin_cave

Gotchas: if maps/<id>.txt exists (a baked or hand-made map), the game uses
that file and ignores the generator. Generated monster flags are named
<id>_grp_<n> and chest flags <id>_chest_<n>.

== dungeon.name | Dungeon name
see: dungeon.id, map.name

The name shown when the party enters, and in kill bounties ("in Greywood
Cave").

Format: any text. Default: the id.

  name=Greywood Cave

If the dungeon is baked, the map file's name= is used instead. Choose a name that tells the player what kind of place it is, such as Greywood Cave or the Research Annex.

== dungeon.style | Dungeon style
see: tab.dungeons, dungeon.loot, dungeon.music

The look and layout:

- cave: winding cellular caves, mushrooms, crystals, webs; ore and ember caps.
- mine: caves with dirt floors; more ore and rough gems (bring a pickaxe).
- crypt: rooms of grey stone with coffins, bones and skulls; bone dust.
- castle: stone rooms with tiled floors, wooden doors, braziers and bookshelves.
- tech: metal rooms with terminals, servers and cryopods; scrap and circuits.
- ship: like tech, with hull walls and grid floors.
- sewer: brick walls, mire and barrels; moonleaf and slime gel.

Format: dropdown. Default: cave.

  style=crypt

Tech and ship dungeons are lit a little better and play tech music.

== dungeon.w | Dungeon width
see: dungeon.h

Width of the generated map in tiles.

Format: whole number. Default: 48.

  w=48

Bigger maps mean more rooms only up to a point (at most 12 rooms); 40-60 is a
good range.

Cave and mine styles fill the whole area with one connected cave; room styles place up to 12 rooms of 5-10 by 4-8 tiles joined by corridors.

== dungeon.h | Dungeon height
see: dungeon.w

Height of the generated map in tiles.

Format: whole number. Default: 40.

  h=36

Very small sizes (under 30) may not fit enough rooms for monsters, chests and a
boss room. Together with w it sets how sprawling the dungeon feels; 36-40 is typical.

== dungeon.seed | Dungeon seed
see: dungeon.bake

A number that picks the layout. The same seed always gives the same dungeon
(the game adds its fixed world seed to it).

Format: whole number. Default: 1.

  seed=11

Change it until you like the layout, then Bake map to keep and polish it.

== dungeon.level | Dungeon level
see: dungeon.monsters, obj.enemy.level

The dungeon's difficulty. Every monster group and the boss get level-1 extra
levels, and chest gold scales with it. Notice boards only post kill bounties
for dungeons up to 3 levels above the hero.

Format: whole number. Default: 1.

  level=3

== dungeon.exit | Dungeon exit
see: dungeon.id, obj.exit.tx, location.x

Where the up-stairs at the entrance lead: a map and the tile to arrive on.

Format: map,x,y. Default: overworld with 0,0 (its spawn).

  exit=overworld,56,79

Gotchas: for an overworld dungeon, use the tile right next to its location
marker (location x,y plus or minus one). The party arrives next to the up-stairs
when entering.

== dungeon.monsters | Dungeon monster pool
see: dungeon.boss, dungeon.level, creature.id

The creatures roaming groups are made from. Most rooms get a group of 1-3
creatures picked at random from this list; the boss gets two escorts from it.

Format: creature ids separated by commas ("+ add" picker). Default: none (an
empty dungeon).

  monsters=goblin,goblin,goblin_archer,rat,spider,bat

Repeat an id to make it more common. Kill bounties near the dungeon also draw
from this pool.

== dungeon.boss | Dungeon boss
see: dungeon.bossflag, dungeon.bossdefeat, creature.boss

The creature waiting in the room farthest from the entrance, with two
escorts from the pool and a treasure chest next to it.

Format: a creature id (picker). Default: empty (no boss room).

  boss=goblin_chief

Give the boss creature boss=1 and ai=boss for the full effect.

== dungeon.bossflag | Dungeon boss flag
see: dungeon.boss, concepts.flags, quest.stage.when

The flag set when the boss group is defeated. It keeps the boss dead and is
the natural thing for quests and dialogue to test.

Format: a flag name. Default: empty.

  bossflag=goblin_chief_dead

Gotchas: without a bossflag the boss comes back whenever the dungeon is loaded
fresh, and its bossdefeat= script can run again.

== dungeon.bossdefeat | Dungeon boss defeat script
see: concepts.scripts, dungeon.bossflag, obj.enemy.ondefeat

A script that runs when the boss group is beaten, just like an enemy's
ondefeat=.

Format: actions key:value separated by ;. Default: empty. Set bossflag= too.

  bossdefeat=set:q_goblins_done;notify:The goblin chief is dead. Return to Elder Mara.

Baking the dungeon copies it onto the boss group's ondefeat=.

== dungeon.loot | Dungeon loot table
see: dungeon.style, obj.chest.items

Which item list the chests draw from:

- common: potions, bandages, torches, flares, ore, oils.
- tech: medkits, stimpaks, ammo, cells, scrap, circuits, grenades.
- rare: strong potions, elixirs, scrolls, rings, steel gear, rift dust.

Format: dropdown. Default: common.

  loot=tech

Every chest also has a 20% chance of an extra rare item, and the boss chest
always holds strong potions.

== dungeon.music | Dungeon music
see: map.music, tab.sounds

The music track played in the dungeon.

Format: a [music] id (picker). Default: tech for tech and ship styles, dungeon
otherwise.

  music=dungeon

A baked dungeon map keeps this as its header music=. Any [music] track from the Sounds tab can be used, including your own imports.

== dungeon.ambient | Dungeon background loop
see: map.ambient, concepts.ambient, tab.sounds

A background loop played under the music in the generated dungeon (the base
game has no [ambient] entries since 1.3.1; a campaign can add its own).

Format: an [ambient] id (picker), or none. Default: empty = silence.

  ambient=my_drips

== dungeon.combatmusic | Dungeon fight music
see: map.combatmusic, campaign.combatmusic

The music for ordinary fights in the generated dungeon, as map.combatmusic does
for a map. Default: empty = the campaign's fight music. Baking copies it into
the map header.

  combatmusic=riders_of_the_storm

== dungeon.touch | Dungeon fights start by touch
see: map.touch, obj.enemy.aggro

Ticked: the monster groups in this generated dungeon only start a fight by
touching the party, as map.touch does for a map. Baking the dungeon copies it
into the map header.

Format: 1 or empty. Default: empty (groups attack on sight within aggro range).

  touch=1

== dungeon.table | Dungeon encounter table
see: map.table, concepts.encounters, table.usedby

An encounter table for the dungeon map (its fallback table=).

Format: a table id (picker). Default: empty.

  table=wasteland

Gotchas: generated dungeons have an encounter rate of 0, so this table is
never rolled until you bake the dungeon and give the map an encounter= rate
and floor tiles with an encounter weight. Baking copies table= into the map
header.

== dungeon.bake | Bake dungeon to a map
see: tab.dungeons, tab.maps, dungeon.seed

"Bake map" (under the Dungeons list) generates the selected dungeon with its
current seed and saves it as maps/<id>.txt, then opens it in the Maps tab.

From then on that file IS the dungeon: paint it, move monsters and chests, add
NPCs, triggers, levers and secrets. The dungeons.txt entry is ignored while the
file exists (delete the file to go back to generating).

The baked map keeps everything the generator made: walls and floors, the
up-stairs exit, the save shrine, monster groups with flags, the boss with its
bossflag and bossdefeat as ondefeat=, chests with flags, and gather nodes. Bake
overwrites an existing file of the same name - it asks first.

== recipe.id | Recipe id
see: tab.recipes, recipe.known, item.effect

The recipe's id. Formula items teach recipes by id (effect=learn:<id>,<id>).

Format: lowercase id, unique in recipes.txt.

  id=herb_bandage

Often the same as the result item's id, unless one item has several recipes.

Renaming a recipe id forgets it for saves that had learned it.

== recipe.name | Recipe name
see: recipe.result

The name in the crafting list and the "Recipe learned" message.

Format: any text. Default: the result item's name.

  name=Moonleaf Bandage

Use a name when the result's own name would be confusing in the list, for example two recipes for the same potion.

== recipe.result | Recipe result
see: recipe.count, item.id

The item the recipe makes.

Format: an item id (picker). Default: the recipe id.

  result=bandage

Equipment results can turn out fine or masterwork with extra affixes when the
station skill is well above the difficulty.

Materials, ammo and consumables stack; equipment results come out one item per count.

== recipe.count | Recipe count
see: recipe.result

How many of the result one craft makes.

Format: whole number. Default: 1.

  count=2

Use 2-5 for arrows, bandages and bullets.

The materials and gold are for the whole batch, not per item. The crafted items go straight into the party's pack. Batch recipes are nice for ammo.

== recipe.station | Recipe station
see: tab.recipes, obj.npc.craft, dlg.actions

Where the recipe can be made:

- forge: smiths. Metal weapons and armour.
- alchemy: alchemists. Potions, oils, enchanting.
- workbench: tinkers. Tech gear, ammo, gadgets.
- any: field crafting from the Items menu (C), anywhere.

Format: dropdown. Default: any.

  station=alchemy

Each station has its own skill that grows as the party crafts there; the best
party member's stat for that bench (STR at the forge, INT/WIS at alchemy,
INT/DEX at the workbench) helps a little.

== recipe.materials | Recipe materials
see: recipe.result, obj.gather.item

The ingredients used up by one craft.

Format: id:count,... ("+ add" appends id:1 - edit the count). Default: none.

  materials=iron_ingot:2,tanned_leather:1

Gotchas: a failed craft loses half the materials. Make sure every material can
be found, bought or gathered in the campaign.

== recipe.gold | Recipe fee
see: recipe.station

Gold paid per craft (the station's fee).

Format: whole number. Default: 0.

  gold=15

Charge a fee for valuable results so crafting does not undercut shop prices. The fee is paid even if the craft fails. A typical fee is a few gold for simple goods and 20-60 for fine gear.

== recipe.level | Recipe hero level
see: recipe.difficulty

The hero level needed before the recipe can be made.

Format: whole number. Default: 1.

  level=5

Recipes above the hero's level still show but cannot be made yet. Use it to keep endgame gear out of reach early. The hero's level is what counts, not a companion's.

== recipe.difficulty | Recipe difficulty
see: recipe.station, recipe.level

How hard the recipe is, 1 to 6, against the station's skill. Difficulty 1, or
a skill above the difficulty, always succeeds; otherwise the chance is about
70% + 15% per skill level above (or minus below) the difficulty, between 15% and
95%. A failure ruins half the materials.

Format: whole number 1-6. Default: 1.

  difficulty=3

Crafting well above the difficulty can produce fine (one enchantment) or
masterwork (two) results.

== recipe.known | Recipe known
see: recipe.reveal, item.effect

known=1: the recipe is available from the start. known=0: it must be learned
first from a formula item (effect=learn:<recipe id>) or a reward.

Format: 1 or 0. Default: 1.

  known=0

Formulas make good chest loot and quest rewards.

A learned recipe is remembered in the save.

== recipe.reveal | Recipe reveal item
see: recipe.known

The recipe only appears in the crafting list once the party has held this item
(once is enough; a "New recipe idea" popup announces it).

Format: an item id. Default: empty (always listed if known).

  reveal=frost_lichen

Use it so recipes for rare materials do not spoil the surprise.

== affix.id | Affix id
see: tab.affixes

The affix's id. Items with affixes get ids like iron_sword@keen+burning.

Format: lowercase id, unique in affixes.txt.

  id=keen

Gotchas: deleting or renaming an affix breaks items with it in old saves.

Ids are stored in item ids in saves, so pick them once and keep them.

== affix.name | Affix name
see: affix.pos

The word added to the item's name: before it for prefixes ("Keen Iron
Sword"), after "of" for suffixes ("Iron Sword of Burning").

Format: any text. Default: the id.

  name=Keen

Suffix names read best as nouns (Burning, the Bear, Warding). Keep it to one or two words.

== affix.pos | Affix position
see: affix.name, affix.tier

prefix or suffix. An item gets at most one of each.

Format: dropdown. Default: prefix.

  pos=suffix

A rare item gets one prefix and one suffix, so you need affixes of both kinds for every item type. Uncommon items get one of either kind.

== affix.tier | Affix tier
see: tab.affixes, affix.types

The lowest loot tier the affix can appear on. Loot rolls tier 1 (plain), 2
(uncommon, one affix) or 3 (rare, a prefix and a suffix); higher-level
creatures roll better tiers more often.

Format: 2 or 3 (1 behaves like 2). Default: 1.

  tier=3

Put strong affixes at tier 3 so they only show up on rare items.

== affix.types | Affix item types
see: affix.mods, item.type

The item types the affix can appear on.

Format: weapon, armor, helm, boots, accessory, offhand or any, separated by
commas ("+ add" picker). Default: weapon.

  types=armor,helm,boots

Use any for general affixes such as +HP; weapon-only for damage and accuracy; armour types for defence and resistances.

== affix.mods | Affix modifiers
see: affix.types, affix.dmgtype

The changes the affix makes to the item.

Format: key:value,... Keys: dmg (both ends), dmgmin, dmgmax, def, evasion,
accuracy, crit, hp, mp, ap, move, range, str, dex, con, int, wis, cha,
res_fire, res_cold, res_shock, res_poison, res_magic, res_physical.

  mods=accuracy:8,crit:5
  mods=dmg:-1,crit:5

Negative values make a cursed or cheap affix ("Rusty").

1.4.0: any other key is an effect mod (see item.fx): ignorehalfcover, flankcrit, noowpenalty, vsfrozen, critburn, covermove, aooslow...
Rare (tier 3) finds roll one of the affixes with an effect mod most of the time.

== affix.dmgtype | Affix damage type
see: affix.mods, item.dmgtype

For weapons: changes the item's damage type ("of Burning" makes it fire).

Format: fire, cold, shock, poison or magic. Default: empty (no change).

  dmgtype=fire

Leave it empty on armour affixes. A damage type on a weapon also changes which status it can inflict (fire may burn, cold may freeze).

== affix.value | Affix value
see: item.value

Price multiplier in percent applied to the item's value.

Format: whole number. Default: 160.

  value=90

Below 100 for bad affixes, 150-250 for good ones.

The multiplier stacks with the item's other affixes and reinforcing. The item's shop price and sell price both follow it.

== banter.class | Banter class
see: tab.banter, class.id

Who says the line: a companion's class id, or any for any companion.

Format: class id or any (picker). Default: empty (never plays - set it).

  class=warrior

Only party members other than the hero banter.

Use any for lines that suit anyone, such as weather remarks.

== banter.when | Banter moment
see: banter.map, banter.if

When the line can play:

- enter: right after entering a map.
- idle: now and then while walking.
- night, rain, dungeon, town, overworld: idle moments at night, in rain or storm, on a dungeon, town or overworld map.
- victory: after a won fight, once the party is back on the map.

Format: dropdown. Default: idle.

  when=dungeon

Gotchas: a line needs a living companion of that class, and its if= and
map= must match. The player's banter setting thins out non-enter moments
(off silences all). Playtest to hear them.

== banter.map | Banter map
see: banter.when

Limits the line to one map.

Format: a map id. Default: empty (any map).

  map=ashfall

Pair with when=enter for a remark on arriving somewhere specific.

The map id is the file name (map.id), not the map's display name. Lines with a map only play on that map.

== banter.if | Banter condition
see: concepts.conditions, banter.flag

The line only plays while this condition is true.

Format: a condition. Default: empty.

  if=q_main>=4&!q_main>=5

Use it to make companions comment on the current quest step.

The condition uses the same syntax as dialogue options, so approval:class:n works too. Test the line in a playtest with the dev console's flag command.

== banter.flag | Banter once
see: banter.if, concepts.flags

Makes the line play only once per game. The name is a label for this line
(stored as the flag _banter_<name>).

Format: a name. Default: empty (can repeat).

  flag=first_ashfall

Gotchas: it is not a story flag: setting the same name elsewhere does nothing.
Use if= to test real flags.

== banter.text | Banter text
see: banter.when

What the companion says. Add several text= lines for variants; one is picked at
random each time. $hero is replaced by the hero's name.

Format: any text, one line per variant.

  text=Watch the corners. Things like to jump out of corners.
  text=Smells like goblin in here.

Keep lines short - they appear in a speech bubble.

== achievement.id | Achievement id
see: tab.achievements

The achievement's id: stored when unlocked and forwarded to Steam in Steam
builds (the Steam achievement must use the same id).

Format: lowercase id, unique.

  id=first_blood

Gotchas: changing an id re-locks it for players who already had it.

Ids are stored in saves/achievements.ini, shared by every save slot.

== achievement.name | Achievement name
see: achievement.desc

The title on the popup and in the Achievements window.

Format: any text. Default: the id.

  name=First Blood

Keep it short: the popup is small. A pun or a nod to the moment works well. It is shown in bold on the Win98-style balloon popup.

== achievement.desc | Achievement description
see: achievement.hidden

The line under the title. The popup shows the first 34 characters.

Format: any text.

  desc=Win your first fight.

For hidden achievements the description is only shown after unlocking, so it can name spoilers. Say what to do in a few words, such as "Open 25 chests."

== achievement.cond | Achievement condition
see: concepts.conditions, achievement.id

Terms joined by &; all must hold. Counters are totals in the current game:

- fights:N kills:N fled:N gold:N (earned) level:N chests:N maps:N (visited) crafted:N bounties:N
- bestiary:N (kinds killed) steps:N day:N travels:N crits:N party:N quests:N (DONE) spells:N damage:N knockouts:N notes:N
- boss:CREATURE (killed one), item:ID (carrying it), approval:CLASS>=N
- flag:CONDITION - any condition, e.g. flag:q_goblins_done or flag:q_main>=7

Format: terms joined by &. Empty never unlocks.

  cond=flag:q_goblins_done
  cond=level:10&party:4

== achievement.tile | Achievement icon
see: concepts.tiles

The icon on the popup and in the Achievements window.

Format: col,row (picker). Default: 41,46.

  tile=0,19

Any tile of the main tileset works: a weapon, a creature, a coin. The icon is drawn at 2x on a grey square. Use the picker to browse.

== achievement.hidden | Hidden achievement
see: achievement.desc

hidden=1 hides the name and description in the Achievements window until it
is unlocked - for spoilers and secrets.

Format: 1 or 0. Default: 0.

  hidden=1

Hidden achievements still pop up normally when unlocked. Use it for story spoilers and jokes, not for ordinary goals players should aim for.

== dlg.nodes | Dialogue nodes
see: tab.dialogue, dlg.options, dlg.actions, dlg.camp

A dialogue file is made of nodes. A node starts with [name] and holds:

- speaker=Name: who talks. $hero is the hero's name. Without it, the NPC's name.
- text=...: the line. Several text= lines join into one paragraph with line breaks.
- option=Label|target|condition: a choice for the player (see Dialogue options).
- next=node: with no options, Enter goes on to that node.
- actions such as set=, give=, gold= (see Dialogue actions).

  [start]
  speaker=Elder Mara
  text=You came. Good. Sit, $hero.
  next=goblins

The conversation begins at [start]. Lines starting with # are comments. Without
options or next=, Enter ends the conversation. Option and next targets must be
node names in the same file, or end. To continue in another file, use the
dialogue= action.

== dlg.options | Dialogue options
see: dlg.nodes, concepts.conditions

  option=Label|target|condition

- Label: the text of the choice.
- target: the node it leads to, or end to close the conversation.
- condition (optional): the option only appears while it is true.

  option=It's me. Want to come?|join|q_main>=1
  option=Rent a room (10 gold).|room|gold:10
  option=About that shield...|shield_turnin|bram_quest&bandit_leader_dead&!q_bram_done
  option=Goodbye.|end

Gotchas: | separates the fields, so a label cannot contain |. If every option
is hidden by its condition, the node behaves as if it had none (next= or end).
Always leave one option without a condition, like Goodbye.

== dlg.actions | Dialogue actions
see: dlg.nodes, concepts.scripts, concepts.flags, concepts.worldmap, dlg.teach

Actions are key=value lines in a node and run, in order, the moment the node
shows. In scripts the same actions are written key:value.

Flags:
- set=a,b=2: set flags (to 1, or a number). flag=name: set one flag. inc=name: add 1. clear=a,b: unset.

Items and money:
- give=id:n,id (item= is the same). take=id:n. gold=n (negative pays; never below 0). xp=n (shared by the living party).

Party:
- join=<npc id>: add that companion NPC (NPCs tab, companion= a class) to the party (4 max): its name, class, party picture, level, stats, gear and spells. Sets joined_<class>. An empty join= adds the NPC being talked to. The older join=class:Name:col,row (Name and sprite optional) still works.
- leave=class or leave=class|text (1.5.0): that companion walks out the way an unhappy one does - gear to the pack, joined_<class> cleared, left_<class> set, back where you met them (amends= in their dialogue can bring them back). The text is logged.
- fell=class|text (1.5.0): that companion is gone for good, off screen (a red line crossed). Gear to the pack, joined_<class> cleared, fell_<class> set; their NPC stays hidden. Give their join and amends options !fell_<class>, and their map placement show=!fell_<class>.
- approve=class:n,class:n (or all:n). rep=faction:n,faction:n: change the party's reputation with a town or group (Factions tab), + or -.
- teach=who:spell or teach=who:spell|loyal_spell: a lasting ability (1.4.0, see Teaching abilities). who = a companion NPC id (bram), a class id, a member's name, or hero.
- heal=1: full HP/MP and sleep to 07:00. rest=1: inn rest - full HP/MP, revives, clears effects, morning. healer=1 or healer=<greeting>: paid healer menu. respec=1 (paid at a shrine) or respec=free.

Places and things:
- teleport=map,x,y (0,0 = spawn). shop=id. craft=forge|alchemy|workbench|any. board=town map id. travel=1: coach.
- combat=creature,creature: fight now. spawn=creature,x,y[,creature...]: add a group on this map (not saved).
- fight=FLAG (1.5.0): the enemy group on this map with that flag= attacks now, with its linked groups (link=) - as if the party walked into it, so its flag= and ondefeat= work as usual. If the party is far away it walks up first. Clear a hide= condition before it in the same node (actions run in order).
- npcmove=npc_id,x,y and mapset=x,y,tilekind: move an NPC / change a cell on the current map (saved).
- hidenpc=id: hide an NPC on this map for good (saved; the NPC needs an id). shownpc=id: bring it back. join= and combat= also hide the speaking NPC for good.
- savepoint=1: a save shrine where the party stands (not saved).
- revealmap=map_id or revealmap=map_id,x,y,r: reveal a whole map or a circle of radius r on the world map.

Messages and flow:
- message=Title|Text (also a journal note), note=Title|Text (journal only), notify=text (popup), log=text, quest=Name ("Quest updated" popup and sound).
- cutscene=line|line, dialogue=other_id (jump to its [start]), win=line|line (ending; sets game_won).

Gotchas: gold= does not check the purse - hide the option with gold:n. Actions
that open something else (combat, shop, teleport, craft, board, travel,
healer, respec, win) close the dialogue.

== dlg.teach | Teaching abilities (teach=)
see: dlg.actions, dlg.camp, tab.spells, class.id

  teach=bram:sedges_guard|sedges_bulwark

teach= gives someone a spell or skill for good. Before the | is the spell they
learn; after it (optional) the stronger version they use instead while the
companion is Loyal (flag loyal_<class> and approval 10 or more). If their
loyalty breaks, they go back to the first spell; when it holds again, the
strong one returns.

- who: a companion NPC's id (bram), a class id (warrior), a party member's
  name, or hero (the hero learns the spell at once; no Loyal version).
- A companion who is not in the party right now still learns it: the lesson
  is kept with the save and applied whenever they travel with you (also after
  they leave and come back).
- Spells taught this way are not class spells, so a respec keeps them.
- Several at once: teach=bram:a|b,orin:c.

The base game uses it at the end of every companion's personal quest: each
quest has two endings, each with its own ability (spells.txt, the block
"companion quest abilities").
In scripts: teach bram:sedges_guard|sedges_bulwark.

== dlg.camp | Companion camp talk ([camp])
see: dlg.nodes, dlg.actions, class.id

A node named [camp] in a companion's dialogue file is their "camp talk": in
the Party menu, select the companion and press T to open it at any time. Use it
for chats, personal quests, and approval-gated stories.

  [camp]
  speaker=Bram
  text=Boss. Need something?
  option=How are you holding up?|chat
  option=You said you were militia. What happened?|story|approval:warrior:15
  option=Nothing. Carry on.|end

The game uses the dialogue that ran the companion's join=, else the companion
NPC's dialogue= (NPCs tab), else any dialogue that contains a join= for their
class. Without a [camp] node: "<name> has nothing to
say right now." Check does not warn that [camp] is never reached.

== dlg.check | Dialogue Check
see: tab.dialogue, maps.check, editor.check, tab.flags

Check tests the open dialogue file, Check all tests every file. Findings
appear on the right as ERRORs and warnings; click one to jump to its line (in
the open file).

Errors: no [start] node, duplicate nodes, lines that are not key=value,
options or next= leading to missing nodes, unknown items, creatures, classes,
shops, maps, tile kinds or dialogue files, malformed teleport/spawn/npcmove/
mapset/approve values.

Warnings: nodes with no option or next, nodes nothing reaches, flags in
conditions that nothing sets, empty texts, zero gold/xp, unknown keys, options
with too many | fields, and dialogue files no NPC or other dialogue uses.

Hide closes the findings and shows the syntax sheet again.

== sound.id | Sound id
see: tab.sounds, item.sound, map.music

The id the game and your data use to ask for the sound. The game's own events
have fixed ids (step, door_open, hit, levelup, combat, boss...); "Used by" shows
what each one is for. Your new ids can be used in sound=, attacksound= and
music= fields.

Format: lowercase id, no spaces.

  id=chest_open

Gotchas: renaming a built-in id makes that game event silent.

== sound.kind | Sound kind
see: sound.id, sound.loop

sfx (a sound effect, [sound] in the file) or music (a track, [music]).
Effects are loaded into memory and can play many at once; music streams, one
track at a time, with a crossfade.

Format: click to switch. Default: sfx for [sound] entries.

  [music]

== sound.desc | Sound description
see: sound.id

A note on what the sound is for, shown in the list filter and the form.

Format: any text.

  desc=a chest creaks open

The list filter searches descriptions too, so a good description helps you find sounds later. It is not shown to players.

== sound.files | Sound files
see: tab.sounds, sound.pitchvar

The audio file(s) the entry plays, relative to assets/audio. With several, one
is picked at random each time (good for footsteps and hits).

Format: file=a.wav,b.wav in sounds.txt. In the form: "change", x, "+ add
existing", "+ import new file...". Files missing on disk show in red.

  file=sfx/hit.wav,sfx/hit2.wav

Supported: .wav, .ogg, .mp3. Audio is shared by every campaign.

== sound.volume | Sound volume
see: sound.files

Loudness in percent of the file, before the player's Settings sliders.

Format: whole number 0-200. Default: 100.

  volume=60

Keep frequent sounds (steps, UI) quiet: 40-60.

Music volumes around 70 leave room for effects. The player's master, music and effects sliders multiply this value.

== sound.pitchvar | Sound pitch variation
see: sound.volume

Random pitch change on each play, +/- this many percent, so repeated sounds
do not sound identical. Effects only.

Format: whole number 0-50. Default: 0.

  pitchvar=10

5-15 suits steps, hits and blips.

Music ignores it. Too much variation (over 20) makes voices and chimes sound wrong.

Works with a single file too: each play picks its own pitch. With several
files the game also never plays the same file twice in a row.

== sound.volvar | Sound volume variation
see: sound.pitchvar, sound.volume

Random loudness change on each play, +/- this many percent of the volume, so
a run of the same sound (footsteps, hits) doesn't sound machine-made.
Effects only.

Format: whole number 0-50. Default: 0.

  volvar=15

10-20 suits footsteps; keep it at 0 for interface sounds.

== sound.crunch | Sound crunch (lo-fi)
see: sound.pitchvar, tab.sounds

Plays the file through a lo-fi filter so it sounds like an old sound chip:
the sample rate is cut down (the sound gets grainy and "pixelated") and the
bit depth is reduced (it gets crunchy and gritty). Done once when the sound
loads; the file on disk is not changed. Effects only.

Format: crunchrate= in Hz (0 = off; 4000-22050 makes sense) and crunchbits=
(0 = off; 3-12 makes sense). Lower = crunchier.

  crunchrate=11025
  crunchbits=7

The buttons set both at once: Light 16000 Hz / 8 bits, Medium 11025 / 7,
Heavy 8000 / 5, Chip 5512 / 4, Off. They play the sound so you hear it
straight away. "Same crunch for N listed" copies this sound's crunch to every
effect in the list on the left - pick a group (or search) first to choose
which.

The bits are counted from the file's own loudest point, so quiet and loud
files crunch the same amount. Very low settings (under 6000 Hz, under 4 bits)
turn most sounds into buzz.

== sound.triggers | Sound triggers
see: tab.sounds, sound.id

A trigger is a moment the game plays a sound by itself: a step, a door, a
hit, a level up, a shop closing... Every one of them is listed in the Sounds
tab, grouped, with "Played when" saying when it fires.

Some triggers have no entry of their own. They borrow another sound, their
fallback: exit_locked, shop_closed, chest_locked and door_sealed borrow
door_locked; lever and door_unlock borrow unlock; gather borrows pickup and
gather_tool hit; burn borrows spell_fire; fuse_lit borrows grenade_throw;
unequip borrows equip; load borrows save; respec and craft_skill borrow
levelup; healer borrows rest; reinforce, enchant and salvage borrow craft;
bounty, recipe_learned and town_reward borrow quest; bounty_paid borrows
gold; reinforcements borrows ambush.

They show at the end of the list as "trigger > fallback". Select one and use
"Give it its own sound": it becomes a normal entry (starting with the
fallback's files and settings) that you can change without changing the
fallback. Delete the entry to make it borrow again.

Items, spells, creatures, objects, resources and tile kinds can name their
own sound (sound=, attacksound=, step=); those win over the trigger.

== sound.loop | Music loop
see: sound.kind

For music: loop=1 repeats the track forever; loop=0 plays it once (a jingle
or fanfare) and then stays silent.

Format: checkbox (loop=0/1 in the file). Default: 1.

  loop=0

The shipped victory fanfare and game over tracks are one-shot (loop=0); the map and combat tracks loop.

== campaign.worldmap | Campaign world map mode
see: concepts.worldmap, map.worldmap, item.effect, location.reveal, dlg.actions

What the M key shows (Campaign tab "World map" control). A map's own
worldmap= header overrides it while the party is on that map.

Format: overworld, off, current, or a map id. Default: overworld.

  worldmap=current

- <map id>: always that map; its exits are the listed places.

== campaign.combatmusic | Campaign fight music
see: creature.music, map.combatmusic, tab.sounds, tab.campaign

The music every ordinary fight in this campaign plays (Campaign tab, "Fight
music"). A map can override it with its own (Maps tab, "fight").

Format: the id of a [music] entry. Default: empty = the combat track.

  combatmusic=crown_of_thorns

Order: a boss's own music (creature.music), else any enemy's own music, else the
map's combatmusic=, else this, else combat.

== creature.music | Creature music
see: creature.boss, map.combatmusic, campaign.combatmusic, tab.sounds

The music that plays while this creature is in a fight (and still standing).
Give it to a boss so its fight has its own theme. Creatures tab: "music" (add
it with the quick-add button if the creature doesn't have it yet); the picker
lists every music track.

Format: the id of a [music] entry. Default: empty - a boss (boss=1) plays the
boss track, any other creature changes nothing.

  music=blood_and_honor

Order in a fight: a living boss's music (or boss), else the music of any other
living enemy that has some, else the map's combatmusic=, else the campaign's
fight music, else combat. When the boss falls the music goes back to the usual
fight music. Every boss in the base game names music=boss.

== campaign.defeat | If the party falls
see: tab.campaign, concepts.scripts, dlg.actions

What a lost fight does in this campaign (Campaign tab, "If the party falls").

Format: a script (actions key:value separated by ;). Default: empty.

  defeat=dialogue:tut_fallen

- Empty: the usual game over - "You have fallen", back to the desktop, load a save.
- A script: the party gets back up at full health, the enemies in that fight
  are whole again and hold still for a few steps (like after fleeing), and the
  script runs. Open a dialogue, teleport the party somewhere safe, set a flag.

The Tutorial uses it so a new player who loses a fight is helped up and
pointed back at the lesson instead of losing their progress.

Gotchas: nothing is lost, so a campaign with defeat= has no real danger.
Use it for tutorials and story-light campaigns. XP from the lost fight is not
given.

== tileset.browse | Browsing the tileset
see: tab.tileset, tile.picker, concepts.tiles

Scroll with the wheel (Shift+wheel moves sideways; dragging with the middle or
right button or the arrow keys pan). Hover a tile for its column and row and
what uses it.

To use a tile: type its col,row into any tile or sprite field (col,row@sheet for
a sheet other than the main one), or use that field's own "pick..." button.

On the base game's sheet, characters live in columns 104-117 (base pose at 104)
with one creature type per row; column 201 holds fallen versions.


== sheet.campaigns | Sprite sheets and campaigns
see: sheet.import, tab.tileset, concepts.campaigns, concepts.tiles

Each campaign keeps its sprite sheets in its own folder:
  assets/campaigns/<id>/sheets/<name>.png   the picture
  assets/campaigns/<id>/sheets/<name>.txt   its grid, categories and groups
The base game's main sheet is assets/tiles.png (its notes are in
assets/data/sheets/tiles.txt); more base-game sheets go in assets/data/sheets.

A new campaign starts with no sheets: its pickers are empty until you import a
picture or press Copy base game's, which copies the base game's sheet (with its
categories and groups) into the campaign's sheets folder, so you can repaint it
without touching the base game. A campaign with inherit=1 also sees the base
game's sheets.

The sheet called tiles is the campaign's main sheet: a tile written without
@sheet comes from it, and so do the pictures the game draws itself (chests,
doors, signs...). Without a tiles sheet of its own a campaign uses the base
game's. Every other sheet is named in the tile: col,row@name.

If a sheet goes missing, the tiles on it draw nothing; Check all lists every
sprite that names a sheet the campaign doesn't have.

== sheet.import | Importing a sprite sheet
see: sheet.campaigns, sheet.categories, tab.tileset

Tileset tab > Import picture... (or drop a PNG file anywhere on the Editor
window). Type or paste the path of the PNG and press Load; then:
- Name: the sheet's id, used in tiles as col,row@name. Calling it tiles makes
  it the campaign's main sheet (see Sprite sheets and campaigns).
- Tile size, First tile at, Gap between: how the picture is cut. Guess reads
  the picture's size; the blue grid over the preview shows where every tile
  is, and the hover line gives the pixel and tile under the pointer.
- See-through pixels: Black (black and transparent pixels are left out, the
  base sheet's way), Transparent only (black stays), or One colour (a
  background colour such as magenta; Pick in the picture takes it from a click).
- As the game cuts it shows the tiles as the game will have them.

The game draws every tile 12x12 pixels: other sizes are scaled (pixel art looks
best drawn at 12x12). Import copies the picture into the campaign's sheets
folder; importing again under the same name replaces the picture and keeps its
categories and groups. Grid... changes the cut of a sheet later; Reload picks up
a picture repainted outside the game; Remove deletes the sheet's files.

== sheet.categories | Tile categories
see: sheet.groups, tile.picker, tab.tileset

Every tile has one category, and a sprite field's picker opens on the matching
one:
- 1 Terrain: ground, floors, walls, water, roads (Tiles tab ground pieces).
- 2 Props: furniture, plants, doors, signs, machines (Tiles tab props, Objects,
  Resources, map objects).
- 3 Characters: party members and NPCs (Classes, NPCs, map NPCs).
- 4 Creatures: monsters and animals (Creatures).
- 5 Items: weapons, armour, potions, loot (Items).
- 6 Effects: spells, icons, symbols (Spells, Achievements).
- 7 Letters: text and digits.
- 8 Unused: never offered in a category (still under All).
- 9 Not sorted: a new sheet's tiles. They are listed after the sorted tiles in
  every category, so a fresh sheet can be used before it is sorted.

The base game's sheet comes sorted. Sort tiles in the Tileset tab (select, then
a key 1-9) or right-click a tile in any picker. Saved in sheets/<name>.txt
under [cells]: one line per row, one letter per column (t p c m i e l x, and .
for not sorted).

== sheet.groups | Tile groups
see: sheet.categories, tile.picker, tab.tileset

A group is a named set of tiles on one sheet - Potions, Swords and blades,
Goblins, Furniture - for finding the right picture quickly. The picker lists
the groups that have tiles in the category it shows (type in "find a group" to
narrow them); clicking one shows only its tiles. A tile can be in any number of
groups.

Make them in the Tileset tab (New... with the selected tiles, + Add selected,
- Remove selected, Rename..., Delete) or from a right-click on a tile in a
picker (Add to a group..., New group with this one..., Remove from ...). Saved
in sheets/<name>.txt as [group] sections (name=, tiles=col,row col,row ...).

== tile.picker | The tile picker
see: sheet.categories, sheet.groups, tab.tileset

Every tile or sprite field's "pick..." button opens it.
- Top row: the campaign's sheets, and Whole sheet (show the sheet as it is laid
  out, dimming tiles outside the category or group).
- Second row: the categories with how many tiles each has. The picker opens on
  the field's category (an item's sprite on Items, an NPC's on Characters...);
  All shows every tile.
- Left: the groups; (the whole category) goes back to the category.
- Click a tile to take it; None clears the field; Esc or Cancel closes.
- Right-click a tile to change its category or its groups without leaving.

Tiles not sorted yet are shown after a "Not sorted yet" line in every category.
== flags.status | Flag status
see: tab.flags, flags.desc, concepts.flags

Each flag in the Flags tab gets a status:

- ok: something sets it and something checks it.
- checked but never set (red warning): a condition tests it but nothing in the campaign ever sets it, so that option, stage or door can never happen. Usually a typo.
- set but never checked (grey): it is set but nothing reads it. Harmless - often a flag kept for later, or one that only matters to you.

Built-in flags (joined_<class>, game_won) count as set by their join= and win=
actions.

== flags.desc | Flag description
see: tab.flags, flags.status

A note you write about what the flag means ("Bram has agreed to look for the
captain's shield"). It is shown in the Flags tab and helps when you come back
to a campaign months later.

Format: any text. Saved in flags.txt in the campaign folder:

  [flag]
  id=bram_quest
  desc=Bram asked us to recover Captain Sedge's shield.

The game never reads flags.txt; it is documentation only. Use "New flag" to
describe a flag before anything uses it - it then appears in the flag
pickers.

== flags.rename | Rename a flag everywhere
see: tab.flags, flags.status, concepts.flags

"Rename everywhere..." in the Flags tab renames the selected flag in every
file that uses it, and saves those files at once:

- dialogue: set=, flag=, inc= and clear= values and option conditions
- map objects: flag, show, hide, moveif, openif, require, if, needs, script, ondefeat and onclear
- quest stage and objective conditions
- dungeon bossflag and bossdefeat
- world location require
- achievement cond and banter if
- the campaign's starting flags, and its note in flags.txt

Save everything first: if a map, dialogue, quest, dungeon, location, banter,
achievement, campaign or flag-note change is unsaved, the button only asks
you to save. If the new name already exists you are asked to confirm, since
the two flags become one.

Gotchas: the replace is whole-word, so renaming q_main does not touch
q_main_done. Ids after item:, itemn: or kills: are not flags and are left
alone even if they spell the same word. Saved games keep the old flag name;
rename before release.

== tab.bounties | Bounties tab (notice boards)
see: board, bounty, editor.check, concepts.flags
Notice boards post bounties: kill jobs, fetch jobs and courier letters to other boards. A board in the game is an NPC with board=<id> (Maps tab, npc object) or a dialogue line board=<id>. This tab edits bounties.txt, which says what each board posts.

- A [board] entry describes one board: its name, the map it stands in, how many random notices it posts a day, which kinds, and the pools they are drawn from.
- A [bounty] entry ("New hand-written notice") is a fixed notice that a board offers every day until it has been paid - a story bounty with your own title and text.

Courier letters only go to other boards in this file, and only once the party has visited that board's map, so a letter can never be sent somewhere without a board. If a campaign has no bounties.txt, every board= in its maps is found automatically and uses the default settings.

The panel on the right says what the selected board posts, lists problems (no NPC opens the board, unknown dungeons, items or creatures, letters to something that is not a board) and shows which NPCs and dialogue open it. Check all reports the same problems for every board.

== board | Notice board ([board])
see: tab.bounties, bounty, obj.npc.board
One notice board. Its id must match the board= value on the NPC (or the dialogue line) that opens it. Every field except id is optional; leave a field out to get the default.
  [board]
  id=hollowmere
  name=Hollowmere
  map=hollowmere
  offers=3
  kinds=kill,fetch,deliver

== board.id | Board id
see: board, obj.npc.board
The board's id: exactly what board= says on the NPC that is the board (or in a dialogue's board= line). Courier jobs and the deliver= lists of other boards refer to it. The Used by box on the right lists every NPC and dialogue line that opens this id; if it is empty, players can never read the board.

== board.name | Board name
see: board
Shown at the top of the board ("NOTICE BOARD - Brasswick"), in courier notices ("carry a letter to Brasswick") and in the journal. Default: the name of the overworld location whose map is the board's map, else the id.

== board.map | Board map
see: board, board.deliver
The map the board stands in. Letters are only sent to boards whose map the party has already visited, so this must be the map the board NPC is on. Default: the board id. The right-hand panel warns if the board NPC stands on a different map.

== board.location | Board location
see: board, location.id
The overworld location used for distances (courier pay, the nearest dungeons for kill jobs) and for the cyan map pin when a bounty is ready to collect. Default: the location whose map= is the board's map.

== board.offers | Notices per day
see: board, bounty
How many random notices the board puts up each morning (0 to 6, default 3). 0 = only its hand-written notices. Untaken notices come down the next day; taken ones stay in the journal.

== board.kinds | Kinds of notices
see: board, board.kill, board.fetch, board.deliver
Which random notices the board posts: kill, fetch and/or deliver, comma separated. Default: all three. A kind without anything to post (no dungeons, no other visited boards) is skipped.

== board.kill | Kill jobs: dungeons
see: board, board.creatures, dungeon.monsters
Dungeon ids whose monster pools the board's kill jobs pick from (bosses are never picked). Default: the 4 nearest dungeons whose level is at most the hero's level + 3.
  kill=greywood,troll_cave

== board.creatures | Kill jobs: creatures
see: board, board.kill
An exact list of creature ids for kill jobs. It replaces the dungeon pools; if kill= is also set, its first dungeon is named as the place to find them.
  creatures=wolf,boar,bandit

== board.fetch | Fetch jobs: items
see: board
Item ids the board asks for (2 to 4 of one). Default: random cheap crafting materials (value 40 or less). Listing items you can actually find nearby keeps fetch jobs sensible.
  fetch=herb_moon,iron_ore

== board.deliver | Courier destinations
see: board, board.map
Board ids that courier letters from here may go to. Default: every other board. A destination is only used once the party has visited its map, and two boards never trade letters back and forth. Naming something that is not a board is an error - that letter could never be delivered.

== board.reward | Reward percent
see: board
Scales the gold of this board's random notices: 100 = normal, 150 = half again, 50 = half. XP is not changed.

== board.rep | Reputation per notice
see: board, tab.factions
How much reputation the party gains with the faction that has this board's id each time a notice here is paid. Default 3; 0 turns it off.
  rep=5

== bounty | Hand-written notice ([bounty])
see: tab.bounties, board
A fixed notice. Its board offers it every day (up to three hand-written notices at once) until the party has done it and collected the pay; repeat=1 puts it back up afterwards. require= hides it until a condition holds.
  [bounty]
  id=wolf_cull
  board=hollowmere
  kind=kill
  target=wolf
  need=6
  where=greywood
  reward=60
  xp=50
  title=WANTED: wolves at the sheepfold
  text=Six of them. Old Tobb will pay.

== bounty.id | Notice id
see: bounty
A unique name for the notice. The save remembers which notices have been paid by this id, so renaming it makes a finished notice appear again.

== bounty.board | Notice board
see: bounty, board.id
The board id that posts this notice.

== bounty.kind | Kind
see: bounty
kill (kill need of a creature after taking the notice), fetch (bring need of an item) or deliver (carry a letter to another board, then come back for the pay).
note (1.5.0): news, not a job - only title=, text= (about two lines) and require=. While require= holds it is pinned at the top of the board (two at most), and it changes as soon as the story does. Use it to let towns react to big choices.

== bounty.target | Target
see: bounty, bounty.kind
What the notice is about: a creature id for kill, an item id for fetch, a board id for deliver. The picker offers the right list for the kind.

== bounty.need | How many
see: bounty
How many kills or items are needed (default 1). Ignored for deliver.

== bounty.where | Where
see: bounty
A dungeon or overworld location id. It is named on the notice as a hint ("seen around Greywood Cave") and pinned on the world map while the bounty is open.

== bounty.reward | Reward gold
see: bounty
Gold paid when the party collects the bounty at the board (default 30).

== bounty.xp | Reward XP
see: bounty
Experience for the party when collected (default 20).

== bounty.title | Title
see: bounty, bounty.text
The headline on the notice. Default: WANTED / NEEDED / COURIER with the target.

== bounty.text | Text
see: bounty, bounty.title
The line under the title. Default: a generated hint about where to look.

== bounty.require | Require
see: bounty, concepts.conditions
A condition (same syntax as dialogue options); the notice only goes up while it is true - after a quest step, say.

== bounty.repeat | Repeat
see: bounty
repeat=1: once paid, the notice goes up again the next day. Default 0 (once per game).

== item.quest | Quest item
see: item.category, item.type, tab.items
quest=1 marks a quest item: the player can't drop it from the inventory or sell it in a shop, so the story can't be soft-locked by losing it (a letter to deliver, a key, a sword someone asked for). It still leaves the pack when a dialogue takes it (take=). Every type=key item is a quest item unless it says quest=0. Quest items are listed under the Quest category and show "quest" instead of a price.
  quest=1

== item.category | Item category
see: item.quest, item.type, tab.items
The heading the item is filed under in the inventory (Items tab of the party menu) and in shops, where the player can filter by category (T / RB or click the chips) and sort by name, value or category (R / Back or the sort button). Default: from the type - Weapons (weapon), Armor (armor, helm, boots, offhand), Accessories, Consumables, Ammo, Materials, Quest (key). Any other name makes a new category; the base game adds Tools, Formulas and Trophies. Quest items always show under Quest.
  category=Tools

== tab.factions | Factions tab (town reputation)
see: concepts.reputation, faction.id, shop.faction, board.rep, concepts.conditions

Factions are the towns and groups that have an opinion of the party. This tab
edits factions.txt: an id, a display name and a line of description. Every
faction starts at 0 and runs from -100 to 100.

- Dialogue and scripts change it: rep=hollowmere:10 (or negative).
- Conditions test it: rep:hollowmere:30 (at least 30), !rep:brasswick:-10 (below -10).
- Achievements test it: rep:hollowmere>=60.
- A shop with faction=<id> prices by it, and a notice board with the same id adds rep= per paid notice.

The panel on the right explains the numbers and lists everything that uses the
selected faction (shops, boards, dialogue lines, quest conditions,
achievements). A faction id that is only a board id still works without an
entry here; the entry just gives it a nicer name and a description.

== faction.id | Faction id
see: tab.factions
The id used in rep=, rep: and faction= (lowercase, no spaces). Giving a faction the same id as a notice board ties the two together.
  id=hollowmere

== faction.name | Faction name
see: tab.factions
Shown in the journal's Stats page, in shop windows and in "Brasswick reputation +5" popups.
  name=Brasswick

== faction.text | Faction description
see: tab.factions
A line about who they are, for your own notes and future journal pages.

== shop.faction | Shop faction
see: tab.factions, concepts.reputation
Prices in this shop follow the party's reputation with this faction: up to 15% cheaper when Honoured (60+), up to 25% dearer when Hated (-50 or worse); selling pays up to 10% more or 20% less. The shop window shows the current standing.
  faction=brasswick

== concepts.reputation | Reputation
see: tab.factions, concepts.conditions, dlg.actions

Reputation is how a town or group sees the party, from -100 to 100. The
journal's Stats page lists every faction the party has dealt with and its
tier: Hated (-50 and below), Disliked (-10), Neutral, Liked (10), Friendly
(30), Honoured (60). Changing tier is announced in the log.

Raise it with rep= in dialogue (finishing a town's quest, paying off a debt),
lower it the same way (stealing, siding with its enemies), and gate things on
it: an option with rep:frosthold:30 only shows to friends; an NPC with
show=!rep:murkwater:-20 only appears to the disliked.

== quest.fail | Quest fail conditions
see: quest.stage, quest.stage.done, concepts.conditions, quest.preview

A fail line ends a quest as FAILED: when its condition is true (and the quest
has started and is not DONE), the journal shows the quest in red with
"FAILED: <your text>", its map pin goes away and its checklist is hidden.

  fail=pell_dead | Pell is dead; nobody will pay for the goods now.
  fail=day_limit>=5&!q_caravan_done | The caravan's goods were sold off.

- Finishing wins: once a DONE stage shows, fail lines are ignored.
- Branches: give a quest two or more DONE stages behind different flags (q_x_spared / q_x_killed) - the last true stage shows, so each ending gets its own journal text. The header above the fail lines counts the endings.
- The preview below the stages includes fail flags, so you can see when the quest would fail.

Gotchas: the flag must be set by something (a dialogue choice, an enemy's
flag=, a trigger). Check all and the Flags tab list fail flags like any other.

== dlg.graph | Dialogue graph view
see: dlg.nodes, dlg.options, tab.dialogue

The Graph button in the dialogue editor's header draws the open file as boxes
and arrows: one box per [node] (its speaker, first line, actions and options),
an arrow per option and next=.

- Green box: [start]. Purple: [camp]. Orange: nothing links to it. Red: a duplicate id.
- Green arrow: a plain option. Yellow dashed: an option with a condition. Blue: next=. Red with a "?name" stub: a target that does not exist. Grey "end" boxes end the talk; purple tags jump to another file (dialogue=).
- Click a box to select it (unrelated arrows dim; the strip at the bottom shows the whole node). Drag a box to move it; drag empty space, right-drag or use the wheel to pan.
- Double-click a box (or Enter) to jump to that line in the Text view.
- Shift-drag from an option row onto another box to point that option at it (undo with Ctrl+Z).
- Re-layout forgets moved boxes. "+ node" adds an empty node and scrolls to it.

The text stays the real file: the graph just reads it, and changes made in the
graph are written into the text.

== campaign.playstate | Play from a state
see: maps.play, campaign.start, concepts.flags

Sets up the party a playtest starts with, so you can test the middle of a
campaign without playing up to it. Saved in the campaign's playtest.txt (an
editor file - the game and exports ignore it).

- Every playtest starts with this party: when ticked, Play > and P over a tile make a fresh game with the state below. Off: they keep the running game (or make a level-1 tester).
- Class and Level: the hero's class (empty = the first class) and level; the level-up screens open as the game starts so you can pick ranks.
- Gold, Flags (flag,flag=2 - as if the story had set them), Items (id:count), Companions (class ids, like join=).
- Play from the start: a fresh game with this state on the campaign's start tile (no intro).

Problems (unknown items or classes) show in red and block Play from the start.

== campaign.export | Export a campaign
see: concepts.campaigns, campaign.version

Export .zip packs the campaign's folder - campaign.txt, maps, dialogue, data
files, art - into one zip named <id>_<version>.zip in the exports folder next
to your saves, with a README_INSTALL.txt. Whoever gets it unzips it into
Triffall's assets/campaigns/ folder; the campaign then has its own desktop
icon and appears in New Game.

Everything is saved first. Editor-only files (playtest.txt) are left out. The
base game itself cannot be exported - only campaigns.

== concepts.tips | Tutorial hints (hints.txt)
see: concepts.conditions

hints.txt (in a campaign folder) drives the green Training panel: guidance
that stays on screen until the player has done what it asks. It is a list of
hints; the LAST one whose condition holds is shown, like quest stages, so
put later lessons lower down. The Tutorial campaign (assets/campaigns/tutorial)
is built this way: each lesson's hint holds while the lessons before it are
done, so the panel always names the first thing still to do, even when the
player does things out of order. Gates (a door's openif=, an exit's require=)
wait for the lessons on that side of them.

  [hint]
  if=tut_lamp&tut_chest
  title=Training
  text=Open the party screen with {menu} and equip the token.

- if: any condition, plus mode:explore|combat|shop|menu|journal|levelup|worldmap|craft, equipped:item, fav:item (or fav:any), map:id, lit.
- A state that can be undone (equipped:, fav:, lit) makes a poor milestone: a
  trigger with require= on it, covering the area where the player will walk,
  turns it into a flag that stays set.
- title: the panel's label (Training by default).
- {action} in the text becomes that key on the device in use ({interact}, {menu}, {journal}, {worldmap}, {endturn}...); {move} says how to walk, {click} adds "(or click)" with a mouse, {craft} names the Items tab's field-crafting key (C, or X on a gamepad). The same works in dialogue, signs and messages.
- finish=CAMPAIGN|line|line in dialogue ends a tutorial-style campaign: closing lines, then the desktop with New Game open for CAMPAIGN.
- defeat= in campaign.txt (Campaign tab, "If the party falls") keeps a lost fight from ending the game: see campaign.defeat.

The base game has no hints (the old one-time tips were replaced by the Tutorial).

== tab.objects | Objects tab (object types, templates and every placed object)
see: objtype, maps.objects, objects.placed, template, tab.resources

1.1.1: the list starts with the object types ("every savepoint", "every
chest"...): what every object of that type looks like and does when used. See
objtype.

Left and middle: object templates (objects.txt). A template is a reusable map
object: an id, a type (npc, enemy, chest, exit, trigger, sign, door, savepoint,
obstacle, lever, change, gather) and the keys that type reads. The buttons
under the add-key box offer the keys the chosen type understands.

A placed object with template=<id> takes the template's type and every key it
does not set itself. So a "town_guard" template with its sprite, dialogue and
wander set can be placed many times, and changing its dialogue here changes
every guard on every map. Keys set on a placed copy win over the template:
that is how one guard can stand somewhere special or say something else.

  [npc]
  template=town_guard
  id=town_guard_3
  x=14
  y=9

Placing copies: Maps tab, Objects tool, "template:" under the type buttons.
Making one from an existing object: select it on a map and press "make
template", or select it in the list on the right and press "Template from
selected". Save the tab (Ctrl+S) after editing: the game reads objects.txt
when you leave the Editor.

Right: every object placed on every map, see objects.placed.

== template | Object template
see: tab.objects
A reusable map object: id, type and the keys every copy shares. Copies are [type] objects on a map with template=<id>.

== objects.placed | Placed objects on every map
see: tab.objects, maps.objects

The right side of the Objects tab lists every object on every map of the
campaign. Narrow it down with the type, "only copies of" the template selected
on the left, and "find": words that must all appear in the map id, the type or
any key=value (for example: iron_ore, or goblin_cave chest, or dialogue=guard).

Click a line to see its keys (dimmed ones come from its template or resource
type); double-click or "Open on map" shows it in the Maps tab.

Changing everything listed at once (each changed map is saved; a confirmation
says how many objects on how many maps first):
- Set key: give every listed object key=value (on a template copy it becomes that copy's own value).
- Remove key: take the key off them (template copies then use the template's value again).
- Link to template: the listed objects of the template's type become copies of the template selected on the left. Keys that already match the template are dropped; different values stay as each copy's own.
- Unlink: copy the template's values into each listed copy and remove template=.
- Template from selected: a new template from the selected object, linked to it.

If the map open in the Maps tab has unsaved changes, it is changed but left
unsaved: save it there. Rescan re-reads the maps.

== objtype | Object types: what every object of a type uses
see: tab.objects, template, obj.savepoint, obj.chest, obj.sign, obj.door, obj.lever

The "every savepoint", "every chest", "every sign", "every door" and "every
lever" entries at the top of the Objects tab list are object types ([type] in
objects.txt). What you set there is used by EVERY object of that type on every
map, in generated dungeons too, unless the object (or its template) sets the
key itself:

  placed object  >  its template  >  its type  >  the built-in default

An empty value means the built-in default. The panel on the right shows the
object as the game draws it (closed and opened, off and pulled) and what using
it does. Save the tab (Ctrl+S) for the game to use it.

The look and use keys:
- sprite: its picture (tile col,row; "pick..." opens the tileset).
- opensprite (chest, door): the picture once it is open. onsprite (lever): the picture while its flag is set.
- color: draw the picture in this one colour (empty = its own colours). Chests, signs and save points.
- sound: the sound event played when it is used (Sounds tab).
- onuse: a script run when it is used, the same actions as a trigger's script=, separated by ; (heal, item:ID:N, gold:N, flag:NAME, message:Title|Text, dialogue:ID ...). "+ action" adds one.
- savepoint: sparkle (the twinkle above it), sparklecolor, text (what the log says when you step on it).
- sign: title (the message window's title). door: text (what the log says when it opens).

Example: every save shrine as a glowing tombstone that heals the party when
used:

  [type]
  id=savepoint
  sprite=35,25
  color=150,220,255
  onuse=heal

"New object type entry" makes an entry for a type that has none yet.

== tab.npcs | NPCs tab
see: obj.npc, obj.npc.npc, obj.npc.companion, obj.npc.dialogue, maps.objects, dlg.actions

The people and animals of the world (npcs.txt). Each NPC is made once here -
name, look, what talking to it does, and for companions how they join the
party - and then placed on maps. A map [npc] object is a placement: npc=<id>
plus its spot and when it is there; everything else comes from here.

The list shows each NPC by name (id), companions marked. The Look card at the
top: the big preview, how it looks on the map, the sprite (Pick sprite...)
and its colour: Sheet colour keeps the picture's own colour; any other colour
draws it as a white shape in that colour (the palette offers the colours other
NPCs use and the sheet's most used ones).

Fields: name, dialogue (pick...), shop, craft, board, travel, hostile, wander,
notes, and for companions companion, partysprite, level, stats, gear, spells.
The buttons at the bottom add the keys an NPC can have.

The box under the fields:
- Where it stands: every placement on every map, with its own id and its
  show/hide/moveif conditions and the keys it sets itself. Click one to open
  the map with it selected.
- Place on map...: pick a map, then click where the NPC should stand.
- Open dialogue: its dialogue in the Dialogue tab.
- Rename id...: changes the NPC's id here, in every placement (npc=) and in
  every join=. The placements' own ids stay (saved games use them).
- Talking to it: what interacting does, in the game's order.
- Companion: the class, party picture, level and gear they arrive with, and
  which dialogue has their join=. Click it to open that line.
- Problems: missing dialogue/shop/class/items, two companions of one class,
  a companion nobody's dialogue adds. Check all lists them too.

With nothing picked, the box counts NPCs and placements and lists the
companions.

== tab.scripts | Scripts tab
see: edit.text, scripting.commands, scripting.values, scripting.actions, scripting.hooks, scripting.coachman, editor.usedby

The Scripts tab edits scripts: small programs in scripts/<id>.txt that the
game runs. A script can talk with answers, work out prices and distances,
keep counters that are saved with the game, loop, roll dice, and use every
dialogue action (give items, take gold, start fights, teleport...).

Left: the list, New (a commented starter script), Save, Delete, Check (this
script) and Check all. Middle: the text, coloured - control words (if, end,
call...) in yellow, talk (say, option, ask, pick) in green, variables in blue,
actions in white, comments grey. Right: a cheat sheet in three pages
(Commands, Values, Actions) and Used by - the NPCs, objects, maps, items,
dialogues and other scripts that run it.

Check uses the game's own reader, so a script that passes Check runs. It also
reports scripts, dialogues, items, creatures, shops and maps that don't exist.
Check all (top right) checks every script with the rest of the campaign.

A script is attached by its id (the file name) - see "Where scripts run".
The coachman in every town is a script: open "coachman" for a full example.

Gotchas:
- A script that breaks while running stops and writes the line and the reason in the message log.
- Running scripts are not saved. Use keep variables for anything that must last.

== scripting.commands | Script commands
see: tab.scripts, scripting.values, scripting.actions

One command per line. # starts a comment. Indenting is only for you.

  let n = 5                 a variable for this run of the script
  keep visits = visits + 1  a variable saved with the game
  n = n * 2    n += 1    n -= 1

keep variables live in the save: every script reads and changes them by
name. A name that was never set reads as 0 (or as the flag of that name).

  if gold >= 10 and not met_mara
    say You look like you could use work.
  elif level > 5
    say Back again?
  else
    say Hm.
  end

  while n < 3          repeats while true
    n += 1
  end
  for p in places()    once for each item of a list (text with commas)
    log {placename(p)}
  end
  for i in 5           1, 2, 3, 4, 5
  end

break leaves a loop, continue starts its next round, stop ends the script.

  call pay_toll 20     runs another script and waits for it; inside it the
                       values are arg1, arg2... (args = how many)
  return fare * 2      back to the caller, which gets it in result
  start town_bells     runs another script alongside, without waiting

Talking:

  say Welcome to {mapname(here)}, {herename}.
  speaker Old Tam      who speaks next ("" = nobody); default: the NPC
  option "Buy a map (5 gold)" -> "map"
  option Just looking
  ask choice What'll it be?
  pick dest Where to?
  wait 2

say shows a line and waits for the player. option lines collect answers;
ask shows them under its question and puts the chosen answer's value (after
->, else its text) into the variable. Long lists scroll. pick opens the world
map: the player chooses a place they have been to and the variable gets its
id ("" if they close the map). wait pauses for seconds of play on the map.

Text: after say, option, speaker and actions, anything in {} is worked out.
"Quoted text" works too, and can be joined with +.

Typing (1.4.0):

  input code Turn the dials. What is the combination?

input opens a box the player types into (Enter = OK, Esc = cancel; on a pad
the d-pad picks letters). The variable gets what was typed, "" when cancelled.
It is how the combination lock and terminal scripts ask for codes. The box's
title is the speaker (else the NPC's name). See scripting.puzzles.

== scripting.values | Values and functions in scripts
see: scripting.commands, concepts.conditions

Values are whole numbers or text. + adds numbers and joins text; - * / %
need numbers. Compare with == (or =), !=, <, <=, >, >=. Combine with and,
or, not. Text compares without caring about capitals.

Built-in values: gold, day, hour, minute, here (the map id), herename, x, y
(the party), level (the hero's), partysize, night (1 at night), stealth (1
while sneaking), weather, npc and npcname (the NPC the script was started
from), won (1 if the last fight was won), true, false. In an item's script:
useditem and user.

Any other name is a variable, else a flag: "if met_mara" is true once the
flag met_mara is set.

Functions:
- flag("name") - a flag's value. cond("item:key&!door_open") - any dialogue condition.
- has(item) - how many the party carries and wears. visited(map). kills(creature).
- inparty(class or name), rep(faction), approval(class).
- stat("cha") - the hero's stat with gear; partystat("str") - the best of the living party (1.4.0).
- random(1, 6), random(10) (1 to 10), chance(25) (1 a quarter of the time).
- places() - the overworld places the party has been to. placename(p), placemap(p), placex(p), placey(p).
- distance(p) - tiles from where the party is on the overworld; leagues(p) = distance / 10 + 1.
- mapname(map), itemname(item).
- Lists are text with commas: count(l), at(l, 2), contains(l, x), add(l, x).
- len(t), upper(t), lower(t), find(t, part) (position, 0 = not there), min(a, b), max(a, b), abs(n), var("name").
- 1.4.0: mid(t, start, length) - part of a text (start at 1; no length = to the end). squash(t) - only the letters and digits, in capitals: compare typed codes with squash(code) == squash(arg1) and "rift-0", "Rift 0" and "RIFT0" all match.
- 1.4.0: plates(group), platesdown(group) - pressure plates on this map with that group= (all of them / those down now). crateat(x, y) - 1 if a crate stands there. lorefile(name) - 1 once that desktop file is unlocked.

== scripting.actions | Actions in scripts
see: dlg.actions, scripting.commands

Every dialogue action is a script line: the action, a space, then its value.
The value may hold {values}.

  give potion:2
  gold -{fare}
  set q_toll=1
  teleport overworld,{placex(dest)},{placey(dest) + 1},Riding north...
  dialogue elder_mara
  combat bandit,bandit
  if won
    say Not bad.
  end

Actions that open a screen - dialogue, shop, combat, teleport, message,
cutscene, craft, board, travel, healer, respec, encounter - pause the script
until the party is back on the map, then it carries on (after a teleport, on
the new map).

New in 1.1.10, for scripts and dialogue nodes alike:
- script=id[,value,...] - runs a script (dialogue: script=id; action lists: script:id).
- time=minutes - time passes. sound=id - plays a sound. encounter - a random fight from the ground underfoot. On a touch=1 map the group appears a few tiles away and chases the party (the script carries on at once); encounter now (action lists: encounter:now) starts the fight at once, as the coach's ambush does.
- weather=new|clear|rain|storm|fog|snow. stat=travels:1 - counts towards a statistic (travels, kills, chests, crafted, bounties, fights).
- teleport=map,x,y,text - the text shows while travelling.

New in 1.4.0:
- resetcrates[=message] - every crate on this map goes back to its placed spot (a "tipping lever" for a stuck plate puzzle).
- lorefile=name - a #locked desktop file (data/lore/<name>.txt) appears in My Computer, for every save slot. See desktop.lorefiles.

== scripting.hooks | Where scripts run
see: tab.scripts, obj.npc.script, map.onenter, concepts.scripts

- An NPC: script=<id> in the NPCs tab (or on one placement). Talking runs it, before its board, travel or dialogue. say lines use the NPC's name and picture.
- A dialogue node: script=<id>. If the script says something it takes the talk box over; otherwise the conversation carries on.
- Any action list - a trigger's script=, an object's onuse=, an enemy's ondefeat=, an obstacle's onclear=, a dungeon's bossdefeat=, the campaign's defeat=: script:<id>.
- A map: onenter= (the "on enter" button in the map header) runs each time the party arrives - by exit, teleport, coach or new game - but not when a save is loaded.
- An item: effect=script:<id> (used up) or script:<id>:keep (kept). It must be a consumable.

== scripting.coachman | Example: the coachman
see: tab.scripts, scripting.commands

The coach in every town is the script "coachman" (NPC coachman, script=
coachman). It greets the party, lets them pick a place they have been to on
the world map, works out the fare (8 gold + 6 per league), asks before
taking the money, lets time pass, rolls for an ambush (less likely while
sneaking), and teleports to the place. An ambush uses "encounter now", so the
fight starts at once even on a touch=1 map.

  say Where to? Coach fare is by the league.
  pick dest "Where should the coach take you?"
  if dest == ""
    stop
  end
  let fare = 8 + leagues(dest) * 6
  option "Pay {fare} gold" -> "go"
  option "Never mind" -> "no"
  ask answer {placename(dest)} is {leagues(dest)} league(s) away. {fare} gold.
  ...

Copy it (New, then paste) to make a ferryman with other prices, or a
caravan that only goes to places with a flag set.

script=<id> runs scripts/<id>.txt when the party talks to the NPC. It wins
over board=, travel= and dialogue=.

  script=coachman

== map.onenter | Map on enter
see: scripting.hooks, concepts.scripts

onenter= runs actions each time the party arrives on the map - usually

or a flag if it should only do something once.

  onenter=script:harbour_bells

== obj.crate | Crate object (1.4.0)
see: obj.crate.heavy, obj.plate, puzzle.plates, scripting.puzzles

A crate the party pushes one tile by walking into it (Sokoban style). It blocks
its cell - in fights too - and can't be pushed into walls, people, chests,
exits, other crates or an open doorway.

  [crate]
  id=mine_crate1
  x=36
  y=25
  name=Ore crate

Crates go back to where they were placed every time the party arrives on the
map, so a puzzle can never be lost for good. A lever with onuse=resetcrates puts
them back at once. Keys: id (tests and scripts name it; default crate1, crate2...),
name, heavy, sprite (default the crate picture 8,36), color.

== obj.crate.heavy | Heavy crate
see: obj.crate, obj.obstacle.needs

heavy=N: walking into it only pushes it if the strongest party member has STR N.
Otherwise a menu offers a utility=force spell (the warrior's heave) or a try with
the best STR. A force spell cast from the Spells menu also heaves the crate in
front of the party, however heavy.

  heavy=16

== obj.crate.id | Crate id
see: obj.crate

A name for this crate on this map (crate1, crate2... when empty). The headless
tests check crate:<id>; scripts can look for a crate with crateat(x, y).

== obj.plate | Pressure plate object (1.4.0)
see: obj.plate.group, obj.plate.onpress, obj.crate, puzzle.plates

A stone plate in the floor. It is down while a crate or the party's leader
stands on it. When it goes down its onpress= runs, when it comes up its
onrelease= runs (action lists, like a lever's onuse=). Plates that belong to one
puzzle share a group=; the script functions plates(group) and platesdown(group)
count them.

  [plate]
  x=35
  y=24
  group=mine_plates
  onpress=script:pressure_plates,mine_plates,mine_plates_open

Keys: group, onpress, onrelease, sprite (empty = a drawn stone square), color.
Place plates on walkable floor.

once every plate of the group is down at the same time.

== scripting.puzzles | Puzzle scripts (1.4.0)
see: puzzle.levers, puzzle.plates, puzzle.combination, puzzle.terminal, scripting.commands, obj.crate, obj.plate

Four ready-made puzzle scripts in data/scripts. Each takes its settings as
arguments, so the same script runs every copy of a puzzle:

  onuse=script:lever_sequence,crypt_seq,3,3142,crypt_seq_solved
  onpress=script:pressure_plates,mine_plates,mine_plates_open
  onuse=script:combination_lock,4721,strongroom_open,Strongroom lock
  onuse=script:terminal,RIFT0,vault_open,ANNEX-NET vault terminal

Each one sets a "solved" flag. Point a door's openif=, a change's if= or an
obstacle's needs=flag: at it. The first lines of each script say what its
arguments are ("# args: ..."); the Editor's script lists show them, and picking
one fills in the argument names for you to replace.

In the base game: the crypt's four lords (levers), the old mine's sorting room
(plates and crates), Kesh's strongroom in the bandit camp (combination lock),
and terminals in the Research Annex, the metro and the starship.

== puzzle.levers | Lever sequence puzzle
see: scripting.puzzles, obj.lever

scripts/lever_sequence.txt - pull the levers in the right order; a wrong lever
springs them all back up.

  args: puzzle, lever, order, solved

Place each lever with toggle=0, flag=<puzzle>_<n> and
onuse=script:lever_sequence,<puzzle>,<n>,<order>,<solved>. order is the lever
numbers as digits (3142). Progress is kept in the flag <puzzle>_step. Leave a clue
for the order somewhere (a sign, a dialogue).

== puzzle.plates | Pressure plate puzzle
see: scripting.puzzles, obj.plate, obj.crate

scripts/pressure_plates.txt - every plate of a group down at once opens it.

  args: group, solved, message

Give each plate group=<group> and onpress=script:pressure_plates,<group>,<solved>.
Add crates for the far plates; the party's leader can hold one plate. A lever
with onuse=resetcrates helps a stuck player (leaving the map resets crates too).

== puzzle.combination | Combination lock
see: scripting.puzzles, scripting.commands

scripts/combination_lock.txt - a box to type the code into (the script input
statement).

  args: code, solved, title

Place it as a sign with no text (Objects tab template combo_lock, a padlock):
onuse=script:combination_lock,<code>,<solved>,<title>. Upper/lower case, spaces
and dashes in the answer don't matter. Hide the code elsewhere: a note, a
dialogue, a desktop file.

== puzzle.terminal | Terminal password
see: scripting.puzzles, desktop.lorefiles

scripts/terminal.txt - an old machine asks for a password. Two wrong tries and
the log hints that the old computer (My Computer on the desktop) knows more.

  args: password, solved, title

Place it as a sign with no text (Objects tab template terminal):
onuse=script:terminal,<password>,<solved>,<title>.

== desktop.lorefiles | Desktop files (My Computer)
see: puzzle.terminal, scripting.actions

The text files in data/lore show in the desktop's My Computer. A file whose
first line is #locked stays hidden until a game unlocks it with the action
lorefile:<name> (a chest's onuse=, a dialogue, a script). Unlocked files stay
for every save slot (files.ini in the save folder, like achievements); the dev
console's reset_files locks them again.

The base game chains its terminals this way: annex_memo is always there (the
Annex password), the Annex vault unlocks metro_dispatch (the metro password),
the metro vault unlocks ship_manifest (the ship password).

== contradictions | Story contradictions (contradictions.txt)
see: editor.check, tab.flags, dlg.actions, obj.enemy

data/contradictions.txt (1.5.0) lists flag combinations that must never all
be true at once - outcomes of one choice:

  goblin_chief_spared & goblin_chief_dead | Grakk can't be both spared and killed

One line per combination, terms joined by &, a note after |. A campaign's own
contradictions.txt is added to the base game's.

Check all looks for a route in the content that could set both flags of a
two-flag line, and reports it as an error. Every place that sets a flag counts
(dialogue nodes, enemy groups and their ondefeat=, triggers, chests, doors,
levers, obstacles, map onenter=, scripts, dungeon bosses, and a companion
leaving at -40 approval), with the conditions that must hold for it to happen:
the option conditions on the way to a dialogue node, the show=/hide=/require=
of whatever starts the talk, an enemy group's show= and one-term hide=. It is
fine when the second setter clears the first flag, or its conditions say the
first flag (or another flag the first setter sets for good) is not set.
Counters (set=q_x=2) are taken to only go up.

Fix a report by adding the missing condition: hide= on the group, !flag on the
option, require= on the trigger - or by clearing the other flag first.

While playing, the game also watches every line (terms may be !flag or
flag>=N there): the first time one becomes true it writes "story
contradiction" to the message log (and the scripts' last error, which the
console's scripts command shows).
